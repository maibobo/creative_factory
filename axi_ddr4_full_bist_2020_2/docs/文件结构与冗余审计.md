## 2. 已确认的冗余项

新工程中未发现独立 `example`/`example_design`/`exdes` 目录。MIG `.gen` 内部包含 Xilinx 自动生成的校准 MicroBlaze、PHY 和仿真文件，它们是 IP output products，不是另一个用户 example 工程；远端正式工程保留，便于离线打开和后续综合。

以下开发过程文件不参与工程并应删除：

- 原最小工程 RTL 的临时参考副本；来源和差异已写入文档。
- 临时 `vio_reference.xci`。
- 本地/远端 `xsim.dir`、`xvlog.pb`、`xelab.pb`、webtalk 和 backup journal。
- Vivado `.cache`、`.hw`、`.ip_user_files`：均可从 XPR/XCI 重新生成。
- 已中止综合产生的 `.runs`：已经删除，防止被误认为综合网表证据。

行为回归只保留最终日志和两份 WDB；重复 WDB、可执行仿真快照和中间编译库不保留。

## 3. 原工程旁路污染

开发初期一次错误 IP output path 在原工程同级生成了 `C:\project\RTDS\DDR\axi_ddr4_min_2020_2.gen`，创建时间为 2026-09-10 17:16，包含 205 个自动生成文件、约 51 MB。它不属于原工程目录，也不被新工程引用；清理时只删除这个精确同级目录，不修改 `C:\project\RTDS\DDR\axi_ddr4_min_2020_2`。

## 4. 本机轻量备份

本机备份路径为 `E:\PCIE-CPU\axi_ddr4_full_bist_2020_2`。它保存 RTL、XDC、CSV、Tcl、文档、日志以及 XPR/XCI，省略体积较大的 `.gen`、`.cache`、`.runs` 和 `.ip_user_files`。

这种备份可用 Vivado 2020.2 打开 XPR并查看工程结构。由于未携带完整 IP output products，首次打开时可能出现“IP output products missing/out of date”一类警告；从目录内 XCI 重新 Generate Output Products 后即可恢复。SHA-256 用于区分这种预期的生成物缺失与真实源文件丢失/损坏。
