# 以太网

按物理接口采样、帧解析、过滤判决、缓存路由和DMA分层。RGMII的双沿采样、GMII字节流和后级存储拍分别定义，接口频率和CRC计算时序不能只按模块名字确定。

## 帧格式与解析

明确前导码/SFD检查方式、SFD后字节编号、DA/SA、EtherType、VLAN、载荷和FCS范围。接收侧可用尾部保持窗口分离4 Byte FCS，避免FCS写进业务数据FIFO。

CRC需要明确输入位/字节顺序、初始值、最终取反和残余表示。固定残余常数只能与对应算法、数据范围及表示方式一起使用；不同CRC模块之间先用确定帧交叉核对。

VLAN剥离后，描述符长度应按实际存储字节计算；如果支持单层标签，QinQ或其他TPID的处理另行规定。短帧、超长、RXER和FCS错误可能同时满足，丢弃原因优先级由当前设计定义。

## 过滤与窗口

| 功能 | 需要确定 |
|---|---|
| MAC/ACL | 本地、广播、组播及白黑名单优先级 |
| 旁路开关 | 旁路哪些策略，格式/CRC/容量保护是否仍生效 |
| 风暴 | 时间窗、帧数/字节数门槛、零配置语义及计入条件 |
| 重复检测 | Hash碰撞、完整CRC存储、epoch翻转和清理优先级 |
| 分类 | EtherType规则、各队列拥塞及不同层丢弃统计 |

直接映射表即使保存完整CRC避免把不同值误判重复，也可能因覆盖旧项漏检重复，设计需定义其能力。窗口切换与新帧同拍、查表与清理竞争是关键边界。

计时器按固定拍增量换算时间时，应绑定实际频率；例如每拍加8只有在125 MHz时对应8 ns。换频率需同步调整时间定义。

## 缓存与DMA

数据与描述符一一对应，发布描述符表示数据已完整可读。目标通道拥塞若排空整帧，接收层丢弃与路由层丢弃分别统计。固定优先仲裁需确认低优先通道是否允许饥饿。

8→64 bit打包同时处理TKEEP/TLAST和字节顺序，反压保持当前有效拍。数据命令、数据、状态、描述符和commit分别检查，成功提交后才推进软件可见指针。

## 测试组合

从正常帧、边界长度、VLAN/CRC、过滤匹配开始，补充窗口相邻周期、重复表碰撞、拥塞、描述符异常、连续帧和DMA超时。异常帧排空后下一帧仍完整；中断合并时软件按队列排空，而非按每次中断只取一帧。
