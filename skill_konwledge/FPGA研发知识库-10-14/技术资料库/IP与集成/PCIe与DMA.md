# PCIe与DMA

分别确定链路代际/lane数、Endpoint/Root Port配置、用户接口宽度与频率、BAR窗口、DMA模式及中断能力。官方example默认值不等于项目目标，BFM和真实Endpoint也要使用一致配置。

## 数据与完成路径

H2C：Host数据/描述符→Root Port→Endpoint/DMA→卡侧存储。C2H：卡侧存储→DMA→Endpoint→Root Port接收→Host目标内存。观察点覆盖地址、长度、有效字节、响应和完成状态。

| 事件 | 可证明的层次 |
|---|---|
| 卡侧AXI响应 | 对应卡侧事务及响应码 |
| DMA描述符完成 | 该DMA定义的描述符完成语义 |
| PCIe写TLP到达 | 接收模型收到的事务、地址和字节 |
| Host内存更新 | 目标模型或软件视角的数据内容 |
| usr_irq_ack | 所用IP的请求确认语义，例如MSI发送确认 |
| 驱动ISR与软件处理 | 软件执行及数据可见性 |

不能用DMA状态或IRQ单项代替端到端比较。缓存维护、内存屏障及发布顺序由主机体系和驱动配合。

## 验证模型

Root Port中的数组可能只负责H2C数据与描述符读请求，不负责收集C2H写回。先检查模型接口和数组写入者，再选择CQ等接口接收器或Host-memory sink。sink应按地址、有效字节和长度写入，scoreboard独立比较内容。

以512 B数据为例，64 bit接口共有64个有效拍，但PCIe TLP分段与用户接口拍数不必相同。逐层检查事务长度和端到端字节，避免跨接口混用计数。

## 配置、描述符与IRQ

描述符地址、长度单位、对齐、窗口和状态定义绑定当前模式。重新启动后的count可能表示本次任务数量，不一定是全局累计；连续任务验证不能只看旧done状态。

应用请求、IP确认、MSI到达和软件处理分别说明。read-to-clear清通知、W1C清错误、ACK释放数据等动作明确作用范围，清通知不能隐含释放队列。

## 高价值场景

先检查LTSSM、协商配置和BAR，再检查基础双向数据。按实际能力扩展多描述符、随机反压、连续双向、非整拍尾包、4KB边界、错误响应和超时恢复。

CPU读寄存器轮询用于最终软件可见性，仿真中可使用本地观察事件减少无意义PCIe事务，但功能判据仍落在真实接口上。

模拟Host接收器与软件ISR是不同验证对象，报告注明数据、事务、DMA与软件各层检查。相关主题：[总线与协议](../工程基础/总线与协议.md)、[观察模型案例](../工程案例/接口映射与观察模型.md)、[跨IP集成](跨IP集成.md)。
