# 总线与协议

区分AXI4、AXI4-Lite与AXI-Stream。记录数据/地址位宽、ID、burst、outstanding、响应顺序及具体IP限制。AXI4-Lite采用单拍事务，不机械套用AXI4的burst与ID场景。

## 真实接受与独立通道

VALID与READY同时有效才表示当前通道接受。发送方不能等READY才首次提出VALID；等待期间保持有效载荷与控制字段。指针、计数和数据消费按真实事件推进。

AW和W分别接受，可不同周期握手；写响应与这两类进度关联。AR、R分别计数，检查RRESP、ID、RLAST及实际内容。AXI响应成功是存储事务层证据，软件可见性还需要系统的内存和提交关系。

| 项目 | 验证关注 |
|---|---|
| burst/len/size | AxLEN为拍数减一，AxSIZE编码每拍字节数；按支持范围检查首尾、地址推进 |
| 4KB与对齐 | burst遵守4KB边界；拆分、非对齐和尾字节策略与规格一致 |
| outstanding/ID | 计数上限、归还时机、同ID顺序和不同ID允许的乱序 |
| AW/W独立 | AW先到、W先到、分别停顿、B延迟 |
| 错误/超时 | 错误码、未知响应、重复响应、旧事务结束及恢复 |
| QoS | 当前仲裁器实际使用字段时检查优先或带宽行为 |

协议本身和项目超时策略分开。已经接受的事务不能因为计时器清零而消失，错误恢复要收口原ID、拍数和响应承诺。已经展示且被反压的响应字段应保持。

## Stream与LocalLink

按真实握手采样TDATA及适用的TKEEP、TLAST等边带，比较有效字节。TKEEP的稀疏模式是否支持以当前接口/IP为准；不能把低位连续有效的某个DMA约定推广到所有Stream。

LocalLink的SOF/EOF/REM与AXI字段不同。例子64 bit流接口的REM仅在EOF表示尾拍有效字节数减一；完整尾拍为7。512 B存储burst为64拍，1536 B帧为三个burst，三种单位分别检查。

## 状态与清除

定义read-to-clear、W1C或ACK的影响范围及清除与新事件同拍的优先级。通知清除不应隐含释放数据所有权，IRQ确认也不自动代表软件已经处理数据。
