# 编码与检视

按项目工具选择Verilog或SystemVerilog语法，设计RTL与验证代码各用适用的文件表。命名表达功能、方向和极性，注释说明非显然的时序、约束、状态转换及异常。

## 语法编译

核对顶层、文件表、参数、宏、include及IP依赖。检查重复定义、端口宽度、输入驱动、参数展开和语言模式，保留编译与展开输出。仿真和综合使用相同的业务配置，工具专用包装单独说明。

## 代码检视

| 对象 | 检视内容 |
|---|---|
| 功能与状态 | 逐条实现规格，触发/退出条件、非法状态、超时和恢复清楚 |
| 组合 | 路径完整赋值，无意外锁存和组合环，默认值符合功能 |
| 时序 | 寄存器更新语义、复位、使能、置位/清除优先级清楚 |
| 接口 | 真实握手推进，反压期间字段稳定，事务完成和释放正确 |
| 算术 | 符号、扩展、截断、进位、移位、终值及非2次幂深度 |
| CDC/IP | 结构、模式、延迟、阈值、复位及约束与方案一致 |

组合计算通常用阻塞赋值，时序寄存器通常用非阻塞赋值，保持过程语义一致。过程块按职责组织；相关寄存器可按共同控制关系描述，独立生命周期不混在一起。

## 常见实现细节

计数按真实接受事件推进。若`valid=1, ready=0`持续三拍，事务计数不能加三。地址步进使用接受或完成事件中的哪一个，应与接口语义一致。

有进位需求时显式扩展操作数；需要回绕时明确截断范围。计数器是否允许达到“深度”取决于它表示索引还是占用数量，深度为8时索引0～7与占用0～8需要不同位宽。

状态机区分当前态、次态和寄存输出，所有合法输入有明确行为；非法状态进入定义的安全状态。超时处理不能简单清除已经接受的事务。

RAM/DSP等资源的复位能力与普通寄存器不同，按器件资源及功能选择。数据有效标志可限制使用时刻，避免为了初始化所有数据而破坏存储器推断。

## 综合检查

检查可综合性和实际结构：RAM/DSP推断、寄存器、锁存、多驱动、黑盒、截断及关键逻辑优化。重要告警结合具体功能处理。综合得到硬件结构，功能正确性由检视与验证共同确定。
