# 仿真回归与定位

按确认的测试表和方案编写验证代码，注释反标测试点，用例名称映射实际入口。保存工具/IP库、顶层、文件表、宏/参数、输入配置与Seed。

## 编译、展开与运行

编译检查语言与依赖，展开检查顶层、参数、绑定和IP模型，运行执行刺激与检查。package及include按依赖排序，同一class不能既被package包含又单独重复编译。

每轮独立目录保存命令、配置、日志、退出码、耗时和结果。按用例表行序执行，功能失败或用例超时保留现场后继续；编译和环境异常停止，剩余结果栏保持空白。

PASS需要正常结束、实际通过标志、无失败标志及方案完成条件。进程返回0、普通日志包含PASS、链路就绪等单项都不能替代完整验收。

## 从现象定位责任边界

| 现象 | 优先核对 |
|---|---|
| 无法展开 | 完整日志、命令参数、库映射、顶层和带空格参数 |
| 没有刺激到达 | 复位busy、校准/链路、实际握手与BFM门控 |
| 数据错一拍 | FIFO模式、输出延迟、monitor采样及尾字节 |
| DMA完成但比较错 | 真实接收路径、Host模型、地址和字节有效性 |
| 反复偶发 | 同Seed复现，排查调度竞态、配置与边界条件 |
| 运行结果矛盾 | 代码与配置版本、日志所属轮次、结束标志及残留 |

固定输入定位后判断是DUT、TB、RM判据或工具环境问题。修改对象和影响范围清楚，先复测相关用例，再执行必要回归；保留原失败和修复结果。

## 每日回归与报告

回归脚本记录用例名称、测试点、命令、Seed及PASS/FAIL匹配式，独立保存每轮现场。相同工具和配置下使用同Seed重放，不承诺跨工具位级相同结果。

报告按测试版本、结果概览、分功能/用例现象与结论、验证结论组织。描述数据接受、响应、检查和完成等具体事件，使结果能被另一位工程师复核。

入口：[回归工具](../../scripts/README.md)。案例：[运行身份与判据](../工程案例/回归记录与判据.md)。
