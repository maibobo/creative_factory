# 门禁判定与故障分类

本页定义V2建议门禁。必需项由任务选择并批准，不是所有仿真任务都需要上板。未安装的工具、未配置的检查器和未执行项必须分别说明，不写成PASS。

## 门禁

| ID | 检查 | 需要的证据 |
|---|---|---|
| G0 | 规格与范围 | 输入版本、关键决策、授权修改目录 |
| G1 | 方案和规则适用性 | 接口表、架构决策、规则profile与批准单元 |
| G2 | 编译与展开 | 工具/源文件版本、完整命令、退出码与新日志 |
| G3 | 验证环境可信度 | 独立expected、检查器正反例、非空事务计数 |
| G4 | 功能仿真 | testcase/Seed、assertion、scoreboard、timeout与里程碑 |
| G5 | 回归与覆盖 | 必需用例集合、失败重放、覆盖项和未覆盖解释 |
| G6 | 修改范围与交付结构 | diff、允许文件、文档追踪和产物完整性 |
| G7 | 人工签核 | 负责人、日期、批准范围与残余风险 |
| G8 | 实现/时序/板级 | 任务要求的实现、STA、硬件结果分别记录 |

G8不适用可以有明确理由；任务要求G8却未执行时，交付状态不能称为完整工程验收通过。

## PASS如何成立

一个适用的工具门禁必须同时具备当前运行身份、任务和代码版本、命令、正常退出码、必要结束里程碑、零个未处理fatal/assertion/scoreboard错误、有效事务数及可定位的日志。证据哈希用于绑定当时文件，不证明内容正确。仅有退出码0或字符串PASS不足以验收。

本轮历史案例为报告级引用。尚未逐一重取原始运行目录和哈希，不宣称已经通过V2证据完整性门禁。

## 分类与处理

| 分类 | 触发 | 处理 |
|---|---|---|
| TEST_FAIL | 执行到用例，行为与期望冲突 | 保留Seed；进一步判断DUT、TB或规格责任 |
| TOOL_FAIL | 找不到工具、许可或编译启动异常 | 修环境；不能据此修改DUT |
| SETUP_RETRY | 尚未进入用例的临时工作目录/配置访问失败 | 保留失败现场；任务批准范围内至多一次同输入重试 |
| INCONCLUSIVE | 旧日志、缺少结束、缺失计数、退出码未知 | 不给PASS，先补证据 |
| PASS | 全部适用条件成立 | 仍需审查范围与G7签核 |

SETUP_RETRY是行动分类，不是最终运行结果；原运行记fail，后续运行单独记录pass/fail。产品界面显示TEST_FAIL，也不代表根因已经确认是DUT。

## 运行记录填写

使用[run manifest](run_manifest.example.json)。默认execution_status为not_run，所有计量和结果为空。后续执行需补run_id、工具、命令、工作目录、时间、testcase、Seed、退出码、里程碑、结果和证据哈希。

本机Vivado入口在本地证据索引中登记；不复制其他主机的路径。不同工具版本不能互相充当签核结果。本轮不启动Vivado。
