# 文档规范：五类模板与实填示例

这些模板是V2建议格式，并非宣称已经成为公司正式制度。字段围绕输入、决策、输出与验收组织。示例采用历史AUR-002复盘，所有运行数字只转述SRC-PCIE，V2重跑仍为not_run。

选定方案、数据路径、控制路径:

风险、验证方法和交付件:
```

### 实填摘要 DESIGN-AUR-001

需求REQ-AUR-001：在冻结接口和512 B事务条件下，恢复Aurora接收后FDMA写完成与IRQ链条。非目标：不修改FDMA、adapter和CONV_DMA模块本体，不改真实串行链路。

当前接口存在名字和方向不匹配。候选A为在wrapper建立语义明确的网线并沿用已验证映射；候选B为重命名模块端口并修改所有调用。历史采用A，变更范围较小。V2复盘仍需人工批准隔离副本和修改文件，不沿用历史人的授权。

### 可复制模板

Seed/超时/回归集合:

```

### 实填摘要 VP-AUR-001

采用既有Root Port/TPI、真实XDMA Endpoint与Aurora LocalLink peer BFM。检查连续64拍、512 B传输、FDMA burst done、IRQ请求与ack、Host sink逐字节scoreboard。expected数据由冻结模式与规格生成，不能从DUT输出反推。

该环境不覆盖Aurora GT、板级信号完整性、操作系统ISR。编译通过只能进入仿真，不能替代数据/中断验收。

### 实填摘要 ISSUE-AUR-002

现象：RX数据已进入FIFO，但写完成与IRQ未出现。初始怀疑FDMA或adapter本体；证据为既有通过的integration TB使用交叉映射，以及CONV_DMA内部方向。历史修复只发生在wrapper。SRC-PCIE记录512 B、IRQ和C2H通过。新复盘的运行ID为空，不能由历史结果填成新运行PASS。
