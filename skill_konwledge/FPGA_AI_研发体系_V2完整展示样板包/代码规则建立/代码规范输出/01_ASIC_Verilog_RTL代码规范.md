# ASIC Verilog RTL 代码规范

版本：1.0.0  
语言基线：可综合 Verilog-2001  
目标：ASIC 设计、仿真、综合、Lint、CDC、STA 和 DFT 协同

## 1. 范围和规则解释

本文件只规范 ASIC 设计 RTL。SystemVerilog 验证代码必须使用独立的《SystemVerilog/UVM 验证代码规范》，不得把验证语法或方法学规则混入本文件。

文件头和一般注释格式不在范围内。本文只要求语义段注释。

规则级别：M1 必须修复；M2 必须遵守或取得书面豁免；R 为推荐。自定义规则具有最高的内部规范优先级。

## 2. 语言、文件和层次

| 编号 | 级别 | 规则 |
|---|---|---|
| `RTL-LANG-001` | M1 | ASIC RTL 只使用综合工具链确认支持的 Verilog-2001 子集；禁止在 `.v` 设计文件中使用 `logic`、`always_ff`、`always_comb`、`typedef enum`、interface、class 等 SystemVerilog 结构。 |
| `RTL-LANG-002` | M1 | 一个设计源文件只定义一个可综合模块。公共宏或常量头文件必须有单独用途，不能夹带模块定义。 |
| `RTL-LANG-003` | M2 | 文件名使用小写下划线形式，模块名使用大写下划线形式，两者忽略大小写后对应。例如 `req_ctrl.v` 对应 `REQ_CTRL`。 |
| `RTL-LANG-004` | M1 | 不得使用语言关键字、工具保留字或仅大小写不同的名称区分对象；名称只能由字母、数字和下划线组成，首字符必须是字母。 |
| `RTL-LANG-005` | R | 建议每行不超过约 100 个字符；端口映射或表达式因可读性需要可以超过。固定 72 列不是签核条件。 |
| `RTL-LANG-006` | M1 | 禁止 `include` 隐式引入可综合模块；文件表必须显式列出模块源。 |

禁止依赖 Verilog-95 的旧式非 ANSI 端口声明。ANSI 风格端口列表属于 Verilog-2001，本规范允许并推荐使用，所有示例统一采用该形式。

## 3. 命名

| 编号 | 级别 | 规则 |
|---|---|---|
| `RTL-NAME-001` | M2 | 信号、端口、变量使用有语义的小写下划线名称；参数、`localparam`、宏和状态常量使用大写下划线名称。 |
| `RTL-NAME-002` | M1 | 低有效信号以 `_n` 结尾；时钟名包含 `clk`，复位名包含 `rst`；不得用名称隐瞒极性或时钟域。 |
| `RTL-NAME-003` | M2 | 实例名采用 `U_<MODULE>`；同一模块多次例化时追加有意义的功能或序号后缀。 |
| `RTL-NAME-004` | M2 | 同步链内部级可使用 `_ff1`、`_ff2` 等后缀，但业务 RTL 不得借此自行实现已要求例化的同步器。 |
| `RTL-NAME-005` | M2 | 状态机当前态和次态分别使用 `<fsm>_curr_st`、`<fsm>_next_st`；锁存、三态、异步等特殊语义可使用项目统一后缀。 |
| `RTL-NAME-006` | M1 | 禁止用 `_reg` 声称综合结构，禁止仅用 `temp1/data2/sig3` 等无语义名称。 |
| `RTL-NAME-007` | R | 名称应简洁且足以表达模块、方向、协议和域；不设置 20/32 字符硬上限，但必须满足所用工具和库的标识符限制。 |

缩写必须在项目术语表中唯一。`cfg`、`addr`、`len`、`req`、`rsp` 等行业常用缩写可以直接使用；同一概念不得混用多个缩写。

|---|---|---|

| `RTL-MOD-002` | M1 | 总线必须显式给出范围并统一使用降序 `[MSB:LSB]`；连接两端位宽、符号性和含义必须一致。 |
| `RTL-MOD-003` | M1 | 模块例化必须使用命名参数和命名端口连接，禁止位置连接。 |
| `RTL-MOD-004` | M2 | 实例端口只连接简单信号、常量或明确的未连接端口；逻辑表达式先形成命名中间信号，不能隐藏在端口映射中。 |
| `RTL-MOD-005` | M1 | 输入端口必须有确定驱动。刻意不用的输出连接到带 `_nc` 后缀的网络；不得依赖悬空输入。 |
| `RTL-MOD-006` | M1 | `inout` 和内部三态只允许出现在芯片顶层 I/O 边界或批准的 I/O 包装器内。芯片内部使用明确的输入、输出和输出使能。 |
| `RTL-MOD-007` | M2 | 模块按功能和时钟域划分；一个模块包含多个时钟域时，CDC 边界必须集中、命名清楚并有 CDC 说明。 |
| `RTL-MOD-008` | M2 | 芯片顶层只负责连接、I/O/电源/时钟复位包装及必要的集成逻辑，不放置难以复用和验证的零散组合逻辑。 |

## 5. 声明、连续赋值和过程块

### 5.1 声明与驱动

| 编号 | 级别 | 规则 |
|---|---|---|
| `RTL-DRV-001` | M1 | 遵守 `CUSTOM-RTL-002`：禁止 `wire name = expression;`；声明和连续赋值分开。 |
| `RTL-DRV-002` | M1 | 每个信号只能有一个逻辑驱动源。不得同时由 `assign`、过程块、实例输出或多个过程块驱动。 |
| `RTL-DRV-003` | M1 | 过程赋值目标声明为 `reg`；网络连接和连续赋值目标声明为 `wire`。 |
| `RTL-DRV-004` | M2 | 简单直连、布尔组合或单层清晰的 2:1 选择可以使用 `assign`；包含多分支、优先级或默认处理时使用 `always @(*)`。 |
| `RTL-DRV-005` | M1 | 禁止嵌套三目运算。单层三目只有在选择条件和两条路径一眼可辨时才允许。 |

```verilog
wire req_fire;
assign req_fire = req_valid & req_ready;

reg [1:0] grant_sel;
always @(*) begin
    grant_sel = 2'b00;
    if (req_hi) begin
        grant_sel = 2'b10;
    end else if (req_lo) begin
        grant_sel = 2'b01;
    end
end
```

### 5.2 一个 always 块的职责

| 编号 | 级别 | 规则 |
|---|---|---|
| `RTL-ALWAYS-001` | M1 | 遵守 `CUSTOM-RTL-001`：一个 `always` 块默认只驱动一个左值根对象。 |
| `RTL-ALWAYS-002` | M1 | 同一向量的整体验证、位选和部分选择计为同一目标；拼接左值包含多个变量时按多个目标计。右值和敏感列表不计数。 |
| `RTL-ALWAYS-003` | M1 | 多目标例外只能用于共同控制结构或按状态集中描述更清晰的紧密寄存器组；不得跨时钟域、复位域或独立生命周期。 |
| `RTL-ALWAYS-004` | M2 | 多目标例外前必须有语义段注释，写明共同条件、分组不变量和不拆分原因，并在评审中显式确认。 |
| `RTL-ALWAYS-005` | M2 | 建议给过程块添加稳定、语义化的命名块标签，便于日志和层次定位；不要把标签当成信号名的一部分。 |

## 6. 组合逻辑

| 编号 | 级别 | 规则 |
|---|---|---|
| `RTL-COMB-001` | M1 | 组合过程必须使用 `always @(*)`；禁止手工列敏感列表。 |
| `RTL-COMB-002` | M1 | 组合过程只使用阻塞赋值 `=`，不得使用非阻塞赋值。 |
| `RTL-COMB-003` | M1 | 所有路径必须完整赋值。优先在过程开头设置默认值，再覆盖具体分支；非预期锁存器为签核错误。 |
| `RTL-COMB-004` | M1 | `case` 必须包含 `default`。状态机默认分支回到安全状态；普通译码默认分支给出确定值。 |
| `RTL-COMB-005` | M1 | 禁止 `casex`、`full_case`、`parallel_case` 等可能掩盖 X 或综合仿真差异的写法。`casez` 只有协议确实定义通配位且有评审豁免时才允许。 |
| `RTL-COMB-006` | M1 | 禁止组合环。握手 ready/valid 路径是否允许组合传播必须由接口架构明确规定，并通过 STA/形式检查。 |
| `RTL-COMB-007` | M1 | `if` 条件必须是明确的一位布尔量；多位向量需进行归约或显式比较。 |
| `RTL-COMB-008` | M2 | 所有 `if`、`else`、`case` 分支都使用 `begin/end`，即使当前只有一条语句。 |

## 7. 时序逻辑

| 编号 | 级别 | 规则 |
|---|---|---|
| `RTL-SEQ-001` | M1 | 一个时序过程只允许一个有效时钟边沿，以及可选的一个异步复位边沿。禁止同一过程混用双边沿或多个时钟。 |
| `RTL-SEQ-002` | M1 | 时序过程只使用非阻塞赋值 `<=`；禁止在可综合 RTL 中给赋值添加 `#` 延时。 |
| `RTL-SEQ-003` | M1 | 寄存器必须在所有时钟路径保持确定行为。时钟使能用 `if (enable)` 表达，不用数据时钟、纹波时钟或普通组合逻辑产生时钟。 |
| `RTL-SEQ-004` | M2 | 只复位架构、协议和安全性确实需要确定初值的寄存器；不为方便仿真而给所有数据寄存器增加复位。未复位数据在有效标志之前不得被使用。 |
| `RTL-SEQ-005` | M1 | 禁止对同一寄存器在同一时钟周期产生含糊的多次非阻塞赋值；有优先级时用完整、清晰的 `if/else` 结构。 |
| `RTL-SEQ-006` | M1 | 禁止锁存器、脉动计数器和业务逻辑生成的复位；确需特殊结构时必须使用批准单元并取得架构、STA、DFT 联合豁免。 |

## 8. 复位、时钟和 CDC

### 8.1 复位

| 编号 | 级别 | 规则 |
|---|---|---|
| `RTL-RST-001` | M1 | 默认采用低有效、异步置位、按目标时钟域同步释放的复位策略。每个时钟域使用批准的复位同步单元输出。 |
| `RTL-RST-002` | M1 | 业务寄存器只使用已经同步释放的域复位；不得直接把芯片异步复位分发到大量叶级寄存器。 |
| `RTL-RST-003` | M1 | 复位同步器必须来自批准登记表；不得在业务 RTL 中自定义两拍/三拍复位同步逻辑。 |
| `RTL-RST-004` | M2 | 复位解除顺序、跨域依赖、PLL/时钟稳定条件和测试模式旁路必须写入模块或子系统设计说明并由 RDC/STA 检查。 |
| `RTL-RST-005` | M1 | 异步复位分支只能赋确定的 0/1 常量或参数化复位值，禁止 X/Z。 |

标准叶级写法：

```verilog
always @(posedge clk_core or negedge rst_core_n) begin
    if (!rst_core_n) begin
        busy <= 1'b0;
    end else begin
        busy <= busy_next;
    end
end
```

### 8.2 时钟

| 编号 | 级别 | 规则 |
|---|---|---|
| `RTL-CLK-001` | M1 | 时钟不能作为普通数据参与逻辑；不得使用寄存器输出或组合门产生新时钟。 |
| `RTL-CLK-002` | M1 | 门控时钟只能例化批准的 ICG 单元/包装器，必须连接测试使能并纳入 CTS、STA、DFT 约束。 |
| `RTL-CLK-003` | M2 | 能用时钟使能实现的低功耗控制优先使用时钟使能；引入新时钟域需要架构和约束评审。 |
| `RTL-CLK-004` | M1 | 一个逻辑时钟域统一使用一个边沿；禁止在同一协议路径混用上升沿和下降沿采样。 |

### 8.3 CDC

| 编号 | 级别 | 规则 |
|---|---|---|
| `RTL-CDC-001` | M1 | 异步输入和跨时钟域信号必须经过已批准的 CDC 结构；不能依靠仿真未出现亚稳态判定安全。 |
| `RTL-CDC-002` | M1 | 稳定单比特电平在源端先寄存并保证无组合毛刺，再使用批准的两级或更多级同步器；级数按 MTBF 和目标时钟确定。 |
| `RTL-CDC-003` | M1 | 窄脉冲不得直接使用电平同步器。使用脉冲展宽、toggle、握手或事件计数结构，并证明事件不会丢失或重复。 |
| `RTL-CDC-004` | M1 | 多比特数据不得逐位打两拍。连续流使用异步 FIFO；低速配置使用握手保持；计数/指针按协议使用 Gray 编码。 |
| `RTL-CDC-005` | M1 | 同步器、异步 FIFO 和握手 CDC 优先从 `approved_cells.json` 例化；相关约束、属性和 CDC waiver 必须与包装器绑定。 |
| `RTL-CDC-006` | M2 | CDC 输入、输出、源域、目的域、稳定性假设和复位关系必须在语义段注释或接口说明中记录。 |

## 9. 状态机

| 编号 | 级别 | 规则 |
|---|---|---|
| `RTL-FSM-001` | M2 | 默认采用组合次态/输出加时序状态寄存器的两段式结构；如果输出需要独立寄存，按一个目标一个过程块拆分。 |
| `RTL-FSM-002` | M1 | 状态编码使用 `localparam`，位宽显式。禁止依赖未声明的整数宽度或仿真器自动枚举。 |
| `RTL-FSM-003` | M1 | 组合次态先默认保持当前态，所有 `case` 有 `default`，非法状态进入定义的安全/空闲状态。 |
| `RTL-FSM-004` | M2 | 多个紧密相关寄存器按 state 集中更新时，可采用 `CUSTOM-RTL-001` 例外；必须说明为什么按状态观察更清晰。 |
| `RTL-FSM-005` | M2 | 状态机输出是否 Moore/Mealy、握手发生条件、超时和错误恢复必须在语义段注释或设计说明中明确。 |

## 10. 参数、常量、位宽和算术

| 编号 | 级别 | 规则 |
|---|---|---|
| `RTL-WIDTH-001` | M1 | 数值常量必须显式给出位宽和进制；只有循环索引、参数计算等语义明确处可使用无位宽整数。 |
| `RTL-WIDTH-002` | M1 | 赋值、比较、拼接、移位和实例连接必须核对位宽与有符号性；禁止依赖静默截断、扩展或 signed/unsigned 混算。 |
| `RTL-WIDTH-003` | M2 | 可配置量使用 `parameter`；模块内部派生常量和状态值使用 `localparam`；相关常量由主参数计算，避免重复魔数。 |
| `RTL-WIDTH-004` | M1 | 参数必须有合法范围，生成分支必须覆盖全部允许配置；不支持的组合在 elaboration/lint 阶段明确报错。 |
| `RTL-WIDTH-005` | M2 | 移位量、加法进位、计数终值、地址与深度的非 2 次幂关系必须显式处理。 |
| `RTL-WIDTH-006` | M1 | 乘除法、开方、浮点和复杂流水算术若已有批准 IP，必须例化批准实现；不得以行为运算符绕过已确定的面积/时序架构。 |

## 11. 循环和生成

| 编号 | 级别 | 规则 |
|---|---|---|
| `RTL-GEN-001` | M1 | 只允许在 elaboration 或综合时可证明静态有界的循环；禁止数据相关、不可证明终止或含 `while/forever` 的可综合循环。 |
| `RTL-GEN-002` | M2 | 重复硬件使用命名 `generate` 块和 `genvar`；生成层次名必须稳定，便于约束和波形定位。 |
| `RTL-GEN-003` | M2 | 过程 `for` 循环的初值、终值和步进必须是静态可判定表达式；循环体不得隐藏跨迭代优先级。 |
| `RTL-GEN-004` | M1 | 参数化生成不能产生多驱动、零宽/负宽总线、越界选择或空实例连接。 |

## 13. 可综合性与仿真一致性

| 编号 | 级别 | 规则 |
|---|---|---|
| `RTL-SYN-001` | M1 | 设计 RTL 中禁止 `initial`、`wait`、`event`、`real`、`force/release`、系统任务以及 `#` 延时；专用存储器初始化只通过批准流程。 |
| `RTL-SYN-002` | M1 | 禁止 UDP、门级原语和未批准的厂商原语；标准单元/IP 通过批准包装器例化。 |
| `RTL-SYN-003` | M1 | 不得给设计状态赋 `x` 或依赖 `x` 作为 don't-care 优化；默认值和错误恢复必须确定。 |
| `RTL-SYN-004` | M1 | 禁止用综合指令掩盖不完整 RTL，例如 `translate_off` 包围设计行为、`full_case` 或 `parallel_case`。工具属性只能按签核流程使用。 |
| `RTL-SYN-005` | M1 | Lint、仿真和综合告警必须分级清零或有具体豁免；不能全局关闭一类检查来掩盖局部问题。 |
| `RTL-SYN-006` | M2 | 综合前后仿真、形式等价、CDC/RDC 和 STA 所使用的宏、参数、文件表和黑盒配置必须可追踪并保持一致。 |

## 14. 语义段注释

| 编号 | 级别 | 规则 |
|---|---|---|
| `RTL-CMT-001` | M2 | 遵守 `CUSTOM-RTL-004`：注释围绕功能段、时序段、协议段、状态转换、CDC 边界或例外组织。 |
| `RTL-CMT-002` | M2 | 注释说明“为什么、何时成立、边界是什么”，不要只把运算符和信号名翻译成自然语言。 |
| `RTL-CMT-003` | M1 | 多目标 always、CDC 假设、特殊复位/时钟结构、参数限制和规范豁免必须有语义说明并关联设计文档或豁免单。 |
| `RTL-CMT-004` | R | 简单直连且命名已完整表达含义时可以不注释，避免低信息密度注释干扰阅读。 |

本规范不规定文件头、注释比例、固定语言、装饰线长度或逐行注释。

## 15. 评审、例外和签核

1. 作者提交前执行《代码评审检查表》的 RTL 部分，并附 Lint、CDC/RDC、综合和必要的形式/仿真证据。
2. 评审意见引用稳定规则编号，例如 `CUSTOM-RTL-001` 或 `RTL-CDC-004`。
3. M1 默认不允许口头例外。确有架构原因时必须由对应 owner 批准正式豁免，列出风险、验证证据、适用实例和失效日期。
4. M2 偏离必须有书面理由和影响分析。R 项不阻断签核，但重复偏离应更新团队约定。
5. 修改四条用户规则只编辑 `config/custom_rules.json`，再执行同步工具；不得直接修改生成区块。

完整来源与历史冲突裁决见《来源与冲突裁决》。
