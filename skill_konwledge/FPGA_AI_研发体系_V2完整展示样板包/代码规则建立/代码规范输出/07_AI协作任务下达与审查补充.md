版本：1.0.0-draft  
日期：2026-09-16  
状态：征求意见稿，未作正式制度

01–06 管"代码长什么样"，本文件管"AI 参与时任务怎么下、资料怎么给、产出怎么审"。本文件不新增编码规则；编码要求仍以 01、02、03 为准，评审结论仍以 [04](04_代码评审检查表.md) 的 PASS / PASS WITH WAIVER / FAIL 为准。

## 1. 任务下达模板

不同人提问方式不同，同一模型的输出方向和可用度就不同。为减少这种方差，AI 协作任务统一按下面的骨架下达。小任务可以压缩成一段对话，但七项内容缺一不可。

```text
1 背景与目标:     要解决什么问题，做到什么程度算完成
2 输入资料:       只允许使用哪些资料（来自 trusted_sources.json 登记项，注明版本）；
                  明确写出"不得引用未登记资料作为设计依据"
3 适用规则:       本任务适用的规范文件与 profile（如 asic_signoff / fpga_project）
4 授权范围:       可读目录、可改文件清单、禁止修改的文件
5 交付件:         要交什么（方案/代码/diff/测试/报告）、格式和篇幅
6 验收条件:       由什么工具或测试裁决；模型自述完成不算证据
7 禁止事项:       不联网找资料、不扩大修改范围、不伪造运行结果、
                  不为通过检查而放宽验收
```

下达后第一轮先让 AI 复述任务边界和它认为的缺项，确认理解一致再执行。复杂任务拆小：单个任务大到人无法判断输出对错时，先拆再下发。

## 2. 可信资料规则

芯片手册/TRM、IP 官方文档、开发环境与 SDK 版本、原理图类资料必须由人提供并登记，模型不得自行联网检索替代——联网资料版本混杂且无法排除污染。

1. 资料登记在 [config/trusted_sources.json](config/trusted_sources.json)，一资料一条目，含版本、路径、负责人和状态。
2. 任务下达模板第 2 项必须引用登记条目；状态非 `approved` 的资料不得作为设计依据。
3. 联网内容只作线索，人工核实并登记后才升级为依据。
4. 资料按项目抽取所需部分进入上下文，不整库投喂；同一芯片多份手册时以登记条目为准，不由模型自选。
5. `trusted_sources.json` 与 `approved_cells.json` 分工：前者回答"依据什么资料"，后者回答"允许例化什么单元"。两者都未补齐前，相关设计保持待决。

## 3. AI 生成代码专项审查清单

04 号文检查代码本身是否符合规范；本节检查 AI 生成过程引入的特有风险。两份清单同时使用。发现任一 M 级问题，按 04 的结论规则处理。

| 完成 | 级别 | 检查项 | 典型问题与处置 |
|---|---|---|---|
| [ ] | M1 | 幻觉引用核查：生成代码涉及的 API、寄存器地址、IP 参数、总线时序逐条对照 trusted_sources 登记资料 | 模型可能生成不存在或版本不符的接口；对不上登记资料的按未确认处理，不得合入 |
| [ ] | M1 | 范围核查：实际修改文件与任务下达第 4 项授权清单逐一比对 | 顺手重构、改动未授权文件均属范围蔓延；以 diff 白名单为准 |
| [ ] | M1 | 伪报验证核查：任何"已编译/已仿真/已通过"声明必须有运行记录（命令、版本、退出码、日志位置） | 无运行记录一律视为 not_run；编造运行结果按流程事故记录 |
| [ ] | M2 | 未声明假设核查：要求 AI 随交付件列出假设清单（时钟频率、复位极性、字节序、缓冲区大小等） | 假设未列入清单而埋进代码的，评审中逐项逼问 |
| [ ] | M2 | 版本错配核查：生成写法对照任务登记的 SDK/标准/工具版本 | 用新版语法写旧工具工程、用别的平台 API 写本项目，均为错配 |
| [ ] | M2 | 功能-编译分离核查：编译通过不代表功能达成 | 功能验证必须由独立测试裁决；防止"能编译就是对的"式交付 |
| [ ] | R | 过度工程核查：实现复杂度与任务规模相称 | 为简单需求生成多层抽象、引入任务外依赖，要求删减 |

## 4. Token 成本控制

1. 增量修改优先：局部修改只提供相关文件和上下文；全量重写需说明理由。全量重写的思考量不减、输出量翻倍。
2. 上下文按任务裁剪：规则、资料、模板按需加载，默认不加载整个知识库和历史聊天。
3. 要求结构化输出（表格、diff、清单），降低人工重读和二次整理成本。
4. 按任务性质选择模型并记录效果；不把成本最高的模型当默认选项。
5. token 消耗与工具等待时间记入第 5 节的协作记录，成本可见才能优化。

## 5. 协作记录字段

每次 AI 协作任务结束时填写，用于日报和后续的重复工作统计：

```text
任务ID/日期/执行人:
AI介入环节与程度:   按环节标注（如 验证用例生成 约70%）
输入资料版本:       trusted_sources 条目编号
人工决策项:         本次由人拍板的内容（批准/驳回/待决）
工具证据:           实际运行的命令与结果；未运行写 not_run
未决问题:           遗留给下次的决策项
token与耗时估计:    量级即可，用于成本观察
回灌候选:           发现的重复工作或规则缺口；没有写"无"
```

高频重复的回灌候选汇总后按部门流程提炼为公共规则或模板；人审的产出不只是判断单次对错，更是修正规范本身，让同类审核逐步被规范替代。
