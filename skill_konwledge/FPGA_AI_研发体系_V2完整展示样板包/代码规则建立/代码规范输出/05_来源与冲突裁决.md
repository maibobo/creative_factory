## 1. 来源清单

### 1.1 本地资料

| 来源代号 | 文件 | 本次使用范围 | 说明 |
|---|---|---|---|
| `H-ASIC` | [海思ASIC工程师手册.pdf](../海思ASIC工程师手册.pdf) | 第 2.1 节，PDF 物理页 33–108（印刷页 30–105） | 规则级别、命名、组合/时序、综合、时钟复位、CDC、FSM、DFT/STA 协同 |
| `H-VLOG` | [海思verilog编程规范.pdf](../海思verilog编程规范.pdf) | 全文 | Verilog 命名、过程块、赋值、可综合性和示例 |
| `IC-NOTES` | [数字IC工作学习资料整理.docx](../数字IC工作学习资料整理.docx) | 与 RTL、CDC、SystemVerilog、UVM 直接相关的章节 | 用于交叉验证和补充方法学，不把其中复制的库源码当成规范正文 |
| `USER` | 用户明确提出的四条规则和后续选择 | 全部 | 内部规范最高优先级，除项目正式豁免外 |

本规范排除了三份本地资料中的文件头模板和一般注释排版要求。唯一纳入的注释规则是用户指定的“按语义段注释”。

原资料包含年代较早的工具假设，部分扫描/OCR 或示例出现明显拼写、字面量和延时宏问题。规范只吸收可确认的设计原则，示例均重新编写，不逐字复制可能错误的代码。

联网资料只用于独立的 SystemVerilog/UVM 验证规范，不把 SystemVerilog 语言基线反向扩展到 ASIC RTL。

## 2. 优先级和裁决方法

1. IEEE 语言标准决定语法和语义；内部规范不能定义与标准相反的语言行为。
2. 项目正式批准的架构/签核决定和豁免单决定特定实例是否例外。
3. 用户自定义规则决定项目编码约束，优先于历史资料中的推荐或示例。
4. 本规范为适应当前 ASIC 流程作出的新增裁决，高于旧资料中已经过时或互相矛盾的细节。
5. 多个旧来源一致且仍适用的内容保留为 M1/M2/R；无法验证的经验描述不升级为强制规则。

每项豁免至少记录：规则编号、实例/配置范围、技术原因、风险、验证证据、批准人、到期或复审条件。不能以“工具没有报错”代替规则符合性证明。

## 3. 已裁决冲突

| 议题 | 历史资料/用户意见 | 本规范裁决 | 理由 |
|---|---|---|---|
| RTL 语言版本 | 手册文字仍偏向 Verilog-95，但同时介绍 `always @(*)`、generate 等较新结构 | 使用可综合 Verilog-2001 子集 | 与当前工具和用户写法一致，同时保持 ASIC RTL 不使用 SystemVerilog |
| `assign` 使用范围 | 旧资料有“assign 只用于改名/直连”的保守建议；用户要求 wire 用 assign 或过程组合逻辑 | 允许清晰的单表达式连续赋值；分支/优先级逻辑用 `always @(*)` | 保留显式驱动，避免把简单逻辑机械改成过程块 |
| wire 声明赋值 | 部分现代语法允许声明时初始化；用户明确禁止 | M1 禁止，声明和 assign 分离 | 用户规则优先，并简化驱动检查 |
| 一个 always 的目标数 | 历史示例常在一个时序块更新多个寄存器；用户默认一个信号，给出共同条件/FSM例外 | 按左值根对象计数，默认一个；严格定义两类例外并要求注释/评审 | 把用户意图转成可检查规则，同时保留状态机可读性 |
| 多目标中的向量切片 | 原资料未明确 | 同一根向量的位选/部分选择算一个目标；拼接中的不同变量分别计数 | 避免按语法片段错误扩大目标数量 |
| 标准单元与技术独立 | 旧资料强调技术独立；用户要求 FIFO、同步器、DMUX 等直接例化成品单元 | 业务 RTL 例化批准的技术无关包装器；技术依赖集中在平台/工艺层 | 同时满足复用、签核和可迁移性 |
| Vivado 宏 | 用户允许 FIFO 使用 Vivado 支持的宏 | 只允许 FPGA 原型 profile 的包装层使用 XPM，禁止进入 ASIC signoff 文件表 | 防止 FPGA 原语污染 ASIC RTL |
| 同步级数 | 资料有两拍或三拍表述；用户举例“两拍同步” | 两级是稳定单比特电平的默认最小值，实际级数由 MTBF 决定，必须使用批准单元 | 不把示例级数误当作所有频率/工艺的充分条件 |
| 多比特同步 | 学习资料指出不能逐位打两拍 | 使用握手、Gray 或异步 FIFO | 防止各位采样不一致 |
| 复位方式 | 资料同时包含同步复位倾向和异步复位讨论；用户已选择异步置位、同步释放 | 默认低有效异步置位、每时钟域同步释放 | 明确统一项目基线，同时要求 RDC/STA 处理 |
| 名称长度 | 手册约 20 字符，学习资料摘录约 32 字符 | 不设硬上限，要求简洁且满足工具/库限制 | 原资料互相矛盾，现代层次命名常需要更多信息 |
| 行宽 | 旧资料采用 72 列 | 建议约 100 列，不作为签核硬门槛 | 保持可读性但不迫使端口表和长名称异常换行 |
| 模块/文件大小写 | 旧资料同时强调对应关系、模块大写和一般小写命名 | 模块大写下划线，文件小写下划线，忽略大小写后对应 | 保留海思风格并消除表面冲突 |
| `begin/end` | 旧示例常省略单语句块 | 所有控制分支都使用 `begin/end` | 降低后续加语句导致的悬挂 else/漏包围风险 |
| 循环 | 部分旧建议笼统要求避免 for | 允许静态有界过程循环和命名 generate；禁止动态/不可证明有界循环 | 与综合语义一致并支持参数化硬件 |
| 时序赋值延时 | 旧示例可能含 `#` 或 ``DLY`` | 可综合 RTL 中完全禁止赋值延时 | 避免仿真/综合行为不一致 |
| X/don't-care | 旧优化方法可能利用 X | 设计状态不赋 X，不用 casex/full_case/parallel_case 掩盖不完整逻辑 | 强化 X 安全和仿真/综合一致性 |
| UVM 运行与现代标准 | 当前环境是 UVM 1.2，当前标准映射是 IEEE 1800.2-2020 | 示例只用 UVM 1.2 可执行 API；文档单列现代映射 | 标准对齐不能冒充旧工具已经支持新 API |
