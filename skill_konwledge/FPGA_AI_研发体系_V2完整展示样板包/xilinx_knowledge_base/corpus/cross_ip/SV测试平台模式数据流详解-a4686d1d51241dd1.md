# SV 测试平台模式（SystemVerilog Testbench）数据流架构详解

> 本文档详述 SV 测试平台模式下的完整数据流，覆盖接口绑定、随机计划生成、BFM 驱动、监控器采集、9 级队列比对、地址检查、帧标记检查的全链路，以及两种 harness 的差异。

## 一、模式概述

SV 测试平台模式使用 SystemVerilog 类实现 BFM/监控器/记分板，通过 `virtual interface` 绑定到静态例化的 harness，实现验证逻辑与 DUT 结构解耦。

| 维度 | SV 仿真模式 | 硬件调试模式 |
|------|-------------|-------------|
| 顶层 | `tc_*_top` 模块 + `harness` 静态例化 | `fdma_aurora_brg_aurora_loop_hw` |
| FDMA 从机 | `tc_base` 类的 BFM task | `fdma_hw_test_engine` RTL |
| 数据源 | LCG 随机 64bit 数据 | 确定性 `{frame,word}` |
| 比对方式 | 9 级队列离线逐级比对 | 硬件实时比对 + 首次错误锁存 |
| 观测手段 | SV 监控器 + `$display` | ILA 波形 |
| 反压控制 | `cfg_*` 随机延迟参数 | 固定 `rvalid<=rready` |
| 可复现性 | `+SEED=` plusarg | 上电即确定 |

## 二、测试平台层次架构

```
tc_*_top (模块)
├── harness h()                          ← 静态例化 DUT + 接口 + 时钟/复位
│   ├── aurora_loop_harness              ← 完整环回（桥+Aurora+GT）
│   │   └── fdma_aurora_brg_aurora_loop  ← DUT
│   │       ├── fdma_aurora_brg_top      ← 桥
│   │       └── aurora_64b66b_top        ← Aurora 核
│   └── brg_harness                      ← 直接桥（仅桥，无 Aurora）
│       └── fdma_aurora_brg_top          ← DUT
│
├── rd_if/wr_if/ll_if/ctrl_if/obs_if     ← 5 个接口实例
│
└── initial 块
    ├── resolve_seed() / resolve_verbose()  ← 解析 plusarg
    ├── test = new(seed, verbose, vifs...)  ← 构造 tc 类，绑定 virtual interface
    ├── test.run()                          ← 生命周期主流程
    └── $fatal / $finish                    ← 结果上报
```

## 三、接口绑定数据流

### 3.1 静态例化（harness 内）

```systemverilog
// harness 中静态例化接口（以 aurora_loop_harness 为例）
fdma_read_if  rd_if(fdma_clk, fdma_rstn);   // 接口实例，绑定时钟/复位
fdma_write_if wr_if(fdma_clk, fdma_rstn);
ll_link_if    ll_if(user_clk, user_rstn);
brg_ctrl_if   ctrl_if();                    // 无时钟（验证专用）
brg_obs_if    obs_if(fdma_clk, user_clk);

// DUT 例化，端口连接到接口信号
fdma_aurora_brg_aurora_loop dut(
    .fdma_raddr(rd_if.raddr),  .fdma_rareq(rd_if.rareq),
    .fdma_rbusy(rd_if.rbusy),  .fdma_rdata(rd_if.rdata),
    ...
);
```

### 3.2 动态绑定（tc_top initial 内）

```systemverilog
// tc_top 的 initial 块
test = new(seed, verbose,
           h.rd_if,    // 传递接口实例给类的 virtual interface 句柄
           h.wr_if,
           h.ll_if,
           h.ctrl_if,
           h.obs_if);
test.run();
```

**关键机制**：`virtual interface` 句柄在 `new()` 中绑定到静态接口实例，此后 BFM/监控器通过 `rd_vif.cb.rbusy <= 1'b1` 等语句驱动/采样实际信号，实现验证逻辑与结构分离。

## 四、随机计划生成数据流

### 4.1 configure() 阶段

```
tc_base.configure() [virtual]
  └── 派生类覆盖：
      ├── tc_aurora_loop_nobp: num_frames=rand_range(1,3), enable_backpressure=0
      ├── tc_aurora_loop_bp:   num_frames=rand_range(1,3), enable_backpressure=1
      ├── tc_aurora_loop_addr_wrap: num_frames=rand_range(9,12), enable_backpressure=0
      ├── tc_brg_tx_fifo_waterline: num_frames=8, enable_backpressure=0
      └── 其他: 按需设置
```

### 4.2 build_random_plan() 阶段

```
build_random_plan()
  │
  ├── total_words = num_frames * FRAME_WORDS (64)
  │
  ├── 分配 6 个延迟数组：
  │   ├── rd_accept_delay[num_frames]      ← rareq→rbusy 延迟
  │   ├── wr_accept_delay[num_frames]      ← wareq→wbusy 延迟
  │   ├── rd_inter_burst_gap[num_frames]   ← burst 间间隔
  │   ├── wr_inter_burst_gap[num_frames]   ← burst 间间隔
  │   ├── rd_valid_gap[total_words]        ← 每 word 的 rvalid 低电平
  │   └── wr_ready_stall[total_words]      ← 每 word 的 wready 低电平
  │
  ├── 生成 expected_q：
  │   for (i=0; i<total_words; i++):
  │     word_data = {next_rand(), next_rand()}  ← LCG 随机 64bit
  │     expected_q.push_back(word_data)
  │
  ├── 填充延迟数组（choose_delay 基于 enable_backpressure + prob）：
  │   for (i=0; i<num_frames; i++):
  │     rd_accept_delay[i] = choose_delay(30, 1, 8)
  │     wr_accept_delay[i] = choose_delay(30, 1, 8)
  │     rd_inter_burst_gap[i] = choose_delay(30, 1, 8)
  │     wr_inter_burst_gap[i] = choose_delay(30, 1, 8)
  │   for (i=0; i<total_words; i++):
  │     rd_valid_gap[i] = choose_delay(20, 1, 4)
  │     wr_ready_stall[i] = choose_delay(20, 1, 4)
  │
  └── apply_directed_plan() [virtual]
      └── 派生类覆盖以注入定向故障：
          ├── tc_brg_rd_ready_stall: 选 stall_word/stall_cycles
          ├── tc_brg_wr_ready_stall: 注入 3 个 stall 点
          └── tc_brg_rx_fifo_overflow: 不用此机制（覆盖 run()）
```

**关键设计**：所有随机决策在并发 BFM 启动前一次性生成，确保同一种子产生同一计划，完全可复现。

## 五、BFM 驱动数据流

### 5.1 fdma_read_slave() 读 BFM

```
fdma_read_slave() [forever]
  │
  ├── burst_idx = 0
  │
  └── while (burst_idx < num_frames):
      │
      ├── 等待 rareq && !rbusy
      ├── fdma_rd_addr_q.push_back(raddr)          ← 捕获地址
      ├── repeat(rd_accept_delay[burst_idx]) @cb   ← 响应延迟
      ├── rd_vif.cb.rbusy <= 1                     ← 接受请求
      │
      ├── for (word_idx=0; word_idx<64; word_idx++):
      │   ├── global_idx = burst_idx*64 + word_idx
      │   ├── repeat(rd_valid_gap[global_idx]) @cb ← rvalid 低电平间隔
      │   ├── rd_vif.cb.rdata <= expected_q[global_idx]
      │   ├── rd_vif.cb.rvalid <= 1
      │   ├── on_read_word_presented(global_idx)   ← 定向注入钩子
      │   └── 等 rvalid && rready 握手
      │
      ├── rd_vif.cb.rvalid <= 0
      ├── repeat(rd_inter_burst_gap[burst_idx]+1) @cb
      ├── rd_vif.cb.rbusy <= 0
      └── burst_idx++
```

**数据流**：`expected_q[i]` → `rd_vif.cb.rdata` → DUT TX 桥 `fdma_rdata` → TX FIFO。

### 5.2 fdma_write_slave() 写 BFM

```
fdma_write_slave() [forever]
  │
  ├── burst_idx = 0
  │
  └── while (burst_idx < num_frames):
      │
      ├── 等待 wareq && !wbusy
      ├── fdma_wr_addr_q.push_back(waddr)          ← 捕获地址
      ├── 检查 wsize == 512
      ├── repeat(wr_accept_delay[burst_idx]) @cb   ← 响应延迟
      ├── wr_vif.cb.wbusy <= 1                     ← 接受请求
      │
      ├── for (word_idx=0; word_idx<64; word_idx++):
      │   ├── global_idx = burst_idx*64 + word_idx
      │   ├── stall_cycles = wr_ready_stall[global_idx]
      │   ├── if (stall_cycles == 0):
      │   │     wr_vif.cb.wready <= 1              ← 立即就绪
      │   ├── else:
      │   │     wr_vif.cb.wready <= 0              ← 拉低 wready
      │   │     check_write_data_stable(stall_cycles) ← 检查 wdata 稳定性
      │   │     wr_vif.cb.wready <= 1              ← 释放
      │   └── 等 wvalid && wready 握手
      │
      ├── repeat(wr_inter_burst_gap[burst_idx]+1) @cb
      ├── wr_vif.cb.wbusy <= 0
      ├── wr_vif.cb.wready <= 0
      └── burst_idx++
```

**数据流**：DUT RX 桥 `fdma_wdata` → `wr_vif.cb.wdata` → 监控器采集入 `fdma_wr_hs_q`。

### 5.3 check_write_data_stable() 稳定性检查

```
check_write_data_stable(stall_cycles)
  │
  ├── 等 wvalid=1
  ├── held_data = wdata                            ← 锁存首个值
  │
  └── for (i=0; i<stall_cycles; i++):
      ├── @cb
      ├── if (wvalid !== 1): record_error("wvalid dropped")
      └── if (wdata !== held_data): record_error("wdata changed")
```

**验证点**：AXI 协议要求 `wvalid` 拉高后 `wdata` 必须保持稳定直到握手成功，此 task 验证 DUT 遵守该协议。

## 六、监控器采集数据流

### 6.1 monitor_fdma_and_fifos() — fdma_clk 域监控

```
monitor_fdma_and_fifos() [forever]
  │
  └── @posedge rd_vif.clk:
      │
      ├── X/Z 检测（首次）：
      │   if $isunknown({rareq,rbusy,rvalid,rready,wareq,wbusy,wvalid,wready}):
      │     record_error("X/Z on FDMA control")
      │
      ├── 读握手采集：
      │   if (rvalid && rready):
      │     if $isunknown({rdata,raddr}): record_error("X/Z on FDMA read")
      │     fdma_rd_hs_q.push_back(rdata)          ← 队列 1
      │
      ├── TX FIFO 写采集：
      │   if (obs_vif.tx_fifo_wr_en):
      │     tx_fifo_wr_q.push_back(tx_fifo_wdata)  ← 队列 2
      │
      ├── RX FIFO 读采集：
      │   if (obs_vif.rx_fifo_rd_en):
      │     rx_fifo_rd_q.push_back(rx_fifo_rdata)  ← 队列 7
      │
      ├── 写握手采集：
      │   if (wvalid && wready):
      │     if $isunknown({wdata,waddr}): record_error("X/Z on FDMA write")
      │     fdma_wr_hs_q.push_back(wdata)          ← 队列 9
      │
      ├── FIFO 峰值更新：
      │   if (tx_fifo_wr_cnt > tx_fifo_peak): tx_fifo_peak = tx_fifo_wr_cnt
      │   if (rx_fifo_rd_cnt > rx_fifo_peak): rx_fifo_peak = rx_fifo_rd_cnt
      │
      └── FIFO 异常检测：
          if (tx_fifo_overflow):  record_error("TX FIFO overflow")
          if (tx_fifo_underflow): record_error("TX FIFO underflow")
          if (rx_fifo_overflow):  record_error("RX FIFO overflow")
          if (rx_fifo_underflow): record_error("RX FIFO underflow")
```

### 6.2 monitor_ll_and_rx_fifo() — user_clk 域监控

```
monitor_ll_and_rx_fifo() [forever]
  │
  └── @ll_vif.mon_cb:
      │
      ├── X/Z 检测（首次）：
      │   if $isunknown({tx_sof,tx_eof,tx_rem,tx_src_rdy,tx_dst_rdy,
      │                  rx_sof,rx_eof,rx_rem,rx_src_rdy,rx_dst_rdy}):
      │     record_error("X/Z on LL control")
      │
      ├── LL TX 握手采集：
      │   if (tx_src_rdy && tx_dst_rdy):
      │     if $isunknown(tx_d): record_error("X/Z on LL TX")
      │     check_frame_markers("LL_TX", tx_frame_word_count, tx_sof, tx_eof, tx_rem)
      │     ll_tx_q.push_back(tx_d)                ← 队列 4
      │     if (tx_frame_word_count==63): tx_frame_count++, word_count=0
      │     else: tx_frame_word_count++
      │
      ├── TX FIFO 读采集：
      │   if (obs_vif.tx_fifo_rd_en):
      │     tx_fifo_rd_q.push_back(tx_fifo_rdata)  ← 队列 3
      │
      ├── LL RX 握手采集：
      │   if (rx_src_rdy && rx_dst_rdy):
      │     if $isunknown(rx_d): record_error("X/Z on LL RX")
      │     check_frame_markers("LL_RX", rx_frame_word_count, rx_sof, rx_eof, rx_rem)
      │     ll_rx_q.push_back(rx_d)                ← 队列 5
      │     if (rx_frame_word_count==63): rx_frame_count++, word_count=0
      │     else: rx_frame_word_count++
      │
      ├── RX FIFO 写采集：
      │   if (obs_vif.rx_fifo_wr_en):
      │     rx_fifo_wr_q.push_back(rx_fifo_wdata)  ← 队列 6
      │
      └── RX FIFO 峰值更新：
          if (rx_fifo_wr_cnt > rx_fifo_peak): rx_fifo_peak = rx_fifo_wr_cnt
```

### 6.3 check_frame_markers() 帧标记检查

```
check_frame_markers(direction, word_in_frame, sof, eof, rem)
  │
  ├── if (sof !== (word_in_frame==0)):
  │     record_error("SOF error")          ← SOF 必须在 word 0
  ├── if (eof !== (word_in_frame==63)):
  │     record_error("EOF error")          ← EOF 必须在 word 63
  └── if (word_in_frame==63 && rem!==111):
        record_error("REM error")          ← EOF 时 rem 必须全 1
```

## 七、9 级队列比对数据流

### 7.1 队列定义与采集点

```
expected_q          ← build_random_plan() 生成（随机源数据）
   │
   ▼ [读 BFM 驱动 → DUT 采样]
fdma_rd_hs_q        ← monitor: rvalid && rready 时的 rdata
   │
   ▼ [TX 桥写入 TX FIFO]
tx_fifo_wr_q        ← monitor: tx_fifo_wr_en 时的 fifo_wdata
   │
   ▼ [TX FIFO FWFT 读出]
tx_fifo_rd_q        ← monitor: tx_fifo_rd_en 时的 fifo_rdata
   │
   ▼ [Aurora TX 引擎发送]
ll_tx_q             ← monitor: tx_src_rdy && tx_dst_rdy 时的 tx_d
   │
   ▼ [GT 自环回 → Aurora RX]
ll_rx_q             ← monitor: rx_src_rdy && rx_dst_rdy 时的 rx_d
   │
   ▼ [RX 桥写入 RX FIFO]
rx_fifo_wr_q        ← monitor: rx_fifo_wr_en 时的 fifo_wdata
   │
   ▼ [RX FIFO FWFT 读出]
rx_fifo_rd_q        ← monitor: rx_fifo_rd_en 时的 fifo_rdata
   │
   ▼ [RX 桥写引擎驱动 FDMA 写接口]
fdma_wr_hs_q        ← monitor: wvalid && wready 时的 wdata
```

### 7.2 check_results() 比对流程

```
check_results()
  │
  ├── compare_data_queues("expected",    expected_q,    "fdma_rd_hs",  fdma_rd_hs_q)
  ├── compare_data_queues("fdma_rd_hs",  fdma_rd_hs_q,  "tx_fifo_wr",  tx_fifo_wr_q)
  ├── compare_data_queues("tx_fifo_wr",  tx_fifo_wr_q,  "tx_fifo_rd",  tx_fifo_rd_q)
  ├── compare_data_queues("tx_fifo_rd",  tx_fifo_rd_q,  "ll_tx",       ll_tx_q)
  ├── compare_data_queues("ll_tx",       ll_tx_q,       "ll_rx",       ll_rx_q)
  ├── compare_data_queues("ll_rx",       ll_rx_q,       "rx_fifo_wr",  rx_fifo_wr_q)
  ├── compare_data_queues("rx_fifo_wr",  rx_fifo_wr_q,  "rx_fifo_rd",  rx_fifo_rd_q)
  ├── compare_data_queues("rx_fifo_rd",  rx_fifo_rd_q,  "fdma_wr_hs",  fdma_wr_hs_q)
  ├── compare_data_queues("expected",    expected_q,    "fdma_wr_hs",  fdma_wr_hs_q)  ← 端到端
  │
  ├── check_addresses()
  │
  ├── if (tx_frame_count != num_frames): record_error("TX frame count")
  ├── if (rx_frame_count != num_frames): record_error("RX frame count")
  └── if (tx_frame_word_count!=0 || rx_frame_word_count!=0):
        record_error("partial LL frame remained")
```

### 7.3 compare_data_queues() 比对逻辑

```
compare_data_queues(lhs_name, lhs, rhs_name, rhs)
  │
  ├── 长度检查：
  │   if (lhs.size() != rhs.size()):
  │     record_error("length mismatch")
  │
  ├── 逐 word 比对（仅报首个不匹配）：
  │   min_size = min(lhs.size, rhs.size)
  │   for (i=0; i<min_size; i++):
  │     if (lhs[i] !== rhs[i] && !mismatch_reported):
  │       record_error("first mismatch at i")
  │       mismatch_reported = 1
  │
  └── 打印摘要：
      $display("[COMPARE] %s/%s size=%0d/%0d first=%h/%h last=%h/%h status=%s",
               ..., (length_mismatch||mismatch_reported)?"FAIL":"PASS")
```

**关键设计**：9 级逐级比对可定位首个出错阶段。例如：
- `expected vs fdma_rd_hs` 失败 → 读 BFM 驱动错误；
- `fdma_rd_hs vs tx_fifo_wr` 失败 → TX 桥读引擎错误；
- `tx_fifo_wr vs tx_fifo_rd` 失败 → TX FIFO 数据损坏；
- `ll_tx vs ll_rx` 失败 → Aurora 传输错误；
- `rx_fifo_rd vs fdma_wr_hs` 失败 → RX 桥写引擎错误。

### 7.4 check_addresses() 地址检查

```
check_addresses()
  │
  ├── 检查读/写地址队列长度 == num_frames
  │
  ├── 期望地址序列：
  │   expected_addr = 0
  │   for (i=0; i<num_frames; i++):
  │     if (fdma_rd_addr_q[i] !== expected_addr): record_error
  │     if (fdma_wr_addr_q[i] !== expected_addr): record_error
  │     if (expected_addr + 512 >= 4096): expected_addr = 0  ← 回绕
  │     else: expected_addr += 512
  │
  └── 打印每 burst 的期望/实际读/写地址
```

## 八、生命周期主流程数据流

### 8.1 run() 主流程

```
run() [virtual]
  │
  ├── 1. configure()                    ← 派生类设置帧数/反压
  ├── 2. build_random_plan()            ← 生成数据+延迟计划
  ├── 3. initialize_drivers()           ← 驱动所有信号到 idle
  ├── 4. print_configuration()          ← 打印配置
  ├── 5. pre_start()                    ← 派生类钩子（如拉低 tx_dst_rdy）
  │
  ├── 6. fork
  │     ├── fdma_read_slave()           ← 读 BFM（forever）
  │     ├── fdma_write_slave()          ← 写 BFM（forever）
  │     ├── monitor_fdma_and_fifos()    ← fdma_clk 监控（forever）
  │     └── monitor_ll_and_rx_fifo()    ← user_clk 监控（forever）
  │   join_none                         ← 并发启动，不等待
  │
  ├── 7. wait_for_channel_up()          ← 等 channel_up（超时 500000 周期）
  ├── 8. after_channel_up()             ← 派生类钩子（如等 almost_full）
  ├── 9. if (error_count==0): wait_for_completion()  ← 等所有写 word 完成
  │
  ├── 10. stop_requested = 1            ← 通知 BFM/监控器退出
  ├── 11. repeat(4) @posedge clk        ← 等退出传播
  ├── 12. disable fork                  ← 强制终止残留任务
  │
  ├── 13. check_results()               ← 9 级队列比对 + 地址/帧检查
  ├── 14. 打印 FIFO 峰值/帧计数
  └── 15. 打印 TEST_PASS / TEST_FAIL
```

### 8.2 wait_for_completion() 完成判定

```
wait_for_completion()
  │
  ├── max_cycles = is_full_loop ? 500000 : 100000
  │
  ├── while (fdma_wr_hs_q.size() < total_words && cycles < max_cycles):
  │     @posedge clk
  │     cycles++
  │
  ├── if (fdma_wr_hs_q.size() < total_words):
  │     record_error("completion timeout")
  │
  └── else: repeat(100) @ll_vif.mon_cb  ← 额外等 100 LL 周期确保排空
```

## 九、两种 harness 的数据流差异

### 9.1 brg_harness（直接桥）

```
[读 BFM] → rd_if → fdma_aurora_brg_top (TX桥) → ll_if.tx_*
                                                        │
                                                        ▼
                                              assign ll_if.rx_* = ll_if.tx_*
                                              （或 ctrl_if.rx_drive_* 直接注入）
                                                        │
                                                        ▼
[写 BFM] ← wr_if ← fdma_aurora_brg_top (RX桥) ← ll_if.rx_*
```

**特点**：
- 无 Aurora 核，无 GT，无初始化等待；
- `channel_up` 由 harness 合成（复位后 4 拍拉高）；
- LL 环回通过 `assign` 直接连线，可注入故障；
- `ctrl_if.can_drive_tx_dst_rdy=1`，测试平台可控制 `tx_dst_rdy`；
- 支持 `force` DUT 内部信号（如 `fifo_almost_full`）；
- 用于 FIFO 边界、反压定向测试。

### 9.2 aurora_loop_harness（完整环回）

```
[读 BFM] → rd_if → fdma_aurora_brg_aurora_loop
                        │
                        ├── fdma_aurora_brg_top (TX桥) → ll_tx_*
                        │                                   │
                        │                                   ▼
                        ├── aurora_64b66b_top (Aurora 核)
                        │     ├── 64b→66b 编码 → GT TX
                        │     ├── GT 物理自环 (TXP→RXP)
                        │     ├── GT RX → 66b→64b 解码
                        │     └── channel_up/lane_up/user_clk/user_rstn
                        │                                   │
                        │                                   ▼
                        ├── fdma_aurora_brg_top (RX桥) ← ll_rx_*
                        │
                        └── ll_if 仅观察（assign 自 dut.ll_tx/rx_*）
                              │
                              ▼
[写 BFM] ← wr_if ← fdma_aurora_brg_aurora_loop
```

**特点**：
- 含 Aurora IP + GT，真实物理自环；
- `channel_up` 来自 Aurora 核（约 29ms 初始化）；
- `ctrl_if.can_drive_tx_dst_rdy=0`，Aurora 核拥有 `tx_dst_rdy`；
- 不支持 `force` DUT 内部信号；
- 用于端到端功能验证、地址回绕覆盖。

## 十一、随机种子与可复现性数据流

### 11.1 种子解析

```
命令行: xelab ... +SEED=260622 +VERBOSE=2
                │           │
                ▼           ▼
         resolve_seed()  resolve_verbose()
                │           │
                ├── $value$plusargs("SEED=%d", seed)

                │
                └── $value$plusargs("VERBOSE=%d", verbose)
```

### 11.2 LCG 随机序列

```
rng_state = seed
next_rand():
  rng_state = (rng_state * 1664525) + 1013904223  ← Numerical Recipes LCG
  return rng_state

rand_range(low, high):
  return low + (next_rand() % (high-low+1))
```

**可复现性**：同一 `+SEED=` 产生完全相同的 `expected_q` 与所有延迟数组，从而产生完全相同的 BFM 行为与监控器采集结果，实现确定性回归。

## 十四、关键设计要点

### 14.1 clocking block #1step

```systemverilog
clocking cb @(posedge clk);
    default input #1step output #1step;
```
- `input #1step`：在时钟沿前一个时间步采样，避免与 DUT NBA 更新竞争；
- `output #1step`：在时钟沿后一个时间步驱动，给 DUT 足够采样时间；
- 消除 SV 仿真中最常见的竞争条件。

### 14.2 9 级队列定位法

每个协议边界一个队列，逐级比对可立即定位首个出错阶段，无需反复跑仿真缩小范围。这是本平台的核心设计优势。

### 14.3 随机+定向结合

- 随机测试（`tc_aurora_loop_bp/nobp`）：覆盖正常场景与随机反压；
- 定向测试（`tc_brg_*`）：覆盖 FIFO 边界、协议违例等罕见场景；
- `apply_directed_plan()` 钩子允许在随机计划基础上注入定向故障。

### 14.4 虚函数多态

`configure()/pre_start()/after_channel_up()/apply_directed_plan()/on_read_word_presented()/run()` 均为 `virtual`，派生类按需覆盖，基类 `run()` 主流程不变，实现开闭原则。

### 14.5 disable fork 安全退出

`stop_requested=1` 通知 BFM/监控器在下一个 `@cb` 检查点退出，`disable fork` 强制终止残留任务，避免任务泄漏影响下一轮仿真。

| 计数器鲁棒 | — | TP-H3 | 饱和不回绕 |

## 十七、可借鉴 Skills（设计/验证/上板方法论卡）

> 以下为提炼的可复用方法论卡，可直接喂给 codex/gpt 作为项目设计、验证、上板阶段的指导 prompt。每张卡含：场景、核心做法、关键代码模式、适用边界。

### Skill-1：多级队列逐级记分板（SV 验证）

```
ROLE: SystemVerilog 验证架构师
SCENARIO: 需要验证一条多级数据通路（源→FIFO→协议转换→链路→FIFO→宿），定位首个出错阶段。
METHOD:
  - 在每个协议边界设一个监控队列（unbounded queue），按握手时刻采集实际数据。
  - 期望数据单独生成一个 expected_q。
  - check_results() 按通路顺序逐级 compare_data_queues(lhs, rhs)，首个不等即定位故障阶段。
  - 每级比对仅报首个不匹配（sticky 标志），避免日志爆炸。
KEY PATTERN:
  expected_q → q1 → q2 → q3 → ... → qN → 宿
  compare_data_queues("expected","q1",expected_q,q1);  // 逐级
  compare_data_queues("expected","宿",expected_q,宿);   // 端到端兜底
APPLICABLE: 任何多级流水/多级 FIFO 通路的功能验证，仿真阶段。
REFERENCE: tc_base.sv#L608-L627 (9 级队列)
```

### Skill-2：虚函数生命周期钩子 + 随机/定向融合（SV 验证）

```
ROLE: SystemVerilog 验证框架设计师
SCENARIO: 一个基类 run() 主流程固定，但不同测试用例需在特定阶段注入不同行为。
METHOD:
  - 基类定义虚函数钩子：configure()/pre_start()/after_channel_up()/apply_directed_plan()/on_read_word_presented()。
  - run() 按固定顺序调用钩子，派生类只覆盖需要的钩子（开闭原则）。
  - 随机计划由 build_random_plan() 统一生成；定向故障通过 apply_directed_plan() 在随机计划上叠加（如注入 stall 点）。
  - on_read_word_presented(global_index) 提供逐 word 回调，支持"在第 N 个 word 注入故障"。
KEY PATTERN:
  virtual task pre_start(); endtask        // 默认空
  virtual task run(); configure(); ...; pre_start(); fork ...; endtask
APPLICABLE: 任何需要随机+定向混合覆盖的 UVM-like 验证平台。
REFERENCE: tc_base.sv#L155-L172, L680-L706
```

### Skill-3：LCG 种子 + plusarg 可复现随机（SV 验证）

```
ROLE: 仿真回归工程师
SCENARIO: 随机测试需可复现，且种子可通过命令行/GUI 传入。
METHOD:
  - resolve_seed(): $value$plusargs("SEED=%d") 优先；无则 $urandom_range(1,999999)。
  - next_rand(): Numerical Recipes LCG (state = state*1664525 + 1013904223)。
  - 所有随机延迟/数据均由 next_rand()/rand_range() 派生，同种子→同序列→同 BFM 行为。
  - 日志打印 seed_source(PLUSARG/AUTO)+seed，失败时直接用该 seed 复现。
KEY PATTERN:
  rng_state = seed;  // 全局唯一随机源
  rand_range(lo,hi) = lo + (next_rand() % (hi-lo+1));
APPLICABLE: 任何需确定性回归的随机仿真，无 UVM 时尤为实用。
REFERENCE: tc_base.sv#L21-L42, L131-L140
```

### Skill-4：异步 FIFO 反压 + 跨时钟域设计（RTL 设计）

```
ROLE: RTL 设计工程师
SCENARIO: 两个异步时钟域之间传突发数据，需防溢出且不丢数。
METHOD:
  - 用 XPM_FIFO_ASYNC（Xilinx 原语）实现异步 FIFO，FWFT 模式读延迟 0。
  - 设 almost_full 阈值（如 448/512），提前反压上游 rready=0，留余量吸收握手延迟。
  - 设 almost_empty 阈值，下游预取（wdata_hold）避免气泡。
  - overflow/underflow 标志接观测，验证阶段必须为 0。
  - 深度按"上游最大突发 + 下游最长反压时间"留 2x 余量。
KEY PATTERN:
  fifo_almost_full → upstream_rready = 0;   // 写侧反压
  wdata_hold <= fifo_rdata; valid=1;        // 读侧预取
APPLICABLE: 任何跨时钟域突发传输（FDMA↔Aurora、AXI↔串行器等）。
REFERENCE: TX FIFO 深512/阈值448, RX FIFO 深2048/阈值2032
```

### Skill-5：可综合硬件从机 + VIO/ILA 上板调试（上板验证）

```
ROLE: FPGA 上板调试工程师
SCENARIO: 仿真验证通过后需上板，但 SV BFM 不可综合，需在线观测与控制。
METHOD:
  - 编写可综合 fdma_hw_test_engine：用确定性数据源 {frame,word} 替代随机源，硬件实时比对。
  - dbg_bus 打包所有计数器/错误寄存器为单条总线，送 ILA 采样 + 顶层解包送 VIO。
  - status_bus 打包测试状态机（running/done/pass/result_code/first_error_index/class）。
  - VIO probe_out 提供运行控制（start/clear/auto_enable/frame_limit），无需重编程即可多次重跑。
  - 计数器全部饱和设计（到 0xFFFFFFFF 停），防长时间运行回绕。
  - 首次错误仅锁存一次（sticky），first_error_index/class 直接定位全局出错位置。
  - ILA 统一用 fdma_clk 采样（避免 Vivado Debug Hub 多时钟域 bug）。
KEY PATTERN:
  dbg_bus[256:0] = {rd_total, wr_total, burst*, error_count, sticky, first_err_exp, first_err_act};
  VIO: probe_out=start/clear/auto/limit; probe_in=status+counters;
APPLICABLE: 任何 FPGA 上板功能验证，尤其带高速接口（Aurora/PCIe/ETH）的环路验证。
REFERENCE: fdma_aurora_brg_aurora_loop_hw.v#L96-L147
```

### Skill-6：Aurora GT 物理自环回验证（上板验证）

```
METHOD:
```

### Skill-7：clocking block #1step 消除 SV 竞争（SV 验证）

```
ROLE: SystemVerilog 仿真工程师
SCENARIO: BFM 与 DUT 在同一时钟沿更新/采样，出现竞争（采样到旧值或 X）。
METHOD:
  - clocking cb @(posedge clk); default input #1step output #1step;
  - input #1step：在时钟沿前一个时间步采样，避开 DUT NBA 更新；
  - output #1step：在时钟沿后一个时间步驱动，给 DUT 足够采样时间；
  - 监控专用 clocking 用纯 input #1step（不驱动）。
KEY PATTERN:
  clocking cb @(posedge clk);
    default input #1step output #1step;
    input rdata, rvalid; output rready;
APPLICABLE: 任何 SV 仿真 BFM/监控器，消除最常见竞争条件。
REFERENCE: tc_if.sv 各 interface clocking 块
```

### Skill-9：SV↔硬件验证模式对齐设计（架构设计）

```
ROLE: 验证架构师
SCENARIO: 同一 DUT 需同时支持 SV 仿真验证与硬件上板调试，二者应覆盖一致的功能点。
METHOD:
  - SV BFM task（fdma_read_slave/fdma_write_slave）与硬件 fdma_hw_test_engine 读/写 FSM 一一对应。

  SV: 队列(高精度,离线)  ↔  HW: 计数器+首错(低精度,在线,可综合)
```

### Skill-10：复位同步链 + 参数化仿真/硅片切换（RTL 设计）
