# 硬件调试模式（Hardware Debug）数据流架构详解

> 本文档详述 `fdma_aurora_brg_aurora_loop_hw` 顶层在 Hardware Debug 模式下的完整数据流，覆盖时钟/复位生成、数据源生成、桥内部传输、Aurora GT 自环回、数据比对、ILA 采样的全链路。

## 一、模式概述

Hardware Debug 模式通过 `HARDWARE_DEBUG` 宏条件编译，使用 `fdma_aurora_brg_aurora_loop_hw` 作为上板顶层。与 SV 仿真模式的核心差异：

| 维度 | 硬件调试模式 | SV 仿真模式 |
|------|-------------|-------------|
| 顶层 | `fdma_aurora_brg_aurora_loop_hw` | `tc_*_top` + `harness` |
| FDMA 从机 | `fdma_hw_test_engine`（可综合 RTL） | `tc_base` 的 BFM task（SV 类） |
| 数据源 | 确定性 `{frame_cnt, word_in_frame}` | 随机 LCG 64bit 数据 |
| 数据比对 | 硬件实时比对 + 错误锁存 | SV 队列离线逐级比对 |
| 观测手段 | Vivado ILA（ila_fdma + ila_user） | SV 监控器 + $display |
| Aurora 初始化 | 真实硅片时间（~29ms） | `SIMULATION=1` 加速 |
| 复位源 | MMCM locked 同步链 | initial 块控制 |

## 二、顶层架构与文件层次

```
fdma_aurora_brg_aurora_loop_hw.v          ← 顶层（HARDWARE_DEBUG 宏）
├── clk_wiz_1                              ← MMCM 时钟向导 [hw#L75-L81]
│   └── clk_in1_p/n (差分 200MHz) → clk_init(50M) + fdma_clk(250M) + locked
├── fdma_reset_sync[1:0]                   ← 2 级复位同步 [hw#L87-L94]
│   └── fdma_rstn = fdma_reset_sync[1]
├── fdma_hw_test_engine                    ← 可综合 FDMA 从机/数据源/检查器/测试编排 [hw#L96-L122]
│   ├── 输入: test_start/test_clear/auto_enable/frame_limit (来自 VIO)
│   ├── 输出: dbg_bus[256:0] (计数/错误)
│   └── 输出: status_dbg_bus[187:0] (测试状态机)
├── vio_hw_ctrl                            ← VIO 运行控制 [hw#L125-L147]
│   ├── probe_in0..15  (16 路只读: 状态/计数/错误/首次错误)
│   └── probe_out0..3  (4 路只写: start/clear/auto_enable/frame_limit)
└── fdma_aurora_brg_aurora_loop            ← DUT（桥 + Aurora + GT 自环）[hw#L150-L186]
    ├── SIMULATION=0, DEBUG_ENABLE=1
    ├── fdma_aurora_brg_top                ← 转换桥
    │   ├── cdc_sync                       ← channel_up 跨时钟域同步
    │   ├── fdma_aurora_brg_tx             ← TX 桥（FDMA→LL）
    │   └── fdma_aurora_brg_rx             ← RX 桥（LL→FDMA）
    ├── aurora_64b66b_top                  ← Aurora 64B/66B 核
    │   └── GT 收发器（TXP/TXN → RXP/RXN 物理自环）
    └── ila_brg_loop                       ← ILA 信号包装器 (DEBUG_ENABLE=1 时例化)
        ├── ila_fdma (41 探针)             ← FDMA 域信号采样
        └── ila_user (26 探针)             ← LL/状态信号采样
```

**关键修正**：hw 顶层同时例化 `vio_hw_ctrl`（VIO）与 `ila_brg_loop`（ILA）。VIO 负责 JTAG 在线运行控制（启停/自动/帧限），ILA 负责波形采样；二者分工互补。`dbg_bus`/`status_bus` 由 engine 产生后，既送入 DUT 供 ILA 采样，又在 hw 顶层解包送入 VIO 的 `probe_in` 供在线查看。

## 三、时钟与复位数据流

### 3.1 时钟生成

clk_wiz_1 例化见 [hw#L75-L81](file:///C:/project/RTDS/fdma_aurora_brg_aurora_loop-validate/docs/sources_1%20-%20loop_validate-6-24-afternoon/sources_1%20-%20loop_validate/new/fdma_aurora_brg_aurora_loop_hw.v#L75-L81)。

```
板载差分 200MHz (clk_p/clk_n)
        │
        ▼
   clk_wiz_1 (MMCM)
        │
        ├── clk_out1 = clk_init (50MHz)   → Aurora 核初始化时钟
        ├── clk_out2 = fdma_clk (250MHz)  → 桥/测试引擎/ILA 采样时钟
        └── locked                         → 复位释放依据
```

### 3.2 复位生成

复位同步逻辑见 [hw#L87-L94](file:///C:/project/RTDS/fdma_aurora_brg_aurora_loop-validate/docs/sources_1%20-%20loop_validate-6-24-afternoon/sources_1%20-%20loop_validate/new/fdma_aurora_brg_aurora_loop_hw.v#L87-L94)，`sys_rst` 见 [hw#L84](file:///C:/project/RTDS/fdma_aurora_brg_aurora_loop-validate/docs/sources_1%20-%20loop_validate-6-24-afternoon/sources_1%20-%20loop_validate/new/fdma_aurora_brg_aurora_loop_hw.v#L84)。

```
locked (MMCM)
    │
    ├──(!locked)──> fdma_reset_sync <= 2'b00   ← 异步复位
    │
    └──(locked)──> fdma_reset_sync <= {fdma_reset_sync[0], 1'b1}
                        │
                        └── fdma_rstn = fdma_reset_sync[1]   ← 2 级同步后释放

sys_rst = ~locked   ← Aurora 核复位（高有效）
```

**关键设计点**：
- `ASYNC_REG=TRUE` 属性防止 2 级同步寄存器被优化/重映射，确保 MMCM 失锁时立即异步复位、锁定后同步释放，避免功能复位恢复违例。

## 四、数据源生成数据流（fdma_hw_test_engine 读侧）

### 4.1 数据格式

```
fdma_rdata[63:0] = {source_frame_cnt[31:0], source_word_in_frame[31:0]}
                    └──── 高 32 位：帧号 ────┘ └──── 低 32 位：帧内 word 偏移 ────┘
```

- 帧 0 word 0：`0x0000_0000_0000_0000`
- 帧 0 word 63：`0x0000_0000_0000_003F`
- 帧 1 word 0：`0x0000_0001_0000_0000`
- 帧 1 word 63：`0x0000_0001_0000_003F`

### 4.2 读状态机数据流

```
RD_IDLE
  │ fdma_rareq=1 (DUT 请求读)
  ▼
RD_ACCEPT
  │ fdma_rbusy=1 (响应请求)
  │ fdma_rdata <= {frame, word}  (预置首数据)
  ▼
RD_SEND
  │ fdma_rvalid <= fdma_rready   (AXI-like 反压)
  │ 循环 64 word:
  │   if (read_hs = rvalid && rready):
  │     hw_rd_word_total++ (饱和)
  │     推进 source_word_in_frame
  │     if (word_in_frame == 63): frame_cnt++, word_in_frame=0
  │     if (rd_word_in_burst == 63): → RD_FINISH
  ▼
RD_FINISH
  │ fdma_rbusy=0
  │ 等 !fdma_rareq
  ▼
RD_IDLE (循环)
```

### 4.3 读数据输出路径

```
fdma_hw_test_engine.fdma_rdata ──> fdma_aurora_brg_aurora_loop_hw 内部连线
    ──> fdma_aurora_brg_aurora_loop.fdma_rdata
        ──> fdma_aurora_brg_top.fdma_rdata
            ──> fdma_aurora_brg_tx.fdma_rdata
                ──> TX FIFO (fifo_wdata)
                    ──> Aurora TX 引擎 (tx_d)
```

## 五、TX 桥内部数据流（fdma_clk → user_clk 跨域）

### 5.1 TX 桥读状态机（fdma_clk 域）

```
RD_IDLE
  │ channel_up_fdma=1 && !fifo_almost_full
  ▼
RD_REQ
  │ fdma_rareq=1
  │ 等 fdma_rbusy=1
  ▼
RD_DATA
  │ fifo_wr_en = (rd_state==RD_DATA) && fdma_rvalid && fdma_rready
  │ rd_word_cnt++ (每次 rvalid)
  │ if (rd_word_cnt==63): rd_burst_done=1 → RD_WAIT
  ▼
RD_WAIT
  │ 等 !fdma_rbusy
  ▼
RD_IDLE (rd_addr += 512, 到 4096 回绕到 0)
```

### 5.2 TX FIFO 跨时钟域

```
fdma_clk 域写 ──> XPM_FIFO_ASYNC (深度 512)
                    │
                    ├── almost_full (阈值 448) ──> fdma_rready=0 (反压读从机)
                    └── FWFT 读 ──> user_clk 域读
```

### 5.3 Aurora TX 发送引擎（user_clk 域）

```
TX_IDLE
  │ !fifo_almost_empty && channel_up
  ▼
TX_SOF
  │ tx_sof=1, tx_src_rdy=1, tx_d=fifo_rdata, tx_rem=111
  │ 等 tx_dst_rdy=1 (Aurora 核就绪)
  ▼
TX_DATA
  │ tx_sof=0, tx_src_rdy=1 && fifo_rd_en
  │ tx_word_cnt++ (每次握手)
  │ if (tx_word_cnt==63): tx_eof=1, wr_burst_done=1 → TX_IDLE
  │     frame_cnt++
```

**一帧 = 64 word = 512 字节 = 一个 FDMA burst**。

## 六、Aurora 64B/66B 核与 GT 自环回数据流

### 6.1 Aurora TX 路径

```
TX 桥 LL TX 接口
  tx_d[63:0], tx_sof, tx_eof, tx_rem[2:0], tx_src_rdy
        │
        ▼
aurora_64b66b_top
  ├── 64b → 66b 编码 (加 2bit 同步头)
  ├── 扰码
  └── GT TX 串行化
        │
        ▼
TXP/TXN (差分串行)
```

### 6.2 GT 物理自环回

```
TXP ──┐
      │ (PCB/SFP 短接)
TXN ──┘
        │
        ▼
RXP ──┐
      │
RXN ──┘
```

板上通过 SFP 光模块或 PCB 走线将 TXP/TXN 直接连到 RXP/RXN，实现物理层自环回。

### 6.3 Aurora RX 路径

```
RXP/RXN
    │
    ▼
aurora_64b66b_top
  ├── GT RX 解串
  ├── 66b → 64b 解码
  ├── 通道对齐
  └── 输出 rx_d[63:0], rx_sof, rx_eof, rx_rem, rx_src_rdy
        │
        ▼
RX 桥 LL RX 接口
```

**初始化时间**：硅片模式约 29ms（GT PLL 锁定 + 速率匹配 + 通道对齐），`channel_up` 拉高后数据方可流通。

## 七、RX 桥内部数据流（user_clk → fdma_clk 跨域）

### 7.1 RX FIFO 写入（user_clk 域）

```
Aurora RX
  rx_d, rx_sof, rx_eof, rx_rem, rx_src_rdy
        │
        ▼
RX 桥: rx_dst_rdy = 1 (恒高，不反压 Aurora)
  fifo_wr_en = rx_src_rdy && !fifo_full
  fifo_wdata = rx_d
        │
        ▼
XPM_FIFO_ASYNC (深度 2048, almost_full 阈值 2032)
  写时钟: user_clk
  读时钟: fdma_clk
  模式: FWFT (First Word Fall Through, 读延迟 0)
```

### 7.2 RX 桥写状态机（fdma_clk 域）

```
WR_IDLE
  │ !fifo_empty && channel_up_fdma
  ▼
WR_REQ
  │ fdma_wareq=1
  │ 等 fdma_wbusy=1
  ▼
WR_DATA
  │ fifo_rd_en = (wr_state==WR_DATA) && fdma_wbusy && !wdata_hold_valid && !fifo_empty
  │ wdata_hold <= fifo_rdata (预取)
  │ fdma_wvalid = wdata_hold_valid
  │ fdma_wdata = wdata_hold
  │ w_hs = fdma_wvalid && fdma_wready
  │ wr_word_cnt++ (每次 w_hs)
  │ if (wr_word_cnt==63): wr_burst_done=1 → WR_WAIT
  ▼
WR_WAIT
  │ 等 !fdma_wbusy
  ▼
WR_IDLE (wr_addr += 512, 到 4096 回绕)
```

### 7.3 写数据输出路径

```
RX 桥 fdma_wdata ──> fdma_aurora_brg_top.fdma_wdata
    ──> fdma_aurora_brg_aurora_loop.fdma_wdata
        ──> fdma_aurora_brg_aurora_loop_hw 内部连线
            ──> fdma_hw_test_engine.fdma_wdata (比对)
```

## 八、数据比对数据流（fdma_hw_test_engine 写侧）

### 8.1 期望值生成

```
expected_data[63:0] = {expected_frame_cnt[31:0], expected_word_in_frame[31:0]}
```

与读源 `source_frame_cnt/source_word_in_frame` 同步递增，格式完全一致。

### 8.2 写状态机比对流程

```
WR_IDLE
  │ fdma_wareq=1
  │ wr_words_expected = (wsize[15:3]==0) ? 1 : wsize[15:3]
  ▼
WR_ACCEPT
  │ fdma_wbusy=1, fdma_wready=1
  ▼
WR_RECV
  │ if (write_hs = wvalid && wready):
  │     hw_wr_word_total++ (饱和)
  │     if (fdma_wdata != expected_data):
  │         hw_error_sticky = 1
  │         hw_error_count++ (饱和)
  │         if (!hw_error_sticky):  ← 仅首次锁存
  │             hw_first_error_expected <= expected_data
  │             hw_first_error_actual <= fdma_wdata
  │     推进 expected_word_in_frame
  │     if (wr_word_in_burst == wr_words_expected-1): → WR_FINISH
  ▼
WR_FINISH
  │ fdma_wbusy=0, fdma_wready=0
  │ 等 !fdma_wareq
  ▼
WR_IDLE
```

### 8.3 错误统计寄存器

dbg_bus 解包见 [hw#L65-L72](file:///C:/project/RTDS/fdma_aurora_brg_aurora_loop-validate/docs/sources_1%20-%20loop_validate-6-24-afternoon/sources_1%20-%20loop_validate/new/fdma_aurora_brg_aurora_loop_hw.v#L65-L72)。

| 寄存器 | 位宽 | dbg_bus 位段 | 说明 |
|--------|------|-------------|------|
| `hw_rd_word_total` | 32 | [256:225] | 累计读 word 数（饱和 0xFFFFFFFF） |
| `hw_wr_word_total` | 32 | [224:193] | 累计写 word 数（饱和 0xFFFFFFFF） |
| `hw_rd_burst_count` | 16 | [192:177] | 累计读 burst 数 |
| `hw_wr_burst_count` | 16 | [176:161] | 累计写 burst 数 |
| `hw_error_count` | 32 | [160:129] | 累计错误数（饱和 0xFFFFFFFF） |
| `hw_error_sticky` | 1 | [128] | 错误粘滞位（一旦置位永不清零） |
| `hw_first_error_expected` | 64 | [127:64] | 首次错误的期望值（仅锁存一次） |
| `hw_first_error_actual` | 64 | [63:0] | 首次错误的实际值（仅锁存一次） |

### 8.4 测试编排状态机与 VIO 运行控制

> **此前文档遗漏的关键控制流**：`fdma_hw_test_engine` 不只是读/写 FSM，还包含一个顶层测试编排状态机，由 VIO 的 4 路 `probe_out` 在线控制，并通过 188 位 `status_dbg_bus` 上报状态。

**控制输入**（VIO `probe_out`，[hw#L143-L146](file:///C:/project/RTDS/fdma_aurora_brg_aurora_loop-validate/docs/sources_1%20-%20loop_validate-6-24-afternoon/sources_1%20-%20loop_validate/new/fdma_aurora_brg_aurora_loop_hw.v#L143-L146)）：

| 信号 | VIO 通道 | 作用 |
|------|---------|------|
| `vio_start` | probe_out0 | 手动模式：脉冲启动一次测试运行 |
| `vio_clear` | probe_out1 | 清除 error_count/sticky/first_error，回到空闲 |
| `vio_auto_enable` | probe_out2 | 1=自动模式（上电后自动启动），0=手动模式（等 start） |
| `vio_frame_limit` | probe_out3[15:0] | 目标帧数；跑到该帧数后自动停止并判定 pass/fail |

**编排状态流**：
```
IDLE
  │ (auto_enable=1 上电自动) 或 (vio_start 脉冲)
  │   → 检查 channel_up=1，否则置 test_link_down
  ▼
RUNNING (test_running=1, test_target_frames=vio_frame_limit)
  │ 读侧持续产生 {frame,word}，写侧持续比对
  │ 累计 hw_wr_burst_count
  │ ├── 达到 frame_limit → DONE(pass=无错误)
  │ ├── test_clear → 回 IDLE (清零)
  │ └── channel_up 掉 → DONE(test_link_down=1)
  ▼
DONE (test_done=1, test_running=0)
  │ test_pass = (hw_error_count==0) && !test_timeout && !test_link_down
  │ test_result_code 编码失败原因
  │ 等 vio_clear 才回 IDLE
```

### 8.5 status_bus（状态总线）映射

`status_dbg_bus[187:0]` 由 engine 产生，解包见 [hw#L56-L64](file:///C:/project/RTDS/fdma_aurora_brg_aurora_loop-validate/docs/sources_1%20-%20loop_validate-6-24-afternoon/sources_1%20-%20loop_validate/new/fdma_aurora_brg_aurora_loop_hw.v#L56-L64)。

| 字段 | 位段 | 说明 |
|------|------|------|
| `test_running` | [187] | 测试运行中 |
| `test_done` | [186] | 测试完成（一次运行结束） |
| `test_pass` | [185] | 本次运行无错误 |
| `test_result_code` | [184:182] | 失败原因码（0=pass，其他=各类失败） |
| `test_target_frames` | [181:166] | 目标帧数（镜像 frame_limit） |
| `first_error_index` | [163:132] | 首次错误的全局 word 索引 |
| `first_error_class` | [131:130] | 首次错误类别（读/写/协议等） |
| `test_timeout` | [1] | 运行超时 |
| `test_link_down` | [0] | 运行中 channel_up 掉线 |

**设计要点**：`first_error_index`（全局 word 索引）+ `first_error_class`（错误类别）比 SV 的"首个不匹配值"更进一步，可在硬件中直接定位出错的全局位置与类别，配合 ILA 波形快速根因。

## 九、调试总线与 ILA/VIO 采样数据流

### 9.2 ILA 信号路径

```
fdma_hw_test_engine.dbg_bus
    │
    ▼
fdma_aurora_brg_aurora_loop.hw_test_dbg_bus
    │
    ├── ila_brg_loop.hw_test_dbg_bus
    │       │
    │       ├── 解包 → ila_fdma.probe33..40 (8 个探针)
    │       │
    │       └── ila_fdma (41 探针, 1024 样本, 1 级流水)
    │           ├── clk = fdma_clk
    │           ├── probe0..14: FDMA 读/写接口信号
    │           ├── probe15..21: TX 桥内部信号
    │           └── probe22..32: RX 桥内部信号
    │
    └── ila_brg_loop 其他输入
            │
            └── ila_user (26 探针)
                ├── clk = fdma_clk (统一时钟域, 修复 Debug Hub bug)
                ├── probe0..2: 状态信号
                ├── probe3..14: LL TX/RX 信号
                └── probe15..25: TX/RX 桥 user_clk 域信号
```

### 9.3 ILA 触发策略

- **错误触发**：`hw_error_sticky` 上升沿或 `hw_error_count != 0` 作为触发条件，捕获首次错误前后窗口。
- **完成触发**：`hw_wr_burst_count` 达到预期值时触发，验证端到端完成。
- **FIFO 异常触发**：`tx_fifo_overflow/underflow` 或 `rx_fifo_overflow/underflow` 上升沿。

## 十一、关键设计要点

### 11.1 为什么用可综合从机而非 SV BFM

- 上板时无法运行 SV 类，必须用 RTL 实现数据源与比对器；
- `fdma_hw_test_engine` 是纯 RTL，可综合进比特流；
- 通过 ILA 观测 `dbg_bus` 即可知道错误数与首次错误值，无需 JTAG 回读内存。

### 11.2 饱和计数器设计

- `hw_rd_word_total/hw_wr_word_total/hw_error_count` 均在到达 `0xFFFFFFFF` 后停止递增；
- 防止长时间运行时计数器回绕导致误判；
- ILA 观测时若看到 `0xFFFFFFFF` 即知已饱和。

### 11.3 首次错误锁存

- `hw_first_error_expected/actual` 仅在 `!hw_error_sticky` 时锁存；
- 一旦 `hw_error_sticky=1`，后续错误不再覆盖首次错误信息；
- 便于 ILA 定位根因：首次错误值 + 对应时间点即可推断故障阶段。

### 11.4 ILA 统一时钟域

- `ila_user` 原本用 `user_clk` 采样，但 Vivado Debug Hub 要求统一时钟域；
- 改为 `fdma_clk` 采样后，LL 信号（user_clk 域）会在 fdma_clk 域被采样，可能采样到亚稳态；
- 实际影响可接受（LL 信号变化慢于 fdma_clk），换取 Debug Hub 稳定性。

### 11.5 DEBUG_ENABLE 参数

- `fdma_aurora_brg_aurora_loop` 的 `DEBUG_ENABLE` 参数控制是否例化 `ila_brg_loop`；
- 硬件调试模式 `DEBUG_ENABLE=1`，仿真模式 `DEBUG_ENABLE=0`（避免 ILA IP 干扰行为仿真）。

## 十二、调试流程示例

1. **生成比特流**：综合实现 `fdma_aurora_brg_aurora_loop_hw`，生成 `.bit` + `.ltx`。
2. **下载与调试**：Vivado Hardware Manager 下载 `.bit`，编程 `.ltx` 探针。
3. **ILA 触发**：设置 `hw_error_sticky` 上升沿触发，运行。
4. **观察**：
   - `channel_up=1` 后数据开始流通；
   - `hw_rd_word_total/hw_wr_word_total` 应同步增长；
   - 若 `hw_error_count=0`：端到端正确；
   - 若 `hw_error_count>0`：查看 `hw_first_error_expected/actual` 定位首个错误。
5. **波形分析**：根据首次错误时间点，回看 FDMA/LL/FIFO 信号，定位故障在 TX 桥/Aurora/RX 桥哪一段。

## 十三、与 SV 仿真模式的对应关系

| 硬件调试组件 | SV 仿真对应 | 作用对应 |
|-------------|------------|---------|
| `fdma_hw_test_engine` 读侧 | `tc_base::fdma_read_slave()` | 提供 FDMA 读数据源 |
| `fdma_hw_test_engine` 写侧 | `tc_base::fdma_write_slave()` + `check_results()` | 接收并比对 FDMA 写数据 |
| `dbg_bus` 计数器 | `fdma_rd_hs_q/fdma_wr_hs_q.size()` | 统计传输量 |
| `hw_error_count` | `compare_data_queues()` 错误数 | 统计比对错误 |
| `hw_first_error_*` | `compare_data_queues()` 首个不匹配打印 | 定位首次错误 |
| `ila_brg_loop` | `monitor_fdma_and_fifos()/monitor_ll_and_rx_fifo()` | 观测内部信号 |
| ILA 触发窗口 | `$display` 日志 | 事后分析依据 |

硬件调试模式牺牲了 SV 的逐级队列比对粒度（无法在硬件中维护 9 级队列），但通过 ILA 实时波形 + VIO 在线状态/控制弥补，可定位到具体信号/时钟周期，并通过 `first_error_index/class` 直接定位全局出错位置。
