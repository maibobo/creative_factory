# 板级集成目录

此目录故意不包含 MIG `.xci` 和板级 XDC。项目组补齐
[board_bringup_inputs.md](../board_bringup_inputs.md) 中的参数后，再在这里保存：

```text
board_integration/
├─ self_2020_2/        # 自研RTL板级Bring-up，保留Vivado 2020.2基线
│  ├─ ip/             # 本板MIG、Clock Wizard、PCIe独立Example等可重建IP
│  ├─ constraints/    # 本板引脚、时钟和时序XDC
│  ├─ bd/             # 不含供应商IP的SmartConnect/MicroBlaze测试BD
│  ├─ scripts/        # 从干净目录重建2020.2工程的Tcl
│  └─ reports/        # MIG校准、CRC、ILA、CDC和时序报告
└─ vendor_2024_2/     # 供应商正式交付后的独立集成工作区
   ├─ vendor_drop/    # 原始交付包只读副本，不在此处直接修改
   ├─ integration/    # 我方RTL、SmartConnect、地址图和Wrapper
   ├─ constraints/    # 基于我方板卡审查后的XDC
   ├─ scripts/        # 2024.2干净重建和回归脚本
   └─ reports/        # PCIe/NVMe、DDR并发、长稳和实现报告
```

推荐先以现有已校准 DDR 工程为底座加入本目录 RTL，不在数据通路骨架中猜测
DDR 颗粒或引脚。

## 1. 版本隔离原则

- 自研RTL继续以Vivado 2020.2行为回归和OOC综合结果为基线；
- 供应商当前工程使用Vivado 2024.2，交付后进入`vendor_2024_2`；
- 不用2024.2直接打开并保存唯一的2020.2工程；
- 不尝试把供应商2024.2 Block Design、PCIe或加密IP强制降级；
- 公共RTL应在两个版本分别编译，不能因为文件名相同就假定IP/XPM行为完全一致；
- 每个工作区都要保留工具版本、Patch、IP版本和重建命令。

当前本机未安装Vivado 2024.2，所以本目录不创建无法验证的2024.2脚本和空工程。

## 2. V2.3板级连接思路

```text
ADC PHY / 内部1 GB/s数据发生器
              │
              ▼
V2.3 ADC域打包 + 329 bit原子CDC
              │
              ▼
ADC DDR Writer 256-bit M_AXI
              │
              ├──────────────┐
              ▼              │
SmartConnect仲裁/必要的宽度转换│
              │              │
              ▼              │
真实MIG S_AXI → DDR          │
              ▲              │
              │              │
NoPHAE 256-bit DDR M_AXI ─────┘
              │
              ▼
PCIe RC → NVMe SSD
```

设计代码保持256 bit Writer的原因：

1. 双通道输入只有1 GB/s，256 bit接口在125 MHz下理论载荷为4 GB/s；
2. 当前尾拍、WSTRB、CRC、4 KiB补齐和Burst已经按256 bit完成回归；
3. 当前XSA已确认NoPHAE `m_axi`为256 bit，MIG S_AXI为512 bit；
4. 位宽不一致应优先由SmartConnect或专用宽度转换层解决；
5. 真实接口到手前重写Writer只会扩大验证面，不增加确定性。

## 3. SmartConnect配置关注点

正式BD中至少要逐项记录：

- 每个S_AXI入口对应哪个AXI Master；
- 每个入口的数据/地址/ID宽度和时钟；
- 是否启用256→512 bit宽度转换；
- 是否启用时钟域转换；
- ID扩展、压缩和返回路径；
- 最大Read/Write Outstanding；
- ADC Writer和NVMe DMA的仲裁策略；
- Address Editor中每个Master可访问的DDR窗口；
- ADC Writer持续写期间的最长AW/W Stall；
- NVMe读DDR期间是否出现写请求饥饿。

供应商截图中的`RD_PRI_REG`属于MIG仲裁配置。它可能有利于NVMe Write时从
DDR读取Payload，但也可能延长ADC写等待。不能只凭配置名称判断是否合适，
必须在1 GB/s并发压力下用ILA测量。

## 4. 分阶段接入顺序

### 阶段A：真实DDR独立通过

1. 使用本板真实参数生成MIG；
2. 运行官方Example Design；
3. 保存`init_calib_complete`和Pattern结果；
4. 运行内部500 MB/s和1 GB/s数据发生器；
5. 通过独立Reader逐字节或CRC读回；
6. 保存FIFO最大水位、AXI Stall、BRESP和错误计数。

### 阶段B：SmartConnect并发通过

1. ADC Writer持续写入Segment；
2. 独立Reader模拟NVMe持续读DDR；
3. 测量读写混合带宽和最长Stall；
4. 确认正常压力下`dropped_sample_times=0`；
5. 根据实测停顿调整FIFO和Segment，而不是修改ADC数据格式。

### 阶段C：供应商IP黑盒数据闭环

1. 在DDR A准备递增Pattern或PRBS；
2. 供应商API执行Write到指定SLBA；
3. Read回DDR B；
4. 逐字节或CRC比较；
5. 验证`Write→Flush→Readback`；
6. 确认整笔大任务Completion等待全部内部SQE。

### 阶段D：真实ADC闭环

1. 接入ADC LVDS PHY、DCO、IDELAY和解串；
2. 先用ADC内部测试Pattern；
3. 再进行真实模拟输入采集；
4. 完成ADC→DDR→SSD→DDR Readback全链路CRC；
5. 连续写至少10分钟并记录最低带宽、最长停顿和温度。

## 5. 地址集成门槛

Vitis源码已经确认NoPHAE高层DMA使用32 bit DDR Offset，V2.3
`nophae_dma_backend.sv`已实现以下换算：

```text
项目32 bit AXI物理DDR地址
→ DDR窗口范围检查
→ 减0x80000000得到32 bit Offset
→ 写NoPHAE dma_srcaddr/dma_dstaddr
→ NoPHAE m_axi访问最终MIG AXI地址
```

还必须隔离供应商SQ/CQ、PRP、Context、MicroBlaze和测试区。当前默认把ADC
Segment放到`0xC0000000`起，但真实工程必须先用地址表确认该区域可用。

MicroBlaze地址图还需新增`0x90000000`、4 KiB，接入
`fdma_vitis_compat_regs.sv`；当前原XSA没有该外设。

## 6. 错误和恢复

V2.3在以下事件后保持致命冻结：

```text
Timeout / Completion错误 / Tag关联失败 / Link Down / ECQE / Flush失败
→ 禁止新Capture
→ 禁止新NVMe请求
→ 保持INFLIGHT或ERROR_HOLD Segment
→ 不自动重试或释放
→ 等待人工恢复
```

供应商只回复“重新下载程序”。在现场确认其具体对象前，不在板级状态机中
实现自动MicroBlaze重初始化，也不假定拉复位即可安全复用旧Buffer。
