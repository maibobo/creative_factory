第一组：IP的基本参数相关问题

1. 自测报告中的数据通路

报告中 3313 MiB/s 顺序写和 3368 MiB/s 顺序读测试时，用户数据的源端和目的端分别位于哪里？是外部 DDR、片内 BRAM、MicroBlaze 内存，还是 IP 内部 Pattern Generator？用户侧采用 AXI4-MM、AXI4-Stream 还是自定义接口？

顺序读写是DDR与SSD交互，用户侧采用axi4访问DDR

2. 外部 DDR 是否可直接作为 NVMe 数据缓冲区

IP 是否支持用户将 FPGA 外部 DDR 中已有数据的物理地址直接作为 NVMe Write 的数据缓冲区，由 IP 自动生成 PRP/PRP List 并完成传输？若支持，请说明地址位宽、对齐限制、最大单命令长度和跨 4 KiB Page 的处理方式。

支持用户将 FPGA 外部 DDR 中已有数据的物理地址直接作为 NVMe Write 的数据缓冲区,支持自动生成 PRP/PRP List 并完成传输

支持2TB访问空间，需要4K对齐，最大命令长度依据MDTS自动协商,跨 4 KiB Page自动生成PRP List

3. SSD 对 FPGA 内存的访问路径

NVMe SSD 发起 PCIe Memory Read/Write 请求时，IP 通过什么用户接口访问 FPGA 外部 DDR？PCIe Bus Address 到 AXI/DDR Address 的映射是否已经包含在 IP 内，还是需要用户额外实现 PCIe-to-AXI Bridge 或地址转换逻辑？

PCIe Memory Read/Write 请求由 PCIe Hard IP 接收，经IP后转换为AXI事务，地址映射已包含在IP内

4. 不支持直接 DDR 时的数据接口

若 IP 不支持直接引用外部 DDR 地址，推荐的用户数据接口是什么？是否支持从 DDR Reader/DataMover 通过 AXI-Stream 连续送入数据？接口位宽、时钟频率、背压方式及最大连续吞吐分别是多少？

推荐采用 AXI4-MM 接口访问外部 DDR。

IP内部负责 DDR 与 PCIe DMA 之间的数据搬运，不要求用户提供 AXI-Stream DataMover
