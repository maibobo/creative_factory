# 以太网工程速查

## 当前结论

现有 RTL 已形成“RGMII 接收 → GMII 帧解析 → CRC/MAC/ACL/风暴判决 → GOOSE/SV/Other 分类 → S2MM 写 DMA”的清晰设计，但还不是可直接加入 Vivado 的完整 IP。

当前有两个独立顶层：`rgmii_eth_storm_filter_top` 负责接收、过滤和分类，`eth_classified_frame_dma_writer` 负责把三组 FIFO 写入外部存储器。两者尚无最终系统顶层；AXI-Lite 寄存器、读 DMA、部分 FIFO/CRC RAM/clock wizard/DataMover IP、约束和正式 testbench 也未完整提供。因此本页描述的是 RTL 行为审计结果，不宣称编译、综合或仿真通过。

## 数据通路

```text
RGMII 4-bit DDR
  → IDDR / GMII 8-bit
  → 前导码与 SFD 识别
  → 帧解析、FCS/长度、MAC/ACL、风暴和重复帧判决
  → 一级异步 frame FIFO + 53-bit descriptor FIFO
  → GOOSE / SV / Other 路由
  → 三组二级 data/descriptor FIFO
  → 8→64 bit 打包 + DataMover S2MM
  → 三个内存环形缓冲区
```

接收和判决运行在 `gmii_rx_clk` 域；分类和建议的 DMA 连接运行在 `clk_125m` 域。一级 FIFO 是主要 CDC 边界。

## 帧格式与 CRC

- 必须先检测至少 7 个 `0x55` 和一个 `0xD5`，SFD 后才开始编号。
- 最近 4 Byte 保存在 hold 寄存器中，帧尾作为 FCS，不写入数据 FIFO。
- 单层 TPID `0x8100` 的 VLAN 标签会被删除；QinQ 和其他 TPID 不会按 VLAN 处理。
- CRC 覆盖 SFD 后的 DA 到 FCS。`cfg_crc_check_en=1` 时残余值必须为 `32'h2144_DF1C`。
- 默认最小长度 60 Byte、最大长度 1514 Byte。短帧会进入最高优先级的 `DROP_CRC_ERR`，而不是 `DROP_LEN_ERR`。

描述符中的长度是实际进入 FIFO 的字节数：不含 FCS，VLAN 帧也不含已剥离的 4 Byte 标签。

## 策略与固定丢弃优先级

| 优先级 | 编码 | 原因 |
|---:|---|---|
| 1 | `0x0001` | `DROP_CRC_ERR`：RXER、短帧或启用检查时 FCS 错误 |
| 2 | `0x0100` | `DROP_DST_MISS` |
| 3 | `0x0040` | `DROP_BLACKLIST` |
| 4 | `0x0080` | `DROP_NOT_WHITE` |
| 5 | `0x0010` | `DROP_BUF_FULL` |
| 6 | `0x0020` | `DROP_LEN_ERR` |
| 7 | `0x0004` | `DROP_FRAME_STORM` |
| 8 | `0x0008` | `DROP_BYTE_STORM` |
| 9 | `0x0002` | `DROP_DUP_CRC` |

同一帧只上报最高优先级的一个原因。`cfg_filter_en=0` 只旁路目的 MAC、ACL、风暴和重复 CRC 策略；RXER、最小/最大长度、FIFO 资源以及独立的 CRC 检查仍可能丢帧。

目的地址允许本地单播、可配置广播和 64 bit 组播 Hash；源 MAC 白名单、黑名单各 4 项，黑名单优先。EtherType 只分 GOOSE、SV、Other 三类，不改变接收侧丢弃优先级。

## 风暴窗口与重复帧

- 默认窗口 10 ms；默认上限为每窗口 1000 帧或 8,000,000 Byte，运行时配置为 0 时回退到默认参数。
- CRC/FCS、目的 MAC 和 ACL 基础检查失败的帧不计入窗口；资源不足、长度超限、风暴和重复帧在满足基础条件时仍可能计入。
- 重复表保存 `{valid, epoch, crc}`。窗口翻转后切换 epoch，并在后台清理旧项；正常查表/写表优先。
- 直接映射 Hash 保存完整 CRC，因此碰撞不会把不同 CRC 误报为重复，但旧项可能被覆盖，导致后续漏检重复帧。
- `frame_time_cnt_g` 每个 GMII 时钟固定加 8；只有在 125 MHz 时才自然对应 8 ns，换频率后不会自动校准。

## FIFO、路由与 DMA 不变量

1. 一级和二级 FIFO 的数据必须始终与描述符一一对应。
2. 二级 FIFO 按 FWFT 使用；若 IP 配成标准读模式，数据会错位。
3. 路由器先写完整帧数据，最后才发布二级描述符。
4. 目标通道拥塞时，路由器静默排空该帧，避免一个通道阻塞其他类型；这类路由级丢弃不属于接收侧 `drop_reason`，必须看独立 route-drop 统计。
5. DMA 固定优先级为 SV > GOOSE > Other，持续 SV 流量可能饿死低优先级通道。
6. S2MM 必须按“数据命令 → 数据 → 数据状态 → 描述符命令 → 描述符 → 描述符状态 → commit”执行。只有最后 commit 才推进 `WR_PTR`。
7. 8→64 bit 最后一拍用低位连续的 `TKEEP`，反压时 `TDATA/TKEEP/TLAST/TVALID` 必须保持。
8. Other 中断是保持到 ACK 的电平，不是逐帧计数；软件应以环指针排空为准。

## 优先处理的风险

- 零长度、超长或 invalid 描述符被弹出却未同步排空数据 FIFO，会永久破坏帧边界。
- 命令、数据或状态接口没有 watchdog，DataMover 不响应可让 `busy` 长期保持。
- 环深度、RD_PTR、基地址、对齐、地址回绕和 DRE 约束没有硬件保护。
- 配置端口跨 `gmii_rx_clk`/`clk_125m` 的同步职责尚未由寄存器桥定义。
- 接收过滤与 DMA Writer 的系统顶层、读 DMA 和软件寄存器仍待实现。
