# 回灌审核与发布流程

当前为建议维护方法，发布责任人与批准记录尚未填写。回灌发生在新建V2资产的候选区，原知识库和规则包本轮不更新。

1. 从任务差异和问题卡提出候选，保留实际来源；AI可以整理，不能自行批准。
2. 区分错误修复、组织规范、项目约束、可观察性、过度设计和个人偏好。
3. 写清适用范围、反例、验证方法与不能泛化之处。
4. 负责人核对原始证据和回归；需要独立专业评审时指定复核者。
5. 批准后发布新版本，记录日期和责任人。旧版本标superseded并保留。
6. 后续任务出现反证或版本变化，停用受影响条目并回到candidate。

## 实填候选 FB-001

AUR-002说明复用历史模块时应该核对真实握手语义。可泛化的是“检查接口方向、接受事件和已验证映射”，不能泛化为“valid/ready永远交叉连接”。

当前只引用历史台账，缺原始AI初稿、正式签核及第二场景适用性复核。因此候选保持candidate、publication_allowed=false。具体记录见[feedback card](feedback_card.example.json)。

## 完成定义

每次发布至少有来源、版本、范围、复核结论和批准记录；对功能性规则还需要相应测试。没有证据的候选可以保存供下一次研究，但不能在Agent任务中当作强制规则自动加载。
