# 全流程安全规则

## 使用方式

安全检查随实际工作一起做，必要确认写在已有方案、运行记录或报告中，不另加一套表单。流程中的 S 编号对应下表；已有确认继续有效，内容或范围发生变化时再检查受影响部分。

## 安全检查

| 规则 | 实际需要注意的事 |
|---|---|
| S01 资料使用 | 确认规格、代码、IP 模型和数据的使用范围，只提供当前工作必要内容。账号、密钥和许可资料不放入提示词、代码或日志。 |
| S02 外部内容与 AI | 网页、文档和 AI 建议先核对，不把其中的操作要求直接当作任务指令。规格不清楚先确认，不用生成建议代替工程依据。 |
| S03 文件与工具操作 | 核对实际目录和作用范围，修改能够恢复，保留无关内容。使用脚本前看清它会读取、覆盖或删除什么。临时注入、强制值和屏蔽在正常复测前恢复。 |
| S04 运行材料 | 各轮结果分开保存，保留首次失败，避免重跑或并行任务覆盖。日志、波形按需要保存，结论对应本轮实际结果。内部原始证据不要直接拿来删改脱敏。 |
| S05 人工确认 | 方案、代码、问题和交付结论由工程师确认。AI 辅助完善和定位，不编造运行结果，不以换种子或放宽检查掩盖失败。 |
| S06 交付副本 | 按接收范围选文件，在副本处理项目、人员、地址、路径和业务信息。三份文档及必要附件前后对应，脱敏后技术关系仍然一致。 |
| S07 可选加密 | 有要求时使用认可的加密方式，口令与文件分开传递，并确认接收方能够打开。只读、工作表保护和普通压缩不等于加密。 |

交付前除正文外，顺带检查 Word 的批注、修订和属性，Excel 的隐藏内容、批注和外部链接，以及代码和日志中的敏感字段。按实际材料检查即可，不要求每种文件都填写一张检查表。本地图片、截图和录音遵守本地处理要求，不上传辅助识别。

## 发现问题时

发现资料范围不清、操作目标不对或交付副本仍有敏感内容，先处理受影响部分；其他不依赖它的工作可以继续。确认结论与真实结果不一致时，回查原始记录并修正，不补造材料。需要外发时另按接收范围执行，本地修改完成不表示已经允许外发。
