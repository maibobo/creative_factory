# 未覆盖项处理规则

## 1 处理原则

未覆盖可能是用例不足，也可能是当前参数关闭功能、工具不能统计或模型无法表达。查明原因才能选择补用例、修改合法配置或说明限制。图中用短名称“查明未覆盖原因”，实际判断要写成具体事实，不能只有“已分析”。

“正常不会发生”需要对应的合法输入或状态约束；“防御性逻辑”需要说明它防御什么条件及规格是否要求响应；“随机跑过很多次”不能证明目标事件出现；“工具问题”需要版本或实际诊断；“当前不用”需要确认交付范围。不能用简短标签取代依据。

若该位置对应约定主要功能，即使模型不能表达也不是自动接受的理由。应改进验证办法、提供能支持结论的证据，或在出口保留未完成。工程师对限制的确认不能把没有执行的功能写成已经验证。

## 2 原因与处理方式

| 原因 | 必须找到的依据 | 应采取的处理 |
| --- | --- | --- |
| 合法场景没有出现 | 规格允许、路径可达、真实接受事件缺失 | 补充有判据的定向场景或调整合法随机约束 |
| 场景计划了但没被接受 | 就绪、握手、驱动和实际计数不一致 | 修正场景控制或环境，重新运行 |
| 参数关闭功能 | 当前参数及生成条件、交付配置范围 | 本次说明范围，其他需要配置补测 |
| 规格条件下不可达 | 输入约束、状态关系或互斥条件推导 | 保留可核对依据并由工程师确认 |
| 错误处理未触发 | 错误入口和预期响应是否定义 | 可注入则测试，并检查异常后的正常业务 |
| 工具不支持或未识别 | 实际版本说明、诊断和采集结果 | 如实记录能力，补充适用功能证据 |
| 模型不能表达 | 模型接口、可变条件和替代边界 | 明确限制；关键能力需补足验证或判未完成 |
| 报告或采集错误 | 范围、顶层、运行编号、选项和文件版本 | 修正采集，不把无效结果用于结论 |
| 原因不明 | 当前没有充分事实 | 保留待处理，不能直接接受 |

缓存满处理未执行：确认请求是否被真实接受、输出是否同时释放容量、深度是否与模型一致，再设计能够形成满条件的节奏。最长输入限制未执行：检查生成范围、长度单位和有效字节，不能只增加随机数据数量。错误恢复路径未执行：确认错误能否从合法模型入口注入，以及规格是否定义处理。

参数相关逻辑未生成：保留当前参数依据，并检查是否还有其他需交付配置；仅当前关闭不代表整个产品不需要。状态机无法识别：说明原生统计能力与已有状态用例，不把状态名称清单当实际经过证据。工具报告范围错误：先修正采集，不围绕错误报告编写理由。

每个保留说明应能回答“为何本次无法或无需执行、什么证据支持、影响哪个功能、是否仍影响完成”。仅有“不可达”三个字不能通过。若条件推导依赖未确认假设，说明仍待确认，不能用推导形式掩盖前提不可靠。

补测应同时检查异常后的恢复。例如触发容量错误后，还要确认下一笔合法事务能处理；触发复位相关路径后，确认模型和队列没有污染。只执行到一行错误处理代码而不检查后果，不足以证明该规格行为正确。

## 3 补测与说明

补测用例写清触发目标、输入控制组件、实际发生证据和结果检查，关联原测试点。先稳定触发目标，再扩大随机组合。补测之后同时核对代码执行信息和功能比较，出现目标但输出错误仍是失败，不能因覆盖率增加而关闭问题。

对参数、等待或复位造成的未触发，优先修正前提而不是无限增加种子。若调整模型，重新确认它和 DUT 的接口语义及相关旧结果。补测运行和报告保存独立编号，能够比较前后差异。

## 4 报告与出口

在仿真回归报告中记录位置、关联规格/测试点、原因、依据、处理、补测运行、剩余影响和确认人，不单独建立覆盖率分析表。原始工具结果保留，人工说明不转换成新的实测百分比。关键项无依据或未处理时不满足出口标准。

记录示例：“当前配置关闭可选入口，对应参数和模块实例见方案；本次交付仅含关闭配置，相关逻辑不属于本次执行范围，工程师确认。”若后续增加开启配置，该说明失效，需重新安排测试点和用例。安全：S02/S04/S05。
