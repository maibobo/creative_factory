# 仿真结果与复现信息规则

## 1 运行条件与记录

运行记录以能说明“测了什么、结果怎样、如何重现”为准，直接利用项目已有日志和报告，不为每个字段另建表。通常保留用例、实际种子与配置、适用代码和工具版本，以及结果和日志位置；出现异常时补充首错及修复前后的对应记录。省略命令参数不等于省略实际生效条件。

| 信息类别 | 记录重点 |
| --- | --- |
| 运行条件 | 用例、实际 seed、mode 和影响行为的参数；能够定位 RTL、TB、模型和工具版本 |
| 结果与异常 | 是否正常完成、实际检查结论；失败时保留首错、现象和相关运行 |
| 证据 | 日志和按方案需要保存的波形或报告；位置可定位，与本轮运行对应 |

事务标识、接受和完成数量等诊断信息按功能需要记录，不要求每个简单用例都建立完整事务账目。已有文件表、工程记录可以引用，避免多处维护相同版本信息。用例、运行和问题需要能相互找到，但不强制采用特定编号格式。

明确顶层、文件表、宏、参数、模型、模式、种子和检查开关。配置应能标识本轮实际生效值，而不只是用户命令文本。共用配置单一来源，组件允许局部覆盖时说明优先级和最终值，防止 DUT、模型与比较器各用不同默认配置。

| 工程配置 | 要求 |
|---|---|
| 源文件与顶层 | 能确定实际编译的 RTL、TB、文件顺序和仿真顶层，避免同名旧文件或旧快照。 |
| 参数与模式 | 使用已确认的合法配置，DUT、模型和检查组件采用一致的有效值。 |
| 依赖文件 | 库、模型和初始化文件可定位，工作目录改变后仍能找到正确内容。 |
| 目录与复用 | 运行之间避免互相覆盖；输入变化时确认缓存是否仍有效，清理只针对本任务目录。 |

源文件、环境、用例、模型、配置和结果可以采用项目已有目录，重点是职责清楚和相对引用有效。禁止通过复制多份同名源文件解决依赖，导致无法确定实际编译哪一份。生成文件和手写文件分开识别，重新生成不覆盖用户维护内容。

基础 TB 不强制复杂层级；轻量级 SV 使用文件表明确公共定义；完整环境避免把已 include 的类文件再次独立编译。外部依赖不能仅写“联网获取”，离线项目应有授权可用副本和明确版本，或者记录阻碍实施的缺失。

位宽、容量、模式改变可能影响模型、随机范围、字节选择和超时，必须联动核对。不同参数生成不同结构时，不能错误复用旧展开对象。工具、库、文件表、宏或相关源变化后，重新判断编译缓存是否有效。

路径包含空格或中文时，检查启动入口和工具能正确传递，不用删除无关目录名绕过问题。错误路径应明确指出，不能悄悄使用当前目录中同名文件。记录中路径可使用结果包内相对位置，实际执行时仍核对绝对目标。

运行任何已有脚本前读清覆盖、删除、下载和外发行为，作用目录与本任务一致。密钥与凭据通过批准的本地配置提供，不能嵌在脚本、命令或日志。工程师按 S03/S05 确认配置有效，再进入实际用例执行。

## 2 工具、模型与仿真库

适配记录应聚焦实际使用的器件、IP、模型和仿真器版本，不建立无关的工具能力大表。先确认模块依赖哪些行为，再核对模型能否表达。项目接口模型和真实 IP 模型分别说明，名称相同不代表行为等价。

| 模型适配 | 要求 |
|---|---|
| 配置与依赖 | 器件/IP、模型、库和参数对应，所用语言及加密模型与实际工具兼容。 |
| 初始化 | 复位、忙和就绪条件与模块要求一致，不能假定撤销复位后立即可用。 |
| 支持范围 | 说明模型能够表达的业务和限制，不把简化接口模型当成完整器件验证。 |
| 变更 | 工具、库或模型改变后，重新检查受影响的启动条件与用例。 |

Xilinx 项目明确使用 IDE 管理或独立仿真入口，核对工程导出的源文件、IP 用户文件及依赖库是否完整。对 XSim 语言、UVM、覆盖率和波形能力分别核对，不从其中一种能力推断其他能力。FSDB 请求仅传给支持后端，不能写成 XSim 原生输出。

国产器件项目同样核对实际供应商模型的语言、加密兼容性、初始化和库依赖，并按所用仿真器确认配置。没有明确资料或实际结果时，保留待确认状态。

FIFO 读模式改变会影响首拍和有效时刻；存储器初始化文件字节排列影响参考值；就绪或校准信号被固定为真可能隐藏启动错误；理想 BFM 不含真实错误反馈可能遗漏恢复路径。应根据待验证行为补足模型条件或明确限制。

模型例化成功但工作不正确，检查参数、时钟、复位、使能和库绑定，不只是文件是否存在。时钟和时间单位冲突可能让仿真看似启动却永远未就绪，日志应指出等待对象与上限。

使用器件/IP 模型先确认材料使用范围和许可要求，凭据和授权文件不写入公开日志。方案只记录支持判断所需信息，不复制整份受限资料。适配和确认分别对应 S01/S03/S05，填写方法见[对应 Skill 的方法说明](../04_Skills/verification-planning/SKILL.md)。

## 3 复现与结果解释

种子不是完整复现条件。相同种子只有在相同随机源、代码、工具、配置和相关调度下才可能重现相同序列；新增随机调用、对象创建或线程可能改变后续输入。独立随机源要记录来源及派生关系，不能只保存未控制全部行为的一个数字。

固定原条件时优先比较实际事件和首次失败特征，确认不是同名报错的另一个原因。更换工具或模型后如果序列发生变化，记录差异和替代验证，不声称与原输入完全相同。无法严格重放并不自动构成问题关闭依据。

日志必须属于当前运行，不能从旧目录复制 PASS；文件修改时间只能辅助判断，还需核对运行编号和配置。波形存在不等于有效，应检查格式、非空、仿真时间范围及目标信号。请求 FSDB 需要后端支持，不能用其他格式更名。

逐例最终状态互斥，采用通过、失败、异常、未执行。功能比较已通过但所需产物缺失时保留辅助事实，最终状态为异常。无输入、检查未启动、缺正常结束证据时不填通过。报告统计从逐例记录计算，不能人工调整总数使其一致。

记录缺失时，先从已有工程和日志恢复。无法找回种子、版本或必要产物，就说明对复现和结论的影响，必要时补跑；不根据摘要补造原始记录。

记录缺项不一定证明功能错误，但会限制能够作出的结论。出口需要的关键事实无法恢复时，应补充真实执行；不能让 AI 根据摘要编写看似完整的日志。人工整理的事务解释应标为解释，原始输出仍保留。

提交复现记录给其他工程师时，先在批准环境确认源、模型和初始化可定位，命令能解析相同配置；检查相对引用不依赖个人工作目录。若接收方工具版本不同，说明复现能力边界，不能只交一个种子数字。

## 4 日志、波形与保存

每条运行有独立标识和结果位置，保存配置、日志、结论及要求的波形。工作目录用于构建和临时文件，结果目录保存本次执行证据，两者可以邻近但职责分清。并行任务不共享可写日志、波形、随机数据文件或默认结果名。

| 结果材料 | 要求 |
|---|---|
| 日志和结论 | 能看出本轮条件、结束情况和首个异常，逐例结果与报告一致。 |
| 波形 | 按方案需要保存，确认属于本轮且包含所需时间和信号；格式由后端实际支持。 |
| 保存与重跑 | 首次失败保留，复测存新位置，能够找到修复前后的关系。 |
| 交付 | 必要材料可定位，敏感内容在副本处理，内部完整材料保留。 |

是否请求波形及保存范围由验证需要和资源决定。可以只为失败或代表场景保留所需时间窗，但应在方案中明确，不能运行后才把缺失波形解释为不需要。FSDB 示例仅针对支持后端，XSim 的波形能力按实际版本和格式使用；统一命令接口不意味着统一底层格式能力。

波形用于定位真实接受、首个偏离及恢复，不代替自检查。截取图需要标明接口、时间、信号和对应运行，仍能找到原记录。没有用例、配置和时间上下文的截图不足以支持完成结论。

启动日志打印有效配置和版本，关键阶段打印就绪、场景开始、接受/完成计数及结束原因；错误打印首个差异和上下文。避免逐拍无界打印导致真正错误被淹没，可按级别保存必要摘要和完整诊断。关闭打印不能关闭检查。

日志中出现多个错误时，保留顺序和首错，按问题关联去重，不抹去原始失败。工具进程退出状态与功能结果同时核对，返回成功码不能覆盖比较失败，非正常中止也不能仅凭已有 PASS 标记通过。

日志、波形和初始化文件可能包含业务载荷、地址和本地路径。内部证据按授权范围完整保存，交付在副本中一致脱敏，不能直接破坏原始文件。清理仅操作确认的本任务临时材料，敏感信息和可选加密见 S04/S06/S07。

工作目录与结果目录按运行隔离，原始失败记录只读保留或采用能防止误覆盖的管理方式。清理先核对实际绝对路径及任务归属，不能广泛删除共享缓存。交付副本按 S06 处理敏感内容，内部原始记录保持完整；日志和波形载荷按 S04 控制访问。

工程师确认关键失败、修复结果和最终有效记录可找到、可解释。缺项不以推测补造，写明缺失和影响。
