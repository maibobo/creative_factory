# 回归与结果判定规则

## 1 入口与用例列表

统一入口如下，大小写和参数名保持一致：

```text
make run tc=<用例名> [seed=<种子>] [mode=<模式>] [wave=fsdb]
h_regress -cur
h_regress -rerun
```

`tc` 必填，其余项可选，实际默认值写入日志。FSDB 只适用于支持后端，XSim 不原生输出该格式。`-cur` 执行确认的当前列表，`-rerun` 沿用上一轮未通过或异常项的原用例、种子及配置。三个入口共享相同判定逻辑，不允许列表运行偷偷关闭单例中启用的检查。本包不提供脚本实现。

## 2 执行与结果判定

| 必须满足的要求 | 不符合时的状态或处理 |
| --- | --- |
| 列表非空、名称有效、配置完整并对应表单 | 异常，不产生零用例全通过 |
| 编译和展开成功，真实模型与 DUT 已绑定 | 异常，受影响项未完成 |
| 关键检查启动，要求的目标事件真实发生 | 未完成项不能通过，查检查或激励原因 |
| 数据、顺序、协议、错误语义按方案检查无失败 | 失败，保留首错并定位 |
| 启用断言无未处理失败 | 失败，纳入统一错误统计 |
| 用例正常完成，未依靠 watchdog 退出 | 业务超时为失败，工具中止为异常 |
| 在途已处理、队列无不明残留、计数关系正确 | 失败或检查异常，不能直接结束 |
| 要求的日志和波形属于本轮且可用 | 异常，功能比较事实另行保留 |
| 逐例结果能重算列表总数 | 不形成最终汇总，先修正记录 |
| 修复先复测原条件，再检查受影响用例 | 缺任一依据不关闭问题 |

通过：所有要求检查、结束和产物均满足。失败：已执行并出现数据、协议、断言或业务超时等检查失败。异常：工具、模型、启动、记录或必要产物使本轮不完整。未执行：条目没有有效启动或因共享环境停止而跳过。根因类别另行记录，不能仅根据状态认定由 DUT 负责。

每条运行只归入一种最终状态。若同一运行既发生功能错误又缺波形，最终记失败，并在原因字段附带产物异常；若没有功能错误但证据不足，记异常。总运行数等于四类数量之和，用例数和配置数另列，不与运行次数混用。

## 3 等待与结束

区分模型初始化、请求接受、事务响应和环境排空。每种等待说明完成事件、责任组件和上限依据。规格有时限时按规格检查；外部环境可等待时区分环境允许范围与 DUT 义务，不能凭空要求固定周期完成，也不能让仿真永久运行。

| 必须满足的规则 | 错误诊断 |
| --- | --- |
| 等待基于真实条件或事件 | 不用任意延时代替就绪 |
| 所有可能无限阻塞的路径有退出控制 | 指明对象、状态和剩余数量 |
| 总 watchdog 只用于异常收尾 | 到时退出不能标正常通过 |
| 超时范围与配置、长度和合法等待相容 | 参数改变后重新计算或核对 |
| 激励完成与事务完成分别判断 | 发送任务结束不提前停止观察 |
| 正常结束检查所有必要队列和在途项 | 不存在不明残留和无人处理对象 |
| 等待中复位或中止有一致处理 | 旧线程不会在恢复后继续错误驱动 |
| 空执行或检查未启动不能通过 | 目标事件和关键计数可查 |
| 修改超时需要依据和复测 | 不靠无限放大上限掩盖卡死 |
| 退出仍保留首错与运行状态 | 工具被杀死不伪装正常结束 |

正常结束同时要求：不再产生新激励、所有已接受事务按规格完成或取消、模型与实际队列无不明残留、必要检查已执行、错误数为零、终结状态和要求产物有效。对允许后台空闲线程的环境，不要求线程全部自然退出，但必须停止其对业务判断和文件保存的影响。

UVM 的 objection 或普通 SV 的结束事件只控制运行期。释放或触发之前应判断业务完成，不能由计时线程在固定延时后无条件结束。异步模型写波形或日志需要收尾时，正常结束应保证写入完成。

先看最后成功事件和当前等待点，再看接受、完成、取消、剩余及队列长度。如果没有输入，查初始化和驱动；输入已接受但无输出，查数据路径和模型；输出齐全但未结束，查计数、关联和线程；工具停止运行，查环境和进程状态。

周期单位、时间精度和时钟周期都影响超时计算。对参数化长度和可变等待，给出上限依据而非一个神秘常数。发生超时保留原条件，修复后验证原场景及更长合法事务，确认没有同时引入过早超时和无限等待。

用已知正常、缺失响应、复位打断等待和观察器未启动等场景走查结束路径。只检查能影响当前环境的实际风险，不为每个循环形式化添加测试。记录按 S04 保存，超时或结束判据修改按 S05 确认。

## 4 异常、复测与汇总

按表单确认的顺序组织。并行任务需要独立目录及资源，工具并行能力和许可应满足。独立功能失败保留后可以继续，公共编译、模型或环境失效应停止受影响项，剩余记录未执行。中止不能自动改记通过。

环境重试次数由项目配置限制并保存每次记录；默认不自动更换种子重试功能失败。重跑结果存新目录并关联原运行，原失败不得覆盖。原种子和配置缺失时不能宣称执行原条件重放。

图中统一用“结果汇总”和“异常定位与修复”表示主线，正文与记录仍保存具体失败原因。工程师核对未执行、异常、失败和遗留状态，确认不能靠删除列表项、屏蔽检查或不断重跑获得全通过。最终结果供出口标准判断，完整通过数量本身不证明规格没有遗漏。

显式功能失败优先保留；同时存在工具或产物问题时记录附加原因。没有功能失败但环境、关键检查或必要证据不完整时不能通过。停止后从未启动的项写未执行，已经启动却中断的项写异常。用例可预期的错误响应属于待检查行为，只有实际结果不符才判失败，不能看到 ERROR 字样就一律失败。

| 运行现象 | 必须核对 | 最终处理 |
| --- | --- | --- |
| 用例主动注入合法定义的错误 | 预期错误码、恢复和统一错误计数的设计 | 预期响应正确且无检查失败可通过 |
| 工具打印警告但业务完成 | 警告是否影响库绑定、截断或检查有效性 | 有依据分类处理，不能全部忽略或全部算 DUT 失败 |
| PASS 后出现残留报错 | 正常结束顺序及最终检查输出 | 失败，前面的 PASS 不覆盖后面的真实错误 |
| 无错误且零事务结束 | 当前用例是否专门检查空闲 | 普通业务用例不能通过；空闲用例需有对应检查 |
| 同一用例部分配置未执行 | 计划配置与实际运行的对应 | 已执行部分保留事实，整体范围未完成 |

汇总修正只修复记录解析和分类，不能删除不利运行。若脚本误判，修正后用原日志重新提取时保留原始记录，并核对解析规则不会把预期异常文本误作失败。需要重新运行才能得到的事实不得从文本处理推导出来。
