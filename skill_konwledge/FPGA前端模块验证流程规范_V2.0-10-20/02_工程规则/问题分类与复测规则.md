# 问题分类与复测规则

## 1 问题分类与影响

原因使用 DUT、TB/用例、规格/判据、工具/模型四类，未确定则待定位。严重度只用严重、一般。主要功能错误、数据丢失破坏、不可恢复卡死、关键检查失效或关键功能无法验证属于严重；一般问题也需要具体影响和处理依据，不因类别是环境或文档就自动接受。

## 2 定位与修改

| 必须满足的要求 | 核对依据 |
| --- | --- |
| 保留首次失败和完整原运行条件 | 能定位用例、种子、版本、配置及首错 |
| 原条件重放对照实际事件和首次偏离 | 不能仅因末尾相同报错就认定同一根因 |
| 先核对输入合法、真实接受、观察和预期正确 | 不看到比较失败就直接修改 RTL |
| 区分已证实根因和排查假设 | 原因不明保持待定位，不用推测关闭 |
| 修改有规格依据和影响范围 | 说明受影响接口、参数、状态及组件 |
| 判据放宽、约束收窄、延长超时或替换模型需审查 | 不能为得到通过而改变正确标准 |
| 原失败条件必须用修复后版本复测 | 原用例、种子和有效配置可查 |
| 关联正常、边界和异常场景按影响补测 | 只复测原例不足以证明没有引入新问题 |
| 改检查器或参考模型时重新判断旧结果 | 大范围假通过不能只关单个问题 |
| 关闭依据包含原因、修改、原条件及影响复测 | 没有实际日志不能写已关闭 |
| 接受遗留单独记录，不写已修复 | 影响、限制、责任人和接受人明确 |
| 严重未解决项阻断出口 | 不以文件齐全或总体通过率代替判断 |

数据通路变更检查内容、长度、有效字节、顺序和反压；控制计数变更检查边界、同拍事件和溢出语义；复位变更检查空闲、在途、部分输出和恢复；ID 关联变更检查复用、乱序域、未知与重复响应；工具模型变更检查启动、初始化及依赖结果。

修改环境也可能影响所有历史通过记录。采样时机、比较掩码、队列清理和完成条件改变后，应识别哪些旧结论基于错误检查，并重新执行对应范围。不能用“只改 TB”作为不需要复测的理由。

## 3 变更与关联检查

每次改变规格、RTL、TB、模型、配置或工具，都判断对预期结果、实际行为和证据适用范围的影响。无需重开无关内容，但要说明为什么不受影响。文件只是格式变化时核对引用和内容即可；逻辑、采样、比较或初始化变化则需要适当复测。

| 变更对象 | 必须联动的内容 |
| --- | --- |
| 规格或合法范围 | 测试点、预期、约束、方案及已有结果解释 |
| 数据通路 | 内容、长度、字节有效、顺序、边界与反压用例 |
| 计数和状态控制 | 临界值、同拍事件、异常、恢复及完成条件 |
| 复位 | 在途取消/保留、模型清理和恢复首笔 |
| Monitor 采样 | 所有依赖该观察路径的结果和首尾拍证据 |
| 参考模型或比较器 | 自检、手算例子及受影响历史通过记录 |
| 参数或模式 | 生成结构、模型配置、随机范围及超时 |
| 器件/IP 模型和库 | 编译展开、初始化、支持边界和依赖用例 |
| 工具或随机实现 | 兼容性、随机序列和原条件重放声明 |
| 用例列表及产物要求 | 汇总分母、未执行记录、证据索引和出口判断 |

规格描述约定行为，表单描述如何检查，方案描述环境如何实现，代码执行真实检查，报告描述实际结果。这条关系中任一环改变，查找相邻信息是否仍成立。不能让文档写一个字节顺序、参考模型算另一种，而报告只写通过。

用例重命名时同步入口、列表、表单和新证据索引；旧记录保留原名并建立对应关系，不篡改历史日志。文件移动后检查相对链接和初始化依赖。模板、草稿与真实产物分清，不能把示例结果迁移成工程事实。

| 修改 | 必须优先复测 | 还应考虑的影响 |
| --- | --- | --- |
| 修正尾拍处理 | 原长度和原等待条件 | 整拍、非整拍、最短、最长及连续帧 |
| 修正发送推进 | 原反压时刻和种子 | 首尾等待、连续接受及复位中断 |
| 修正 ID 释放 | 原复用和完成顺序 | 同域顺序、未知响应和最大在途 |
| 修正队列清理 | 原复位中断条件 | 空闲复位、部分输出和恢复首笔 |
| 修正观察快照 | 原错误字段和时间关系 | 连续不同事务及动态字段复制 |
| 修正比较掩码 | 原失配有效字节 | 其他尾长、控制未知态及旧通过范围 |
| 修正模型就绪 | 原启动配置 | 所有依赖初始化、忙和恢复的用例 |

原失败消失而出现新错误时，不将其当作单纯记录噪声；先判断新错误是否由修复引入或原来被前序失败遮蔽。根因相同可继续关联一个问题，不同根因建立新项并说明关系。问题数量不是评价修复成败的依据，关键是原条件、影响范围与事实是否闭合。

若规格确实发生变更，关闭旧问题前说明原行为是否不再要求、哪些新测试点取代、结果如何重新验证。不能在没有需求变更依据时通过修改预期消除报错。工程师确认对象是最终行为和证据，而不只是代码差异。

## 4 复测、遗留与确认

关闭项记录原问题、根因、修改版本、原条件复测运行、关联检查及确认人。偶现问题没有再出现但根因未明，保留待定位或明确限制，不默认关闭。根因已知但修复未实施，不能以临时绕过后的通过写为关闭。

一般遗留由工程师判断是否影响约定目标，写受影响配置、出现条件、规避措施、后续责任和接受依据。遗留限制应同步方案和报告，必要时反映到实际可用范围。严重项不能通过更换名称降为一般。

调试副本和原始材料分开保存，修改可恢复。临时强制值、注入、屏蔽和测试专用替换在正常复测前恢复。AI 辅助定位时只提供必要内容，输出事实由工程师核对。对应 S02–S06，填写见[对应 Skill 的方法说明](../04_Skills/simulation-regression/SKILL.md)。

记录变更前后版本、原因、受影响功能、选取的原条件和关联用例、实际结果及确认人。选择范围应能覆盖改变的风险，不机械把所有变化都变成全列表，也不能因为改动行数少只跑一例。共享检查器改变往往影响多用例，应重查依赖范围。

原失败运行只读保留，修复后的运行有新编号。若工具或随机调用变化无法得到原序列，说明实际条件变化并提供替代验证依据，不能宣称严格同条件复现。报告最终引用的是当前有效结果，失效记录用于历史定位。

工程师确认 AI 提出的影响判断和代码修改，安全规则 S02/S03/S05。交付前再次核对三份产物、代码与证据一致，执行 S06；敏感处理在副本完成，保持别名、地址、长度、位宽和图文逻辑一致。未确认的变化不得作为关闭问题或完成出口的依据。
