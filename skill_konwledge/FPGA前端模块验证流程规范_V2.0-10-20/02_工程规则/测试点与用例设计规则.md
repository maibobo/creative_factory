# 测试点与用例设计规则

## 1 规格、测试点与用例

适用于规格分解、表单编写和用例维护。规则用于判断条目是否完整、可实现和可追溯；方法选择见相关 Skill。表单只保留设计规格、测试点、测试用例三个页签，用例结果来自实际运行。规则编号供评审引用，不要求另建规则报告。

| 必须满足的要求 | 检查依据 |
| --- | --- |
| 测试点对应已确认规格，描述触发条件和可观察行为 | 能从规格找到点，也能从点找到规格编号及短说明 |
| 分类以实际功能为主，子分类描述边界、等待、异常或恢复 | 不能只有“接口检查”等主题而没有具体行为 |
| 一点可对应多个用例，一例可检查多个点，但每个点均有独立判据 | 对照预期结果，不能由用例执行一次自动判全部点通过 |
| 用例名称唯一并与真实入口一致，编号遵循项目统一形式 | 列表、表单、日志和代码能使用同一名称定位 |
| 规格数量、地址、时限和长度单位明确 | 字节与数据拍、周期与时间不会混用 |
| 正常用例不施加规格禁止的输入，非法场景需有定义的响应 | 约束及错误注入依据能指出具体条款 |
| 关键数值和容量边界由可确定触发的场景保证 | 最小最大及边界前后没有全部依赖随机碰到 |
| 等待、连续事务、复位中断和恢复按模块适用行为覆盖 | 记录为何适用或不适用，不机械加入不存在能力 |
| 预期结果可转换成比较、计数、状态或有界等待 | 不使用“正常”“成功”作为唯一判据 |
| 适用主功能安排合法随机，随机维度影响真实行为 | 仅随机无关字段不能满足该功能随机验证要求 |
| 预期依据独立，观察值取自被接受接口事件 | 不直接复制 DUT 内部结果作为正确答案 |
| 实际结果初始为未执行，修改后重新判断旧结果适用性 | 模板示例、未执行及失效记录不算通过 |

## 2 场景范围与边界选择

| 规格特征 | 应增加的具体检查 | 不能采用的简化判断 |
| --- | --- | --- |
| 输入有长度字段 | 最短、最长、尾拍非整拍及单位换算，核对有效字节和结束 | 只测一个常用长度，或把数据拍数当字节数 |
| 输出允许反压 | 在首拍、中间和尾拍等待，核对稳定及恢复无丢失重复 | 只配置概率而不观察真实等待 |
| 输入输出可并行 | 选择先输入、先取出、同拍和边界附近事件 | 人为串行后声称并发能力已检查 |
| 共享缓存或容量 | 空、接近满、满、释放后接受及同时进出 | 请求很多次就认定缓存已满 |
| 错误后可恢复 | 定义错误、响应、清理及下一笔正常业务 | 只检查错误码，不检查后续状态 |
| 参数改变数据布局 | 选择改变位宽、有效字节和计数关系的实际配置 | 默认参数通过即代表所有配置 |

评审时先读规格再读表单，检查是否遗漏支持行为；再从用例反查预期结果，确认不是只覆盖名字。一个点的描述过大导致无法单独判定时拆分；多个点只有措辞不同但输入和判据完全相同时合并。编号稳定，不因添加一条用例就重排所有旧编号。

对每个主要功能提出一个“若实现错了，用例会怎样失败”的反例。例如顺序错误应由序列比较发现，丢失应由预期残留或超时发现，重复应由额外输出或已完成标识发现。不能说出失败路径时，优先完善检查，而非增加相同类型的运行次数。

选择会改变计数、存储、分包、地址和算术语义的临界点。最小最大只是起点，还要考虑整拍与非整拍、计数回绕、地址边界和同时增减。只测试数值不同但行为相同的很多点，不能替代真正的边界检查。

| 必须满足的要求 | 应使用的检查 |
| --- | --- |
| 长度明确为字节、数据拍或事务数量 | 驱动、模型、比较和计数使用一致单位 |
| 最短和最长合法输入稳定触发 | 内容、有效字节及正常结束正确 |
| 分包或字节布局分界前后有场景 | 尾拍、帧界和输出拍数符合规格 |
| 缓存占用来自真实接受与取出 | 请求计划不代替满空状态 |
| 空、接近满、满和释放按适用行为检查 | 满空标志及数据完整性同时核对 |
| 同拍增减依规格处理 | 临界上不误接收、不漏接收或重复 |
| 算术符号、扩展、截断和溢出明确 | 模型有限位宽结果与规格一致 |
| 地址及长度关联合法 | 不把未支持对齐或跨界行为当正常输入 |
| 参数改变边界时同步模型和超时 | 旧常量不继续用于新容量 |
| 非法数值仅在响应有定义时判断 | 未定义行为先澄清，不擅自规定结果 |

对每拍 W 字节的接口，非整拍长度应构造相应有效范围并检查尾部，不能用填充字节补齐后假定全部有效。输入输出宽度不同时比较规范化有效字节序列和帧边界，收发拍数可不同。结束标志过早、过晚或重复都应有明确检查。

长度为零是否有效由规格确定；没有定义时不自动加入普通合法随机。计数上限不是软件无限整数，模型应明确截断、饱和或回绕语义。随机数据接近全零或全一不能替代有符号边界和溢出检查。

形成满条件时，需要根据输入输出相对节奏控制占用。接收端始终取走时，即使发很多事务也可能永远不满。若有预留位置或多拍事务，容量单位应与规格一致，不简单按请求数计算。释放后检查下一笔接受和内容顺序，不能只看满标志下降。

同拍读写时的容量更新和状态标志可能有特定规则，应先确认，再在临界附近安排场景。复位取消、错误丢弃和合法重试会改变守恒关系，必须纳入账目，不能把所有数量变化都归为丢失。

关键边界有确定触发的用例和真实事件证据，随机用于扩展交互。工程师检查选取的边界来自哪一条规格或状态变化，避免机械枚举大量无差别值。边界问题修复后检查原值、相邻合法值和有关等待恢复，按 S05 确认。

不同类型模块应从自己的业务特点补全场景，不要求套用完全相同的清单。带寄存器或命令接口的模块，要把配置写入、实际生效和业务响应连起来检查：默认值是否符合规格，允许修改的内容是否生效，重复命令和忙时命令怎样处理，状态或错误信息何时更新。清零、保留、只读等行为按实际定义判断，不因为接口上有一个字段就额外规定它必须具备某种功能。

数据运算和格式转换模块，应同时考虑数值范围与数据组织。参考结果明确有符号和无符号、扩展或截断、舍入或饱和等适用语义；算法允许误差时，比较办法及容许范围由规格确定。流水处理还要核对输入与输出的对应关系，避免数值正确却对应了错误事务。选择一般值、会改变结果处理方式的边界及连续输入，通常比大量没有行为差异的数值更有意义。

带帧、包或记录边界的模块，不只检查中间的数据内容，还要检查一笔业务从开始到结束是否完整。长度、有效字节、结束标记和错误信息应共同支持结论；不同帧的数据不能意外混合。对短帧、非整拍、相邻帧、输入间断和输出等待等适用情形，用例说明它们影响哪个行为。格式错误只有在规格定义了处理方式时才检查其响应，不自行设计一套非法输入规则。

多个输入源共享输出或资源时，关注是否正确接收、选择、释放和继续处理。场景需要表达请求之间的关系，而不是简单启动几个独立任务；没有被接受的请求不应当成丢失，已经接受的请求也不能无故消失。优先级、公平性或最大在途等有要求时才设置对应判据；没有要求的行为，不凭测试人员的直觉规定结果。

对有响应时间要求的控制模块，先说明时间从哪个实际事件开始、到哪个事件结束，以及允许的等待条件。周期要求用于检查规格规定的功能关系，不能把理想模型的固定延迟写成 DUT 必须遵守的时限。状态变化还应与数据和完成信息一致，避免只检查状态到达而遗漏业务内容。

实际模块可能同时具备以上几类特点，测试点按共同的业务链组织即可，不必为每一类重新建立一套重复用例。对同一场景可以共用激励和初始化，但预期结果仍要说清它支持哪些判断。这样增加的是对不同模块和行为的适用性，而不是要求每个项目都填写更多字段或执行没有实际意义的组合。

## 3 输入与判据

准备与输入写本例差异：关键变量中文含义、控制组件、设置理由、范围和顺序，通常 3–30 行。共用时钟复位、模型和库放入方案。预期写被检查对象、允许关系、结束条件和失败条件。例如反压需要描述等待期间稳定、恢复后无丢失重复和有效字节序列一致，不是只写“反压测试通过”。

参数改变数据路径、容量、计数或错误处理时，应为实际交付配置安排相应检查。不同配置可复用用例，但每项结果必须注明配置；不能将某一默认模式通过扩展到全部合法模式。动态改变配置时确认模块是否支持以及生效边界。

“发送一帧，结果正确”缺长度、握手、输出及比较依据；“随机十次”缺范围、种子及目标行为；“复位后正常”缺在途处理和恢复首笔；“错误场景不适用”缺规格依据。评审应改写成能驱动和检查的条件，无法确认的写为待确认问题。

同一条预期同时检查多个独立行为时，代码中应存在对应检查路径。只比较计数会漏掉相同数量的错序，只比较数据前缀会漏掉尾拍，只检查完成会漏掉错误码。检查项不能因为实现困难而从表单中悄悄删除。

按规格检查有效内容、长度、顺序、标识、错误语义及完成数量。单纯收发数量相等不能证明数据正确，也不能发现等量重复与丢失互相抵消。事务关联从实际接受事件建立，不从准备发送对象预先假定完成。

| 必须满足的规则 | 检查依据 |
| --- | --- |
| 数据样式能区分相邻事务 | 可识别交换、重复和旧数据泄漏 |
| 字节顺序及大小端定义统一 | 不用显示格式变化代替实际转换 |
| 长度单位及尾拍有效范围明确 | 有效字节总数符合规格 |
| 严格顺序接口逐笔消费预期 | 交换两笔应失败而非任意搜索匹配 |
| 乱序接口按有效键和顺序域关联 | ID、通道和允许复用规则完整 |
| 未知响应和额外输出显式报错 | 不能忽略无法匹配的记录 |
| 重复响应或重复完成能识别 | 已完成项不再次消费预期 |
| 缺失输出由超时或结束残留发现 | 不以固定延时退出而漏报 |
| 错误响应检查数据和状态的后续影响 | 不只看到错误码就算异常处理完成 |
| 复位取消纳入事务账目 | 合法取消与意外丢失区分 |
| 多接口汇总保持事务边界 | 某条通道完成不代表整笔完成 |

协议不允许乱序时，Scoreboard 应按队首比较，不能在整个队列中搜索任意匹配数据而把交换当正确。协议允许乱序时，选择足以唯一定位当前在途事务的键，明确相同 ID 是否允许复用及同 ID 顺序约束。不能把所有相同 ID 一律判重复，也不能只凭 ID 匹配而忽略长度或子通道。

关联结构保存接受、完成和取消状态，完成后释放资源的时刻符合协议。ID 回绕或复用时区分上一代事务，防止旧响应误匹配。多数据拍事务必须正确识别起止边界，丢失尾部要由长度或结束条件发现。

宽度转换、合并、拆分和重排先定义规范化有效字节序列，再检查输出布局。字节使能仅屏蔽无效范围，不屏蔽有效位的未知态或控制错误。对算术模块明确符号、扩展、截断、饱和或回绕，避免参考模型采用无限精度而偏离硬件规格。

对一进一出业务，可核对接受数等于完成数、合法取消数及当前在途数之和；对拆分和合并先换算成共同单位。记录数据拍数、字节数和事务数各自含义。守恒关系用于发现遗漏，但仍需内容和顺序检查。

工程师用不同载荷、尾拍等待和合法 ID 复用等场景走查，确认关联规则没有把设计错误容忍掉。相关观察和比较依据写入方案，实际差异保留在运行日志。

## 4 维护与确认

规格或判据改变时同步测试点、用例、环境和报告；保留原结果适用范围。工程师编写初稿后，AI 可检查遗漏与矛盾，工程师完善确认。涉及业务资料和模型输入执行 S01/S02，代码与结论执行 S05。填写示例见[对应 Skill 的方法说明](../04_Skills/verification-planning/SKILL.md)。
