# 可选断言使用规则

## 1 使用范围与判据

断言用于动态仿真中的局部时序和不变量检查，项目按需要启用。启用后的失败必须计入用例失败，不能仅显示在工具窗口。关闭时记录开关和原因，不把关闭当成已通过。无法使用断言语法时可采用等效过程检查，但采样时机和判断语义必须明确。

| 必须满足的要求 | 检查依据 |
| --- | --- |
| 每条检查有明确规格意图和唯一标识 | 能判断为何报错、对应哪个行为 |
| 时钟、采样关系和有效前提明确 | 不混淆当前采样与更新后的值 |
| 复位屏蔽范围来自实际语义 | 不屏蔽正常业务，不漏查复位后首笔 |
| 有界响应使用规格允许的时间范围 | 合法反压不被误判，永久等待能够失败 |
| 前提事件是否发生独立可查 | 没有触发前提不宣称目标已验证 |
| 失败进入统一错误统计及最终结果 | 受控违例能使该用例失败 |
| 数据稳定检查包含必要侧带信息 | 不只检查数据而漏掉长度、ID 或尾部标志 |
| 工具和语法能力已确认 | 编译失败不当作断言正常，也不静默取消 |
| 修改条件、时限或屏蔽需重新审查 | 不以放宽判据掩盖真实问题 |
| 局部检查与端到端比较配合 | 不能从时序无错推断全部数据内容正确 |

## 2 检查有效性

反压期间保持：当前有效事务尚未接受时，下一采样点的数据和相关控制保持；接受或复位等允许改变的条件应按协议排除。请求响应：实际接受请求后，在约定条件与上限内得到相应响应；如果协议允许无界外部等待，就不能凭空添加 DUT 必须在固定拍数响应的要求，应将环境限制和系统 watchdog 区别记录。

禁止组合：只检查规格禁止的控制组合，不把合法状态过渡误判。复位检查：明确复位期间允许什么输出，退出后何时要求初值或新业务；异步进入和同步观察的关系要解释。未知态检查用于要求确定的控制或有效数据，不能无区别禁止协议允许未定义的空闲数据。

蕴含式检查的前提未发生时可能没有失败，因此应从真实事件计数或用例观察确认前提出现。检查有触发不代表异常分支已检出，还需要受控违例自检。若误报来自采样错误，应修正时间关系，而不是屏蔽所有等待场景。

断言日志保存标识、层次、时间和用例/种子，对重复报错可汇总同一根因，但原始失败不能丢失。一个功能错误同时被 Scoreboard 与断言发现时，可以关联同一问题记录，不能借去重而清空用例失败。

| 检查意图 | 必须补充的定义 | 容易漏掉或误报的情况 |
| --- | --- | --- |
| 等待时数据稳定 | 接受边沿、保持到何时、复位条件和侧带集合 | 只看 data 漏掉尾标志变化，或接受后合法改变被误报 |
| 请求必须响应 | 请求接受事件、响应关联及允许等待 | 前提从未出现、响应属于其他 ID |
| 复位后状态正确 | 何时开始要求、模型忙状态及有效输出 | 撤销复位立即判断导致误报，或屏蔽过久漏错 |
| 控制无未知态 | 哪些控制必须确定、有效数据条件 | 空闲无效数据被无必要禁止 |
| 容量不越界 | 数量单位、同拍增减和合法取消 | 同拍事件未净算，边界上误报或漏报 |

断言与过程检查应采用可解释的采样语义。对跨时间关系，明确检查的是哪些采样点及前后值；不能通过在同一时刻插入任意延时让结果偶然正确。工具支持情况不确定时，先在允许环境确认语法和报告接入，再用于工程结论。

关闭某条检查可能让相关测试点失去唯一证据，应同步更新方案和出口判断。若存在其他独立有效检查，可以说明替代关系；不能仅记录开关关闭但继续宣称原检查覆盖的行为已证明。

## 3 结果与人工确认

工程师确认启用范围、规格依据、复位屏蔽、前提和结果接入。AI 可提出检查模板，不能替代上述判断。自检在可恢复副本中按 S03 进行，恢复后正常运行；记录与结论按 S04/S05 核对。
