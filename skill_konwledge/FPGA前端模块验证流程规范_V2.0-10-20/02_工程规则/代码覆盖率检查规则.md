# 代码覆盖率检查规则

## 1 指标与统计范围

只记录行、条件、状态机三个指标。行看可执行语句，条件看逻辑取值，状态机看状态与转换；各项口径以实际工具及版本为准。工具报告帮助发现未执行内容，不能代替数据、协议和规格检查，也不设跨工具统一百分比门槛。

| 必须满足的要求 | 核对依据 |
| --- | --- |
| 范围明确到当前 DUT、源版本、实例和配置 | 排除 TB、库及其他实例混入统计造成误导 |
| 记录工具版本、语言、支持指标和采集选项 | 不从其他版本说明推断本机支持能力 |
| 原始报告与数据保留，不人工改写实测数值 | 报告摘要能够找到原始来源 |
| 参与运行编号与结果状态可查 | 失败运行不能作为成功功能证据 |
| 合并前确认版本、范围、参数及数据库兼容性 | 不把互不兼容数据凑成更高数字 |
| 区分不支持、未启用、无数据、零覆盖和不适用 | 状态不能混用或统一填零 |
| 条件指标按工具口径解释 | 不等价于全部输入组合或全部功能已验证 |
| 状态机先确认识别能力和识别对象 | 未识别不伪造原生统计，用功能证据说明 |
| 补测对照目标位置和实际事件 | 不能仅以总数变化认定目标已处理 |
| 结论写入仿真回归报告并经人工确认 | 不增加独立工作表，不以说明修改百分比 |

## 2 工具和配置

不同版本、语言和模型的能力不相同。XSim 的具体支持按所用 UG900 版本和实际配置核对；不能从较新版本支持某项推断旧版本同样支持，也不能把波形查看能力当统计能力。国产器件模型要核对是否能展开、工具是否能进入受保护模型及统计范围；受限内容如实记录。

工具报告不能直接操作保留项时，在仿真回归报告中说明位置、原因和影响，保留原始数字。不要求为了统一格式强行生成工具没有的字段。对状态行为可用测试点和实际转换证据补充，但该证据不写成工具原生状态机百分比。

## 3 结果读取与表达

先核对本次 DUT 和版本，再看各模块是否有有效数据，接着检查关键功能相关的未覆盖位置。大量空白可能是顶层错误、复位未退出或模型未就绪；先排除采集和运行问题，再安排补测。当前参数关闭的逻辑与合法输入未触发的逻辑分别处理。

同一源码在不同参数下生成结构不同，分开保留配置结果，报告说明整体交付范围。即使工具允许合并，也需要判断合并口径是否适合完成结论。不能仅保留总体截图而丢失文件与位置细节。

| 状态 | 含义 | 报告写法要求 |
| --- | --- | --- |
| 有实测结果 | 工具对当前范围产生有效统计 | 写数值、范围、版本及参与运行 |
| 未启用 | 支持能力存在，但本轮没有正确开启 | 不能填零表示测过，修正采集并运行 |
| 不支持 | 实际版本或语言没有该统计能力 | 写依据、补充功能证据和限制 |
| 无有效数据 | 运行或数据库未产生可用信息 | 查顶层、启动和路径，不作为已测结论 |
| 零覆盖 | 已统计且对象未被执行 | 查触发条件和实际事件，安排处理 |
| 不适用 | 当前约定范围不含该对象或功能 | 写范围依据和确认人，不等于工具不支持 |

当报告只给总体值时，应保留能够定位关键模块和未覆盖内容的信息；不能用一个总值掩盖主要模块根本没执行。报告位置随源码移动时保留版本关联，避免用新的行号错误解释旧报告。

补测后若目标行为出现但数字不变，检查工具统计单位、优化和识别能力；若数字变了但行为证据不足，检查是不是其他路径贡献。两种信息互相核对，不强行要求每个用例对应固定的百分比增量。

## 4 结论与确认

工程师确认支持能力、统计范围、原始结果、补测和剩余说明。原因未知的关键项保持待处理，不能用“防御性代码”统一解释。处理方法见[未覆盖项处理规则](未覆盖项处理规则.md)，安全要求 S03/S04/S05/S06。
