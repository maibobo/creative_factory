# 随机验证规则

## 1 使用范围与约束

适用的主要功能必须安排随机验证，选择数据、长度、地址、请求间隔、反压位置、等待时长和合法参数等影响行为的维度。控制简单且没有有意义随机变化的部分可用定向检查并说明原因，不要求所有变量随机。关键边界先由定向用例保证，随机用于扩大组合。

| 必须满足的要求 | 检查依据 |
| --- | --- |
| 每个随机维度有规格范围和选择目的 | 能说明它改变哪一种行为或相互关系 |
| 合法激励和故意错误注入分开 | 普通随机不会生成未定义输入并错误归责 DUT |
| 相关字段共同满足协议约束 | 长度、地址、对齐、有效字节和边界一致 |
| 随机生成失败立即上报 | 不复用旧值，不使用未初始化对象继续 |
| 关键边界有可确定触发的安排 | 最小最大和尾部等待不全靠概率命中 |
| 种子及有效约束配置记录完整 | 隐含随机源和派生方式可以解释 |
| 实际事件有可观察证据 | 设定概率不代替真实反压和接受记录 |
| 随机输入仍经过有效参考模型和比较器 | 不只运行随机流而不判断结果 |
| 失败保留原条件，修改后先重放 | 不换种子掩盖问题，不覆盖首次失败 |
| 约束改变需说明规格依据及旧结果影响 | 不用收窄合法范围逃避缺陷 |

## 2 场景有效性

随机反压概率为某个值不证明本轮出现等待，应记录实际等待发生次数及必要的最长持续时间。生成了长帧也不证明 DUT 接受了长帧，检查输入实际握手和结束事件。若连续运行没有触发目标，先看复位就绪、范围约束和 Driver 行为，再决定调整次数。

数据可采用可区分序号加随机载荷，既能扩大数值组合，又便于发现错序和重复。只随机所有字段可能破坏合法关联，应从事务语义出发先生成合法长度和地址，再生成相应数据。需要验证非法组合时使用专用用例并写明预期响应。

| 功能风险 | 有价值的随机变化 | 应保留的定向保证 |
| --- | --- | --- |
| 反压时推进错误 | 等待起点、持续长度、间隔和载荷 | 首拍和尾拍长等待必定发生 |
| 长度与尾字节处理 | 合法长度、非整拍长度及有效字节模式 | 最短、最长和关键分界前后 |
| 缓存容量 | 输入输出节奏和连续事务数量 | 空、满及临界同拍事件 |
| ID 或请求关联 | 合法 ID、完成先后和通道延迟 | 复用边界、允许的同域顺序 |
| 复位清理 | 合法复位时刻和事务节奏 | 接受后未完成、部分输出和恢复首笔 |
| 错误恢复 | 定义范围内的错误位置和恢复等待 | 每种约定错误入口和正常恢复 |

随机不意味着均匀分布。可以根据风险提高关键组合出现机会，但概率与约束必须保留，不能把低概率合法场景永久排除。约束互相冲突时先修正规格或生成设计，不能在生成失败后偷偷使用默认事务。

增加随机次数前，先确认每轮是否实际产生不同输入、随机源是否真正生效、关键接口是否被驱动。如果种子变化却事务完全相同，要查种子传递、固定重设和对象随机化调用；如果种子相同却行为变化，要查共享状态、调度和环境输入。

## 3 复现、失败处理与确认

相同 seed 不保证跨工具、代码或对象创建顺序得到同一序列。记录随机源、调用条件和线程相关配置；多个接口独立随机时，固定派生关系或保存各自实际种子。并行运行不得因共享文件覆盖随机数据或配置。

同种子偶现时重点检查采样竞态、共享可变对象和线程生命周期，不能一律归为随机正常现象。需要保存事务摘要以重放特定失败时，记录它与原条件的关系，不将后生成的一组输入当成原组。

先复现首个偏离，判断激励合法性和检查器是否正确，再实施修改。修复后执行原失败条件、关联边界和新的随机组合。任何被排除的输入范围都应说明是否属于规格限制，并由工程师确认。记录按 S04 保存，AI 建议和约束修改按 S02/S05 审查。
