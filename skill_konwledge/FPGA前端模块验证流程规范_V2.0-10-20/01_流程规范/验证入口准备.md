# 验证入口准备

## 1 入口目标

开始前要明确验证哪个模块、哪些功能和合法配置，以及怎样得到可靠的预期结果。入口准备是工作前提，不单独编号为验证阶段。未解决的问题按影响区分：不影响当前功能的可以保留并开展其他工作；决定预期行为的关键歧义应先确认，不能通过观察现有 RTL 自行定义正确结果。

## 2 输入材料及检查内容

| 输入 | 必须读到的内容 | 发现缺失时的处理 | 安全规则 |
|---|---|---|---|
| 设计规格 | 功能、输入输出关系、合法值、状态变化、响应时限和异常恢复 | 记录具体问题及受影响用例，不填模糊的“待完善” | S01、S02 |
| 接口资料 | 位宽、方向、握手边沿、数据有效范围、帧或事务边界 | 与模块端口逐项对应，接口名相同也核对含义 | S01、S05 |
| RTL 与参数 | 顶层、依赖模块、文件顺序、宏、参数、初始化文件 | 列出实际采用值，避免环境默认值与 DUT 不一致 | S03、S05 |
| 器件/IP 资料 | 器件系列、IP 版本、仿真模型、依赖库、复位与就绪条件 | 将缺失模型与可替代接口分开，不把替代模型当真实 IP | S01、S03 |
| 工具环境 | 仿真器版本、语言支持、模型兼容性、运行入口和结果目录 | 先确认可用配置，再选择环境实现形式 | S03、S04 |
| 已有代码与结果 | 适用版本、配置和已知问题，哪些组件可以复用 | 复用前检查职责及判据，旧通过结果不自动沿用 | S02、S04 |

## 3 准备步骤

1. 工程师确定模块边界：邻接模块由何种模型代替，验证从哪一个输入事件开始，到哪一个输出或状态结束。把物理设备无法在 RTL 模型中表达的行为列为限制，不将其混入模块仿真结论。安全：S01、S02。
2. 将每项规格中的数量和时间单位统一，例如长度以字节还是数据拍表示、地址是否对齐、最大等待是时钟周期还是仿真时间。单位不清时，记录待确认值及影响。安全：S02、S05。
3. 确认复位有效电平、退出方式和就绪前提。对使用 IP 的模块，区别复位撤销与模型可接受业务两个时刻。需要校准或启动完成的，以有效状态信号作为条件并设等待上限。安全：S03、S05。
4. 列出当前需要交付的实际参数组合，说明哪些组合改变逻辑结构或检查规则。只保留项目合法范围，不根据 RTL 中存在参数就认定全部组合都受支持。安全：S02、S05。
5. 记录工具、库和文件位置，验证工作目录与结果目录分开。只读取当前任务所需资料；检查现有启动文件是否会清理或覆盖其他目录。安全：S01、S03、S04。
6. 将资料缺口整理成“问题—影响功能—暂时处理—确认结果”，由工程师确认后写入验证方案输入部分。安全：S02、S05。

## 4 入口填写示例

示例对象为带输入和输出握手的数据缓存模块。输入接收条件为 valid 与 ready 在规定边沿同时有效，输出以相同规则计数。深度采用项目配置，复位中断时按已确认规则丢弃旧数据，复位后等待就绪再接收新事务。此时需要的判据是被接受的数据在输出端保持内容及顺序，不是“发送任务调用了多少次”。

若规格没有说明满缓存时是否允许同拍读写，应把该行为作为待确认问题。可以先验证空闲初始化、一般写入读出和不涉及满边界的反压；相关边界用例在确认前不填写通过。若仅有接口模型，报告明确验证了接口级行为，不能延伸到真实存储器的物理特性。

## 5 人工确认问题

入口应能回答：是否知道每个端口何时有效；是否知道预期结果的独立来源；是否有合法参数表；是否知道复位后何时允许业务；是否明确真实 IP 与替代模型的边界；是否能指出输出结果保存位置。任何否定答案都应落实到具体受影响工作，不以“资料已收到”代替可开始实施的判断。

## 6 交付与完成条件

在验证方案中写入模块范围、输入资料版本、参数配置、工具与模型、待确认事项和限制。无需另建入口表。主要功能及判据明确、实际对象可定位、模型与工具具备实施条件后进入 V1。资料更改后更新记录，并把影响通知到相应测试点和环境组件。

安全编号及处理方式见[全流程安全规则](../06_质量与发布/全流程安全规则.md)。
