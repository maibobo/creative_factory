# 每日回归脚本使用

[脚本模板](../scripts/run_daily_regression.py) · [配置模板](../scripts/regression_config.template.json)

由第四阶段按项目仿真入口填写配置，case顺序与用例表一致。每条配置写用例名称、测试点反标、命令参数列表、超时、PASS/FAIL匹配式；随机用例另写Seed，命令中可用{seed}代入。匹配式由项目实际自检结果确定。

复制配置模板后填写项目工作目录、编译命令和cases。空cases不执行，不产生通过结论。工作目录相对于配置文件解析，输出目录由命令指定；脚本不创建定时任务，可由现有每日调度调用。

~~~powershell
python scripts/run_daily_regression.py --config regression_config.json --output runs
~~~

命令以参数列表执行，不自动拼接shell命令；PowerShell/Tcl/远程入口由项目配置指定。每轮创建独立目录，保存配置快照、每例日志、命令、Seed、退出码、耗时、结果及汇总JSON/CSV。

功能失败或用例超时记录FAIL后继续；编译失败、工作目录/工具缺失停止，后续项记NOT_RUN。退出码：0全部通过；1有功能失败；2配置、编译或环境异常。PASS同时要求正常退出、有通过匹配且无失败匹配，最终仍按验证方案核对检查内容。

单例复现使用--case "用例名称"，沿用保存的配置和Seed。修复后再执行批准的回归集合；工具身份和最终时序结论记录在仿真报告。

case配置示意，命令与匹配式替换成当前项目实际入口；无随机参数时省略seed：

~~~json
{
  "name": "用例名称",
  "test_points": ["项目.001.001＋测试点内容"],
  "command": ["仿真可执行入口", "项目参数", "{seed}"],
  "timeout_seconds": 600,
  "seed": 17,
  "pass_pattern": "(?m)^TEST_RESULT=PASS$",
  "fail_pattern": "(?m)^TEST_RESULT=FAIL$|\\bFATAL\\b"
}
~~~

超时和Seed是示意值，由验证方案给出本项目取值。可用environment_error_pattern识别许可或工具异常；编译失败匹配式可用compile_fail_pattern覆盖默认ERROR/FATAL匹配。配置快照已固化工作目录，可直接作为--config用于同版本单例复现。
