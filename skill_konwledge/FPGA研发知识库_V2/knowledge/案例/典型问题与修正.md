# 典型问题与修正

以下为历史记录提炼的排查经验，本轮未重跑。通用化的对象是检查方法，原工程修复动作与数字仍受其配置限制。

| 现象 | 原记录中的原因/处理 | 新任务如何使用 |
|---|---|---|
| RX数据进入FIFO，完成和IRQ不出现 | 旧FDMA端口名与实际valid/accept语义相反，wrapper映射修正 | 设计/审查核对端口方向、内部驱动与真实握手；测试以完成事务计数而非信号名推断 |
| 卡侧读完，Host数组哨兵未变 | Root Port数组并非C2H接收存储，补接收模型后比较 | 验证方案先说明每个模型能观察/存储什么，分层比较地址、字节和内容 |
| FIFO数据似乎错拍 | FWFT monitor观察存在采样竞争 | 查读模式、采样时刻和快照；先辨TB与DUT责任，再修改 |
| almost_full场景未触发 | busy期间注入无效 | 观察实际写入/握手数和初始化状态；等待周期按当前IP确定 |
| 展开报work.-相关错误 | 含空格路径的参数解析问题 | 看完整命令及日志，正确传递参数，不仅从错误尾行猜顶层 |
| 新运行显示旧PASS | 读取了上一轮日志 | 独立运行目录、版本和结束记录，保留失败与重试身份 |

## 把经验落实到交付

设计方案写清接口与状态语义；代码审查核对实现；测试点定义故障可观察条件；验证环境确保激励确实到达、检查位置正确；报告说明通过的层级和未覆盖内容。无需把旧案例的演示话术、固定修复顺序或历史优先级搬进新流程。
