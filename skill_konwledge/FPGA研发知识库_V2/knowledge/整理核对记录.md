# 整理核对记录

本记录说明对参考资料做了哪些适用性处理。它是文档核对，不是对历史工程重新验证。

| 原资料内容 | 风险 | 本版处理 |
|---|---|---|
| ASIC规则要求CTS/DFT、工艺单元、ASIC文件表隔离 | 直接变成独立FPGA项目的必做项 | 规则适用页先区分配置；保留代码编号与例外，ASIC专属项单列 |
| 原规范来源标签涉及两份已排除PDF | 继续宣称所有规则都是核实的厂商原文 | 不纳入原05来源声明及PDF，仅保留已确认项目规则并说明身份 |
| Aurora历史主题给出线路速率、位宽与用户时钟关系 | 跨编码/IP模式套算 | IP专题绑定历史配置，当前工程按XCI/Core输出核实 |
| DDR历史BIST仅单拍、单outstanding | 把最小示例能力误当DDR/AXI通用限制 | 专题说明历史边界，当前测试按实际burst/ID/并发能力展开 |
| 以太网历史CRC残余、帧长、过滤优先级 | 将实现审计结果写成协议标准 | 专题明确属于该工程，实现与测试回到当前规格 |
| 原案例要求busy连续两拍低再发刺激 | 推成所有FIFO的固定等待时间 | 提炼为核对IP就绪与真实接受条件，周期数按当前IP处理 |
| 历史valid/ready端口名颠倒 | 形成“valid/ready必须交叉”的错误经验 | 只保留核对方向、内部驱动及协议的检查方法 |
| 原示例包含UVM phase/factory/objection规则 | 迫使所有轻量SV采用完整UVM | 通用SV与UVM专属职责分开，按实际环境规模取用 |
| 原以太网表有优先级分组 | 回到已否定的分级执行流程 | 新流程统一用例行顺序，历史快照说明原分组不适用本版 |
| 原V2展示包有演示门禁、冻结合同和管理话术 | 把展示组织形式变成开发必填步骤 | 只提取技术案例、边界和来源；四阶段沿用已确认流程 |

## 四类场景走查

| 场景 | 设计与实现依据 | 策划与执行核对 |
|---|---|---|
| DDR初始化与读写 | [DDR](IP/DDR与MIG.md)区分域复位、校准、AXI独立通道 | 测试点包括启动前置、反压、响应、读回；行为模型结论不扩为PHY通过 |
| AXI反压与突发 | [AXI](通用/AXI与流接口.md)区分类型、len、size、ID和并发配置 | 检查真实握手、稳定性、边界、响应；超时策略取项目规格 |
| CDC/FIFO | [CDC](通用/时钟复位与CDC.md)按信息类型选结构；[FIFO](通用/FIFO与数据一致性.md)核对读模式 | 检查事件完整、满空、复位和数据/描述符一致性；不以数字仿真证明MTBF |
| Aurora接口映射 | [Aurora](IP/Aurora.md)和[案例](案例/典型问题与修正.md)保留接口适用范围 | 检查实际方向、不可反压输入、尾字节与端到端比较，不照搬旧修复 |

上述主题均可从四阶段入口按功能找到，最终交付格式由现有模板规定。来源不足的部分集中在[内容缺口](内容缺口.md)，不补造企业规则或工程通过结论。
