# 规则适用说明

本版沿用用户确认的代码规范输出和四阶段流程口径。规则中保留的“厂商风格”指现有项目采用的命名、组织和检视习惯；本包不将其宣称为已经核实的厂商原文制度。两份已排除PDF不读取、不打包，也不依据其摘要新增要求。

## FPGA项目如何采用

| 范围 | 使用方式 |
|---|---|
| 用户四条规则 | 保留单always默认单目标及共同控制/FSM例外、wire声明与驱动分离、公共功能复用、语义段注释 |
| 命名、模块、组合时序、FSM、位宽 | 沿用现有项目规则与编号。模块大写下划线、文件小写下划线、低有效 `_n` 等是书写约定，不误称语言限制 |
| 语言与综合 | 按已确认的项目语言基线。既有ASIC稿使用Verilog-2001；SV验证规范不自动授权改变RTL语言，也不据此否定项目明确采用的可综合SV |
| CDC、复位与公共模块 | 保留对应功能的结构检查和复用要求。具体单元、IP及配置以项目实际确认项为准，登记为pending的条目不写成approved |
| ASIC专属约束 | ICG/CTS、工艺库、DFT、低功耗/等价签核等不自动纳入FPGA必做项；原规则中的ASIC signoff文件表隔离要求仅用于对应配置 |
| FPGA时钟与初始化 | 厂商时钟原语、PLL/MMCM、专用I/O、存储器初始化等按当前器件和工具支持及项目要求处理；不能机械套用ASIC稿的全部禁止项 |
| SV/UVM | 通用SV部分按所用组件适用；factory、phase、objection、TLM等UVM专属规则只在UVM环境使用，不要求轻量TB采用整套UVM结构 |
| 审查证据 | 当前流程的lint/CDC由Skill辅助与人工检视完成；编译、综合、仿真结果分别取实际输出，人工功能结论由工程师确认 |

## 自定义规则的关键边界

- `CUSTOM-RTL-001`：按左值根对象计数；同一向量的位选、部分选择仍是一个目标。多个目标只有共同控制或紧密FSM寄存器组等原规则例外可合并；不得混入独立时钟、复位或生命周期，注释说明理由。
- `CUSTOM-RTL-002`：`wire req_fire; assign req_fire = req_valid & req_ready;`。声明赋值禁用是项目约定；Verilog过程赋值目标声明为reg，并核对唯一驱动。
- `CUSTOM-RTL-003`：复用项目认可的FIFO、同步器及公共功能实现；使用前核对版本、接口、延迟、配置及证据。随包批准单元表是历史快照，不是本项目新增批准。
- `CUSTOM-RTL-004`：注释说明功能意图、时序、约束与例外；不另加文件头、注释比例或装饰线要求。

M1/M2/R沿用原稿级别，但先判断本项目是否适用。例外说明技术理由、影响与确认结果；不适用项不计为缺陷。
