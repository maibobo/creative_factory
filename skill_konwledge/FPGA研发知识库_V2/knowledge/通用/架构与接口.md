# 架构与接口

适用于顶层、子模块及多IP数据通路设计。输入是工程师给出的功能边界、速率、容量和关键参数初值。

## 模块职责与数据流

按功能和时钟域划分模块，明确每一级接收什么、缓存什么、何时提交、何时输出。连接图同时标出数据、控制、状态及跨域位置。计算吞吐时区分线路速率、用户接口有效吞吐与协议开销；持续到达的数据不能只靠平均带宽判断可接收。

缓冲预算需覆盖下游最长暂停、反压传播期间仍会到达的数据，以及不能中断的完整事务。深度取值由本项目流量和延迟推导，再核对IP允许配置。无ready的入口不能假定上游会等待；容量不足时的丢弃、报错和恢复行为要在设计中定义。

信号表从当前模块视角写方向，注明中文含义和位宽；有效条件、采样时钟域以及尾拍字段的作用写在含义中。`valid`、`ready`、`accept`、`done`等名字不能代替行为说明。

## 完成与可见性

| 信号或事件 | 实际证明的内容 | 仍需检查 |
|---|---|---|
| 输入握手 | 当前拍被该接口接受 | 数据是否最终送达 |
| FIFO写入 | 数据进入当前缓存 | 是否溢出、跨域和后续排出 |
| AXI响应 | 对应总线事务响应 | 响应码、关联关系、端到端数据 |
| DMA完成状态 | 当前DMA定义的完成阶段 | 内存内容、软件可见性与一致性 |
| IRQ请求/确认 | 具体IP定义的中断阶段 | 是否到达软件ISR、软件是否处理完成 |

地址、长度明确单位：字节、拍、word不能混用。端口转换需要说明字节顺序、尾拍有效字节、SOF/EOF或TLAST转换。配置寄存器需定义何时生效，清除与新事件同拍时谁优先；跨域配置不能让半帧使用旧值、半帧使用新值，除非功能明确允许。

## 设计与验证连接

每个模块首小节列功能规格及实现功能。时序图至少说明关键握手、反压、启动/复位与完成关系，不为每个简单信号绘图。验证重点包括持续输入、最长暂停、边界长度、清状态同时发生新事件、运行中改配置及异常恢复；只选本模块实际涉及的场景。

历史wrapper曾出现端口名与真实握手含义相反的问题，见[接口映射案例](../案例/典型问题与修正.md)。复用旧模块时核对内部驱动和协议，不按同名机械相连。
