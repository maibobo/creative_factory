# RTL结构与审查

以[规则适用说明](../规范/规则适用说明.md)确定范围，再逐功能核对实现。下面是现有规则的使用要点，完整例外以原规则为准。

| 功能结构 | 检视内容 | 对应规则 |
|---|---|---|
| 声明和驱动 | wire声明/assign分离；过程目标类型正确；无连续、过程、实例多源驱动 | CUSTOM-RTL-002、RTL-DRV |
| always职责 | 默认一个左值根对象，多目标按共同控制或FSM例外说明 | CUSTOM-RTL-001、RTL-ALWAYS |
| 组合逻辑 | 默认值与各路径赋值完整；无意外锁存、组合环、掩盖X的casex | RTL-COMB |
| 时序逻辑 | 使用非阻塞赋值；使能、复位、清除与置位优先级明确 | RTL-SEQ、RTL-RST |
| 状态机 | 当前态/次态清楚；非法状态回到已定义安全状态；握手、超时和恢复行为正确 | RTL-FSM |
| 算术和参数 | 位宽、符号、进位、截断、移位、终值与非法参数组合 | RTL-WIDTH、RTL-GEN |
| 公共功能 | 模块/IP、配置、延迟、复位和约束匹配，禁止虚构批准模块 | CUSTOM-RTL-003、RTL-IP |
| 注释 | 说明语义段意图、时序条件、边界及例外 | CUSTOM-RTL-004、RTL-CMT |

## 典型错误与修正方向

wire声明同时赋值改为独立声明和assign，不改变功能；计数器按真实握手推进，避免反压时多计；有进位要求的加法先明确扩展宽度；环深度非2次幂时显式处理终值；清除和新事件同拍按已确认规格写清优先级。

不能为了“一个always一个目标”机械拆散满足原例外且更清楚的FSM寄存器组。也不能用给所有数据寄存器加复位来掩盖有效标志问题。未复位数据只有在有效条件成立后才能使用。

[RTL示例](../../examples/rtl/asic_rtl_template.v)演示两个状态的请求/响应、握手事件和独立计数过程。它是原规范示例，参数需为合法正值；不是通用满吞吐流水模块，不能据其接口外形推断每周期都接收请求。注释中的批准同步器是占位说明，不是可实例化模块。

## 四步检查的职责

编译先确认文件表、顶层、语言、参数和依赖；人工lint/CDC检视结构风险；人工功能检视逐功能核对行为和边界；综合检查真实推断的寄存器、RAM、DSP、锁存、多驱动、黑盒及关键告警。可综合不代表功能正确，编译通过也不能代替功能检视。
