# 时钟复位与CDC

适用于接口、状态、控制与数据跨域。先列源域、目标域、时钟关系、复位关系和需要保持的信息，再选结构。相同标称频率不等于同步时钟。

| 信息形态 | 可考虑的结构 | 需要说明的条件 |
|---|---|---|
| 稳定单比特电平 | 已确认的同步器 | 源端无组合毛刺，保持时间足够；同步级数需结合目标条件，不能把两级当作普遍充分证明 |
| 窄脉冲或事件 | 展宽、toggle、握手、事件计数 | 允许的事件速率、最小间隔、是否可能丢失或重复；toggle并不能无限速接收事件 |
| 低速多比特配置 | 握手并保持数据 | 数据相对握手稳定，整体值一致，确认后才能改动 |
| 连续多比特流 | 异步FIFO | 满空行为、复位、吞吐与读模式满足接口要求 |
| 指针或计数 | 适用协议下的Gray等结构 | 编码变化条件、采样及实现约束；不能随意将任意多比特总线改成Gray |

多比特逐位同步可能得到不属于任一源时刻的组合值。数据同步正确还不够：配置生效时刻、状态清除确认、满空恢复及复位后的首个事务都需有协议说明。

## 复位

项目默认采用低有效、异步置位、目标域同步释放的既有规则；厂商IP端口按其实际复位协议处理，不强行改写。叶级使用已定义的域复位；说明时钟稳定、IP初始化与业务释放的先后关系。异步FIFO两侧复位及busy状态按所用版本处理。

复位打断事务时，明确未完成数据丢弃、保留或重发，monitor和scoreboard采用相同的事务边界；不能仅清checker队列来隐藏DUT仍输出的旧数据。sticky状态清除若只发生在目标域，旧的源域电平可能再次置位，需核对确认或清除握手。

## 检视与用例

检查跨域信号是否都经过正确结构，同步器前后组合逻辑、扇出与约束是否匹配；记录人工检视结果，本版不宣称执行专用CDC工具。仿真选择不同频率比、相位、背靠背事件及运行中复位，检查事件数与数据完整性。数字仿真通过不能证明亚稳态概率或物理实现安全。

示例边界：历史FIFO测试要求busy连续两拍低后再注入，仅适用于该环境，不是所有IP的通用复位等待周期。
