# 仿真回归与定位

适用于已确认测试点和验证方案的执行。先固定源文件、顶层、宏/参数、工具/IP库版本、filelist、配置和用例入口；测试代码反标测试点，用例名称与入口一一对应或明确参数化映射。

## 编译到运行

编译检查语言与依赖，展开检查顶层、参数、绑定及IP模型，运行阶段才执行用例。找不到工具、许可证、库或模型时属于环境/构建异常，不记作DUT功能失败。UVM的interface、package及class include顺序参考[随包示例](../../examples/sv_uvm_minimal/README.md)，不能把已include的class文件重复编译。

每轮使用独立结果目录，保存输入配置、命令、Seed、日志和结果。按用例表行顺序运行；功能不匹配或用例超时保留现场后继续，编译/环境失效停止并标记后续未运行。每日脚本及配置沿用[现有回归入口](../../references/每日回归脚本使用.md)，由当前项目填写工具命令和判据。

## 失败定位

| 现象 | 优先核对 |
|---|---|
| 无法编译/展开 | 完整日志、文件表、库映射、参数转义、路径中的空格、实际顶层 |
| 没有事务或覆盖不增长 | 前置条件、复位busy、链路/校准、刺激是否真正握手 |
| 数据错一拍 | FIFO读模式、接口采样边沿、clocking block快照、尾拍有效范围 |
| DMA完成但数据不匹配 | 地址/字节有效、真实接收路径、Host模型职责、monitor位置 |
| 有PASS字样仍有错误 | 总错误计数、checker、残留队列、超时、日志是否属于本轮 |
| 时好时坏 | 同Seed/同版本复现，分辨调度竞态、随机配置与真实边界错误 |

先区分需求/判据、DUT、TB和环境，再决定修复对象。固定Seed复现后进行必要扩展，不通过无限重跑直到成功来覆盖原失败。

## 结果与复现

PASS需要正常结束、实际通过标志及无失败标志，同时满足验证方案的检查条件。脚本能识别文本不代表测试点充分覆盖；未激励、未检查或因环境中断的项保留未完成。

报告第三章按功能或用例给出现象、必要证据、结论，第四章说明验证范围、未覆盖及遗留问题。模型边界保持明确：行为级内存、用户接口BFM、真实IP模型和板级软件分别属于不同验证层级。
