# 反标关系示例

此例仅演示交付关联，不是新的项目需求或已执行用例。采用[原规范RTL示例](rtl/asic_rtl_template.v)默认DATA_W=8、COUNT_W=8，输入复位按该示例的域复位前提提供。它有IDLE/RESP两个状态，不支持每周期持续接受请求。

## 测试用例

编号：DEMO-CASE-001。名称：请求加一与响应保持。验证层级：UT。

测试点反标：DEMO.001.001＋请求接受后的加1及回绕；DEMO.002.001＋响应反压期间保持。

准备与输入：

1. req_data（请求数据）由TB驱动，选8'h00、8'h7f、8'hff，分别观察正常加1和回绕，覆盖DEMO.001.001。
2. req_valid（请求有效）来自TB，保持至req_ready（DUT请求就绪）为1的采样边沿，确保请求真实接受。
3. rsp_ready（响应接收就绪）由TB先拉低3个响应周期，再拉高，以触发DEMO.002.001的保持场景。
4. rsp_valid/rsp_data（响应有效/数据）来自DUT，由monitor在统一采样时刻记录；不从driver意图推断结果。

预期结果：分别得到8'h01、8'h80、8'h00；每请求恰好一个响应，反压期间valid为1且数据稳定；完成后无残留事务。执行结果：未执行。
