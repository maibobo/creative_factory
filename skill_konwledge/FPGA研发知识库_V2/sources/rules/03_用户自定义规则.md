# 用户自定义厂商风格 RTL 规则

版本：由 `config/custom_rules.json` 的 `document_version` 管理  
适用语言：ASIC Verilog RTL

本文件是四条用户规则的可读版本。随包 `config/custom_rules.json` 保存原规则定义快照；本文件保留要求、例外和示例。规则变更需同时核对正文、配置与检查表。

规则解释原则：

- 用户规则高于本规范包引用的历史资料。
- “一个 always 一个信号”按左值根对象计算，而不是按右值引用数量计算。
- 例外不是自动许可。作者必须证明满足所列条件，评审者必须显式确认。
- 本文件不新增文件头或一般注释排版要求。


## CUSTOM-RTL-001：一个 always 块默认只驱动一个信号 [M1]

**适用范围：** ASIC Verilog RTL 的时序和组合过程块

**规则：** 一个 always 块默认只能包含一个左值根对象，尤其是时序逻辑。同一向量的整体验证、位选和部分选择均归属于同一个左值根对象。

**理由：** 限制过程块职责，降低多目标赋值遗漏、局部修改连带影响以及综合后追踪困难。

**定义：**

- 左值根对象指去除位选、部分选择和拼接包装后实际被写入的变量。
- 敏感列表中的信号和赋值右侧引用的信号不计入驱动目标数量。
- 拼接左值中包含两个不同变量时，按两个左值根对象计算。

**允许的例外：**

- 多个目标的复位条件、时钟、主要使能以及 if/case 分支结构完全相同或大部分相同，拆分会产生重复且更难维护的控制结构。
- 状态机存在较多紧密相关寄存器，按 state 集中观察其更新关系明显优于按信号拆分。

**例外成立的附加条件：**

- 不得跨时钟域、跨复位域或混合独立生命周期的寄存器。
- 必须在 always 块前添加语义段注释，说明合并对象、共同控制条件以及不拆分的原因。
- 代码评审必须把该例外作为显式检查项；不能仅以减少代码行数作为理由。

**符合示例：**

```verilog
// 响应状态组：两个寄存器共享复位、使能和完整状态分支，
// 集中描述用于按 state 检查握手行为。
always @(posedge clk or negedge rst_n) begin
    if (!rst_n) begin
        rsp_valid <= 1'b0;
        rsp_data  <= 8'b0;
    end else begin
        case (curr_st)
            ST_RESP: begin
                rsp_valid <= 1'b1;
                rsp_data  <= result_data;
            end
            default: begin
                rsp_valid <= 1'b0;
                rsp_data  <= rsp_data;
            end
        endcase
    end
end
```

**不符合示例：**

```verilog
always @(posedge clk or negedge rst_n) begin
    if (!rst_n) begin
        req_count <= 8'b0;
        timeout   <= 1'b0;
    end else begin
        if (req_fire) req_count <= req_count + 1'b1;
        if (timer_expired) timeout <= 1'b1;
    end
end
```

**评审提示：** 统计每个 always 块的左值根对象；超过一个时检查是否满足例外条件及是否有语义说明。

## CUSTOM-RTL-002：wire 声明与驱动分离 [M1]

**适用范围：** ASIC Verilog RTL 的网络和组合逻辑

**规则：** wire 变量不得在声明时赋值。连续赋值必须分成 wire 声明和 assign 语句；由 always @(*) 驱动的目标必须声明为 reg。

**理由：** 显式区分声明、连续驱动和过程驱动，便于检查单一驱动源并避免不同工具对声明赋值语义的误解。

**定义：**

- wire 只能由模块端口、实例输出或连续赋值等网络驱动源驱动。
- reg 仅表示过程赋值目标，不等同于一定综合为触发器。

**允许的例外：**

- 不允许例外。

**例外成立的附加条件：**

- 不适用。

**符合示例：**

```verilog
wire req_fire;
assign req_fire = req_valid & req_ready;

reg grant;
always @(*) begin
    grant = 1'b0;
    if (request) begin
        grant = enable;
    end
end
```

**不符合示例：**

```verilog
wire req_fire = req_valid & req_ready;

wire grant;
always @(*) begin
    grant = request & enable;
end
```

**评审提示：** 搜索含等号的 wire 声明，并核对每个过程赋值目标是否声明为 reg、每个对象是否只有一个驱动源。

## CUSTOM-RTL-003：常用功能必须例化批准的成品单元 [M1]

**适用范围：** ASIC RTL、CDC、时钟、存储器及 FPGA 原型适配层

**规则：** FIFO、单比特或复位同步器、DMUX、ICG、存储器宏及项目指定算术 IP 等常用功能，必须例化 approved_cells.json 中状态为 approved 的单元、IP 或统一包装器，不得在业务 RTL 中自行重写。

**理由：** 复用已经验证并纳入时序、CDC、DFT、功耗和签核流程的实现，避免相同功能出现多个不一致版本。

**定义：**

- 成品单元可以是标准单元、项目公共 RTL、第三方 IP 或统一封装模块。
- 批准状态、适用工艺和允许使用的设计配置以 approved_cells.json 为准。

**允许的例外：**

- 仅 FPGA 原型配置允许在平台包装层内使用目标 Vivado 版本支持的 XPM；XPM 不得进入 ASIC 签核文件表。
- 登记表尚未补齐时，相关设计必须保持待决，不得自行假定模块名或以临时代码替代后直接签核。

**例外成立的附加条件：**

- 所有技术相关实现必须封装在明确的平台或工艺适配层。
- 新增或替换单元必须经过项目评审并更新 approved_cells.json 的版本、负责人和证据字段。

**符合示例：**

```verilog
// 单比特 CDC：源端信号已寄存且无组合毛刺，
// <APPROVED_BIT_SYNC> 必须替换为登记表中的真实批准包装器。
<APPROVED_BIT_SYNC> U_<APPROVED_BIT_SYNC> (
    .clk_dst  (clk_dst),
    .rst_dst_n(rst_dst_n),
    .data_src (status_src),
    .data_dst (status_dst)
);
```

**不符合示例：**

```verilog
reg status_ff1;
reg status_ff2;
always @(posedge clk_dst or negedge rst_dst_n) begin
    if (!rst_dst_n) begin
        status_ff1 <= 1'b0;
        status_ff2 <= 1'b0;
    end else begin
        status_ff1 <= status_src;
        status_ff2 <= status_ff1;
    end
end
```

**评审提示：** 识别 FIFO、CDC、DMUX、门控时钟、RAM 和算术结构，核对实例是否来自批准登记表及对应配置。

## CUSTOM-RTL-004：按语义段添加注释 [M2]

**适用范围：** ASIC Verilog RTL；不包含文件头模板和一般排版规则

**规则：** 注释必须围绕一个完整语义段，说明功能意图、时序关系、协议约束、状态转换或规则例外，不得仅逐行复述语句。

**理由：** 让评审者先理解设计约束和不变量，再阅读实现细节；同时避免高密度低信息量注释。

**定义：**

- 语义段可以是一个组合判定、寄存器更新、状态转换、协议握手、CDC 边界或标准单元实例组。
- 注释语言可按项目约定使用中文或英文，本规范不规定固定比例和文件头格式。

**允许的例外：**

- 名称和结构已完整表达含义的简单直连可以不增加注释。

**例外成立的附加条件：**

- 任何自定义规则例外、非显然时序关系、CDC 假设和协议限制仍必须说明。

**符合示例：**

```verilog
// 请求接受条件：只有队列可写且下游未暂停时才完成握手；
// req_fire 是计数器、地址推进和写使能的共同事件。
wire req_fire;
assign req_fire = req_valid & req_ready;
```

**不符合示例：**

```verilog
// req_valid 和 req_ready 相与
wire req_fire;
assign req_fire = req_valid & req_ready;
```

**评审提示：** 按功能段检查是否交代意图、边界或假设；删除只翻译代码表面的低信息注释。
