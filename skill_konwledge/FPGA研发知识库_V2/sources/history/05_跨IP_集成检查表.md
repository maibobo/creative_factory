# 跨 IP 集成检查表

本页用于 Aurora、PCIe/XDMA、DDR/MIG 和以太网数据通路联调。每项应绑定 RTL 位置、测试用例和日志证据；“接口已连接”不等于“功能已通过”。

## 1. 先固定接口契约

| 项目 | 必须写清 |
|---|---|
| 数据方向 | 站在谁的视角命名 TX/RX、H2C/C2H、读/写；不要只看历史端口名 |
| 拍宽与尾包 | 数据宽度、字节序、`keep/rem` 含义、SOF/EOF/TLAST 规则 |
| 握手 | 哪一侧可反压；反压期间哪些信号必须稳定；无 ready 的入口怎样吸收 |
| 地址 | 基地址、窗口、对齐、长度单位、4 KB 边界、最大 BTT、是否允许回绕 |
| 描述符 | 字段位宽、发布顺序、有效位、错误状态、生产者/消费者指针 |
| 完成语义 | 数据已进入 FIFO、AXI response 完成、DMA descriptor 完成、软件可见或中断确认分别代表什么 |

## 2. 时钟、复位与 CDC

- 为每个接口列出源时钟、目标时钟、复位极性、同步/异步释放方式。
- 多 bit 数据走异步 FIFO 或握手保持；单 bit 电平走两级同步；脉冲走 toggle/ack/计数，不直接跨域。
- 配置寄存器跨域时定义“何时生效”，避免一帧或一次 DMA 中途改变阈值、地址或长度。
- sticky 状态清除必须考虑旧 CDC 电平重触发；用 clear handshake 或源域确认。
- MIG 业务复位等 `ui_clk_sync_rst=0 && init_calib_complete=1` 后再释放。
- Aurora 业务等 `channel_up=1`；GT/PMA reset 与协议 reset 分开。

时钟值必须绑定具体层级：Aurora 64B/66B 10.3125G 的 64-bit 用户时钟约 161.1328 MHz；125 MHz 可是 RGMII/系统时钟；PCIe 大仿真中的 156.25 MHz LocalLink BFM 不能直接替代真实 Aurora Core 的用户时钟结论。

## 3. 缓冲与反压预算

- Aurora RX 和线速以太网入口不能假定能暂停远端发送；在第一个可控边界前计算最坏突发并留 FIFO 裕量。
- 对每级 FIFO 同时检查 data 和 descriptor 容量，定义 `full/prog_full/almost_full` 的提前量。
- 数据和描述符要么一起提交，要么一起丢弃/排空。异常描述符不能只弹描述符而留下旧数据。
- 目标通道拥塞采用阻塞还是静默丢弃必须显式选择；若丢弃，统计要能区分接收侧和路由侧。
- 固定优先级仲裁要验证饥饿；必要时改为轮询、配额或 aging。

## 4. DMA 与内存一致性

1. AXI AW/W 独立握手，`VALID` 保持到 `READY`；读写 response 必须检查。
2. AXI burst 不跨 4 KB 边界；非整拍尾包要检查 strobe/keep/rem 和实际 BTT。
3. 内存发布顺序采用“先 payload、后 descriptor、最后推进 producer pointer”。
4. DMA 状态、AXI response 和 Host/软件实际可见数据是三层不同证据，不能互相替代。
5. 环指针同时包含 index 和 wrap；满/空判定、运行时深度、地址乘法和回绕都要做边界测试。
6. 定义缓存维护和内存屏障。FPGA 写 DDR/Host 后，软件看到 producer pointer 之前必须保证 payload 和 descriptor 可见。
7. 命令、数据、状态和中断都设置超时；超时后的 abort/recover 不能推进未完成条目的指针。

## 5. 中断与状态

- 区分请求、IP 接收/发送确认、PCIe MSI 发出、操作系统 ISR 到达和软件处理完成。
- 电平中断可能合并多帧；软件应以环指针或计数器排空，不按一次中断只处理一帧。
- read-to-clear、write-one-to-clear 和 ACK 优先级要覆盖“清除与新事件同拍”的用例。
- 错误状态应 sticky，另提供单周期 pulse 或计数；清错误不能悄悄中止正在进行的事务。

## 6. 分层验收

| 层级 | 最低证据 |
|---|---|
| 静态审计 | XCI/参数、端口方向、时钟、复位、约束和源文件哈希 |
| 模块仿真 | 正常、反压、边界长度、故障注入；断言和逐字节 scoreboard |
| 集成仿真 | 真实产品模块跨 IP 闭环；每级独立里程碑和错误计数 |
| IP/PHY 模型 | MIG/Aurora/PCIe 官方模型覆盖各自的初始化和协议边界 |
| 实现 | 综合、实现、DRC、STA，且无未解释的 critical warning |
| 板卡/软件 | 链路、数据、带宽、长稳、温度/电压、驱动 ISR、缓存一致性和恢复 |

最终报告应逐层标注“已通过、已实现、待验证、设计边界”。不要把行为模型通过升级为 PHY/板卡通过，也不要把 `channel_up`、`init_calib_complete` 或 DMA status 单独当成端到端数据正确的证据。
