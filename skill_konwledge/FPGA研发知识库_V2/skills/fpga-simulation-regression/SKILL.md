# 验证代码、仿真与回归

依已确认测试点、用例和方案选择规模：简单模块基本TB，可选SV；小型轻量SV；复杂或大型完整SV，已有UVM或明确需求时用轻量UVM。完整SV推荐tb_top、interface、test/激励、driver/BFM、monitor、RM、checker/scoreboard、coverage及env/config，按需取用。

验证代码反标测试点，围绕对应功能组织激励与检查，并采用有界超时和明确完成条件。编写仿真入口及每日回归脚本，按表行顺序跑，不分P0/P1/P2。单例失败保存日志、输入和Seed并继续；编译或环境失效时停止。

定位根因，修复后复测并回归；需改变已确认功能或判据时返回对应阶段确认。功能验证基本完成后开展implement及时序收敛，相关修改补做回归，提前评估为可选。

据真实结果回填测试表、写仿真报告，未执行项标明待执行，提交最终人工确认。

按当前功能与配置，从[阶段知识入口](../../knowledge/stages/04_验证代码仿真与回归.md)读取相关主题，必要时回查随包来源与示例。
