# 质量门定义

## 统一状态

| 状态 | 含义 |
|---|---|
| `NOT_RUN` | 尚未执行 |
| `IMPLEMENTED` | 文件或代码已生成，但未证明运行正确 |
| `TOOL_VERIFIED` | 工具已执行并产生可复核证据 |
| `PASS` | 满足该门全部准入条件 |
| `PASS_WITH_RISK` | 主要条件满足，但有已批准风险 |
| `FAIL` | 已发现未接受的问题 |
| `BLOCKED` | 因输入、环境或依赖缺失无法判断 |
| `NEEDS_SIMULATION` | 静态阶段无法关闭，必须仿真验证 |
| `NEEDS_IMPLEMENTATION` | 必须综合/实现后才能判断 |
| `N/A` | 经批准确认不适用 |

`FIXED` 只表示代码或配置已修改，不能替代 `VERIFIED`。`IMPLEMENTED` 不能替代 `PASS`。

## G0 项目入项与环境基线

**入口：** 原始需求、已有工程或源文件、目标器件和预期交付物。

**必须检查：** 项目模式、顶层、器件、Vivado/Vitis 版本、语言、仿真器、License、源文件清单、IP/约束依赖、输出目录。

**出口：** `project_manifest.yaml` 已填写；关键环境项可发现；缺失项已标记 `BLOCKED`。

## G1 需求与设计方案基线

**必须包含：** 功能边界、系统位置、接口、时钟复位、数据格式、缓存、FSM、寄存器/IP、异常、性能和验收条件。

**出口：** 设计方案获得确认；所有关键 TBD 有责任人；形成 `DESIGN_BASELINE`。

## G2 RTL 实现完成

**必须检查：** RTL 文件、模块树、接口、Clock/Reset Map、CDC 结构、FIFO/Memory、IP 配置、约束和设计偏差。

**出口：** RTL 可交给工具解析；无未披露的关键假设；生成 `RTL_CANDIDATE`、变更记录和开放问题清单。

## G3 静态工具验证

**必须执行或明确豁免：** Compile/Elaboration、Vivado RTL Lint、CDC/RDC、必要的 DRC 和接口检查。

**出口：** Critical/Major 问题已关闭或批准接受；报告、版本、命令和原始日志已保存。

## G4 RTL Review / Stable RTL

**审查范围：** 设计一致性、模块职责、接口、时钟复位、CDC/RDC、FSM、位宽算术、Ready/Valid、FIFO/Memory、IP、寄存器、异常、Timing/Resource 风险。

**出口：** Review 结论为 `PASS` 或 `PASS_WITH_RISK`；所有问题有 ID、严重等级、证据、责任人和状态；发布 `RTL_STABLE`。

## G5 仿真验证方案

**必须定义：** P0 主链路、P1 定向/异常/边界、P2 随机回归；每个 Test ID 的激励、Expected、Checker、Timeout、通过条件和覆盖目标。

**出口：** 设计项和 RTL 风险均映射到测试项；验证计划可直接指导 G6；真实结果字段保持空白。

## G6 Testbench 实现

**必须生成：** TB、DUT 实例、Clock/Reset、激励、Expected/参考模型、Checker、Timeout、PASS/FAIL、Seed 说明和 Test ID 映射。

**出口：** 适用 Test ID 均为 `IMPLEMENTED` 或明确 `BLOCKED/N/A`；编译入口、外部依赖和运行方式已说明。此时仍不能声称仿真 PASS。

## G7 仿真执行与回归

**必须检查：** 编译、Elaboration、运行终止、显式 PASS 条件、失败 Test、Assertion、Coverage、Seed、日志和波形。

**出口：** P0/P1/P2 按项目准入条件通过，或形成带证据的 `FAIL/BLOCKED/PASS_WITH_RISK`；失败必须分类为 design、testbench、environment、timeout 或 tool defect。

## G8 综合、实现与时序

**必须检查：** 综合状态、资源、时钟、约束、Timing Summary、Methodology、DRC、关键路径、WNS/TNS、利用率和实现版本。

**出口：** 时序和方法学满足项目门限，或风险经过批准；不得以零延迟仿真结果替代时序证据。

## G9 硬件调试

**必须检查：** bitstream/PDI 版本、板卡和配置链路、时钟复位、ILA/VIO 观测点、触发条件、采集结果和问题复现性。

**出口：** 关键上板场景有可复核采集证据；仿真、实现和硬件版本一致。

## G10 发布与交付

**必须包含：** 版本标签、源文件清单、IP/约束、构建脚本、工具版本、报告、证据、已知风险、变更记录和重建说明。

**出口：** 干净目录或独立环境可以重建工程；交付包与 `project_manifest.yaml` 一致。
