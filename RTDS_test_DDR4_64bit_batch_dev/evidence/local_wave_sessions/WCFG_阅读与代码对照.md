# WCFG 里是什么，怎样结合代码看

ring、axi、regs 三组的逐时间窗信号跳变、握手判据、读回检查和代码关联见 [WCFG_ring_axi_regs_观察链与时间刻度.md](WCFG_ring_axi_regs_观察链与时间刻度.md)。

## 先回答“够不够看”

对这七组**模块级测试**，接口和可追踪内部信号已列全，足以沿输入、内部状态、输出和检查器定位问题。2480 个可显示对象与 WDB 逐项核对，没有无法解释的漏项。

但“信号列全”不等于“所有系统场景已验证”。这七组不是一个完整系统连续运行的七段波形：有些上下游由测试台模拟，axi 与 axi_tail 也是同一 CONV_DMA 的不同场景。它们不能单独证明 PCIe、DDR、Aurora 实际物理链路或整机长时间交互正常。是否覆盖新问题，还取决于测试台有没有施加对应激励。

## WDB、VCD、WCFG 的分工

- **WDB**：Vivado 的波形数据库，保存本次记录。需要看数组元素时使用它。
- **VCD**：用于离线分析的变化记录，也是三栏查看器的波形数据来源。
- **WCFG**：Vivado 的显示配置，定义显示哪些信号、排列分组和显示进制。它本身不生成波形，也不会补录未记录的信号。
- **HTML 查看器**：将 VCD 与当时的源码一起放入一个本地文件，不随以后磁盘上的 RTL 修改而改变。

三栏查看器包含 WCFG 的全部唯一对象，但去掉了分组之间重复显示的同名行。17 个 unpacked array 不在 VCD 中，因此在 HTML 明确标为“仅WDB数组”，用启动命令的 `-Vivado` 模式展开。XSim 明确不支持的 53 个自动局部变量或动态对象见每组 `unsupported_objects.txt`；不包含漏掉的硬件端口。

## 四个分组应该怎么看

| WCFG 分组 | 内容 | 用途 | 建议 |
|---|---|---|---|
| 01_TESTBENCH | 时钟、激励控制、参考值、统计计数 | 确认测试台正在做什么，期望是什么 | 看用例开始、结束和错误注入 |
| 02_INTERFACE | bus 下完整输入输出接口 | 对照相邻模块之间实际传递的数据和握手 | **先看这一组** |
| 03_DUT | DUT 全部直接端口、内部状态和组合条件 | 解释为何接受、停顿、完成或报错 | 接口出现疑问时往这里追 |
| 04_ALL_HIERARCHY | 全部可显示内部层次，含 CDC、XPM、RAM、clocking block 别名 | 定位更深的跨时钟/FIFO/存储问题 | 日常不必逐行阅读 |

01～03 的对象在 04 中可能再次出现，这是不同阅读入口，并非发生了两次传输。测试接口的 clocking block 还可能产生带 `_in` 的采样别名，它们是测试台采样视角，不是新增的硬件通道。

新版 HTML 默认使用“业务信号”视图，隐藏标准CDC/复位同步/XPM实例内部和clocking block别名；保留父DUT连接信号及自定义逻辑。可切换“全部信号 / 测试台 / 接口 bus / DUT端口/状态”。默认简名只显示最后的信号名，全称显示完整路径；同名信号仍是独立对象，悬停和底部可区分。标准模块父信号的“连接”按钮会跳到实例端口连接行，多次点击循环连接点。

## 七组各自负责哪一段

| 组 | 观察链条 | 重点信号或信号族 | 能回答的问题 |
|---|---|---|---|
| 1g | 配置输入 → CDC → 周期发出 | cfg_byte/cfg_byte_valid、cfg_req/cfg_ack、cfg_user、configured、tx_*、skipped_periods | 配置是否到达目的时钟域，发送是否被反压或错过周期 |
| tx | FDMA 取数 → 异步 FIFO → 10G 用户接口 | raddr/rareq/rvalid/rready、limit、fifo_wr_cnt、fifo_almost_full、valid/ready、sof/eof、received | 是没取到数据、FIFO 满暂停，还是下游 ready 不允许发送 |
| rx_fifo | 10G 用户输入 → FIFO → 存储域输出 | rx_*、frame_*、fifo_full、dropped_frames、length_error | 是否按序跨域，拥塞时是否丢失并计数 |
| ring | 低32bit拼接 → FDMA写 → 发布块 → CPU确认 | half_*、fdma_w*、used_bytes、seal/push/pop 条件、head_*、ready_blocks、irq/cpu_ack | 是否成功写后才发布，尾字节是否正确，队列满时是否保护旧块 |
| axi | FDMA请求 → AXI五通道 → 响应完成 | fdma_*、M_AXI_AW* / W* / B* / AR* / R*、allow_aw/allow_w/allow_b | 地址/长度拆分是否正确，各通道停顿后是否保持和完成 |
| axi_tail | 同地址FF全写 → 0F部分写 → 读回 | fdma_wstrb、M_AXI_WSTRB、M_AXI_WDATA、M_AXI_RDATA | 只写低四字节后，高四字节是否保持 |
| regs | CPU AXI-Lite写 → 内部命令 → 状态读回 | aw*/w*/b*/ar*/r*、CPU_WR_DONE、start/done、ack、starts/acks | 重复提交是否被抑制，完成是否清零，WSTRB是否正确过滤 |

`*` 表示一组实际端口名称，不表示文件中存在一个带星号的信号。全部精确名称和变化统计见各组 `signals.csv`、`signals_summary.md`。

## 最有效的代码对照顺序

1. **先读测试台**：在文件下拉列表选 `tb_rtds_<case>.sv`，找 initial、调用任务和 `$fatal` 检查。先确定当前区间是复位、正常发送、反压、满队还是错误注入。
2. **再看接口**：筛选“接口 bus”，观察时钟与复位，再找 valid/ready、地址、数据、长度和完成信号。只有对应时钟边沿的握手才算传输；总线保持一个数值并不代表重复发送。
3. **点击有疑问的信号**：右侧先定位该标识符的代码出现位置，通常是端口/声明。点击“查找下一处”继续找 `assign`、`always` 中的条件与赋值，再关联状态变量。**黄色行是静态源码定位，不是仿真执行断点或逐周期运行到的行。**
4. **放大变化前后**：点击“上一变化 / 下一变化”，自动在所选信号的变化点附近显示不超过 200ns 的区间；需要更长的 CDC 或周期过程时再缩小。比较变化前的输入条件和变化后的寄存器/输出，注意时钟域和非阻塞赋值时序。
5. **最后回到检查器**：比较 received、计分板判断和 PASS/失败信息。波形用来解释过程，测试台检查用来核对数据及预期。

例如 tx：先看 `ready=0` 时 `valid` 与数据是否保持，再看 `fifo_wr_cnt` 是否达到 504、`fifo_almost_full` 是否阻止继续取数；随后观察 ready 恢复后水位下降、FDMA 补读、received 增加。代码中依次找对应 ready 判断、FIFO 阈值条件、读取状态机和发送状态机。这比从所有 XPM 内部信号逐个看更容易定位原因。

## 栏宽、显隐与滚动

顶部勾选信号、波形、代码，可任选一栏、两栏或三栏。默认宽度22%/48%/30%，分隔条宽6像素；拖动可将某栏收窄到24像素，完全隐藏则取消勾选。说明文字全部收在“操作说明”内。各区右侧有加宽竖向滚动条，可直接拖动。鼠标放在哪个区域，滚轮就只滚动该区域。信号名与波形必须同步滚动，避免同一行错位；代码独立滚动。

Ctrl+波形区滚轮用于时间缩放，拖动波形用于时间平移。同一信号上移动时间光标不再把代码重置到声明行；切换信号时才自动定位，或手动点“信号定位”。源码字体已放大。

七组入口和运行路径见 [README.md](README.md)。已经打开的旧窗口需刷新或重新打开，才能使用新版界面。此轮只更新查看器和说明，仿真记录与 RTL 未改变。
