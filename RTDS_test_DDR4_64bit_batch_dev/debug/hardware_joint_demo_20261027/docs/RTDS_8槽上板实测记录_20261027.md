# RTDS 主机 8 槽板内联动实测记录

日期：2026-10-27，远程 Windows 时间 14:52–14:55。运行编号 `20261027_145225_fec56b93`。实验使用 ARM `192.168.50.10`、主机 FPGA 和 DDR；上行数据由 VIO 固定源产生，真实 Aurora 和子机没有参与。

## 1. 结果

| 项目 | 本次结果 | 判断依据 |
|---|---|---|
| 环境、寄存器 | PASS | 端点 `0000:01:00.0` 绑定 XDMA；`VERSION=0x2001`、`DDR_STATUS=0x3`，初始和最终队列与丢字均为 0。 |
| DDR 16 Byte 往返 | PASS | 卡端 `0x8000` 的 H2C/C2H 请求及完成均为 16 Byte，读回 `000102030405060708090a0b0c0d0e0f`，逐字节一致。 |
| 8 块慢速 | PASS | 队列 `0→1→…→8→7→…→0`；8 个槽逐个写入、读取并归还，每个确认状态停留约 2 秒。 |
| 8 块连续 | PASS | 无人为演示停留，8 块依次写入、读取并归还；仍受 VIO/JTAG 和控制开销影响，不是性能测试。 |
| 结束状态 | 正常 | `0x2C=3`、`0x30=0`、`0x38=0`；PCIe `COMMAND=0x0006`，BAR0=`0xF0200000`，BAR1=`0xF0300000`。 |

开始前，Linux 原先保存了设备和驱动信息，但实际 `COMMAND/BAR0/BAR1=0`，版本读取为 `0xFFFFFFFF`。无人占用 XDMA 节点时，只对 FPGA 端点执行一次移除和父桥重扫，寄存器访问恢复；没有重启 CPU，也没有重新下载 FPGA。恢复前后原始证据见原实验包 `validation/recovery_20261027_144120.json`。

实测 PCIe 链路为 **2.5 GT/s ×2**；低于端点声明的 8 GT/s 能力，是后续速率/训练排查项，不能据此次小数据量通过推断性能达标。

## 3. ILA/VIO 怎么看

- 共保存 **18 组 ILA/CSV**：DDR 往返 ILA1 两组、8 槽写入 ILA2 八组、8 槽读取 ILA1 八组。连续轮没有逐块重新采集 ILA；其逐块数据和 ACK 记录在实验结果中。
- DDR 写波形有一次 `AW` 握手，地址 `0x8000`；两次 64 bit `W` 握手，`WSTRB=FF`、末拍 `WLAST=1`、`BRESP=0`。读波形一次 `AR`、两次 `R` 握手，末拍 `RLAST=1`、`RRESP=0`。
- 8 组 ILA2 的 `fdma_wareq` 地址依次与上表一致，`fdma_w_source_valid` 期间数据为 `0x0000002200000011`，采到的 `adapter_rx_state_dbg` 覆盖 0、1、2、3。`source_valid` 持续多个采样拍不能独自当作多次成功写入。
- 8 组 ILA1 的 `AR` 地址与上表一致；每组两次有效 `R` 握手，首拍数据为 `0x0000002200000011`，`RRESP=0`、末拍 `RLAST=1`。第二个 64 bit 拍属于 16 Byte 对齐读取中的非有效尾部，不作为 8 Byte 业务数据判据。
- 所有 10 组 ILA1 的 `ila_errors` 采样值均为 0。数据握手判读以 VALID 和 READY 同时为 1 为准；ILA1 捕获的是 DMA AXI，不直接展示 `0x14` 等 BAR 寄存器写事务。
- Vivado 的 VIO 实例以路径识别：`u_pcie/G_RX_VIO.U_VIO_RX_START` 看 `rx_test_start`、`rx_test_accepted_r` 和 `rx_test_blocks_r`；`u_pcie/U_PCIE_LINK_DEBUG/vio` 看 link、DDR 和历史计数。此次出现的状态数值 `11` 为十进制 `0xB`，含就绪及通知位；不要误读为十六进制 `0x11`。

ILA 需先布防并在指定条件触发后上传，显示的是有限采样波形；VIO 和 Linux 状态读取分别刷新，也不是同一时刻的原子快照。回看本次结果时，在 Vivado 的波形标签或数据窗口中选择对应时间的 `gui_fdma_*.ila`、`gui_native_*.ila`；可使用随附 CSV 和下方 JSON 对照地址和数据。
