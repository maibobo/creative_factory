## 2. 失序路径根因

### 2.1 MIG 300MHz 到主逻辑 250MHz：-2.714ns

最差路径从 MIG 的 `calDone_gated_reg_replica` 到 `INFO_EXCH.axi_rdata_reg[1]`。原代码把 `mig_calib_complete` 直接输出给 250MHz 寄存器读取，因此 Vivado 按两个独立 MMCM 的边沿关系给出仅 0.667ns 的 setup 要求。这既造成时序失败，也是不安全的单比特跨时钟。

第二条 -2.712ns 路径从 `ui_reset_pipe_reg[1]` 到 `ready_sync_reg[0]`。`ready_sync[0]` 本来就是两级同步器首级，亚稳态由后一级吸收；原工程缺少同步器属性和只针对首级 D 端的异步路径例外，所以工具错误地要求首级满足普通同步 setup。

修复：

1. 给 `ready_sync` 增加 `ASYNC_REG=TRUE` 和 `SHREG_EXTRACT=NO`，禁止综合器把两级同步器合并成移位结构，并帮助布局器邻近放置。
2. `init_calib_complete` 改用 `ready_sync[1]`，不再将 MIG 原始校准状态直接送入 250MHz 域。
3. 在当前工程实际启用的 `DDR4_PIN.xdc` 中，只对 `ready_sync_reg[0]/D` 设置 `set_false_path`。第二级和其他跨域路径仍正常检查；AXI Clock Converter 的内部 CDC 继续使用 IP 自带约束。

没有使用 MIG 与 250MHz 两个时钟的全局 `set_clock_groups`，避免误屏蔽未来新增且未同步的跨域路径。

### 2.2 SYSMON 到 AXI 读寄存器：-0.759ns

温度数据原先从 `SYSMONE1.DO` 直接穿过寄存器地址译码到 `INFO_EXCH.axi_rdata_reg`，数据路径 4.131ns，其中布线 3.505ns。修复是在 `TOP.v` 中用 250MHz 时钟增加一级 `fpga_temp_status` 寄存器。软件看到温度和 busy 状态最多晚一个 4ns 周期，编码和寄存器地址不变。

### 2.3 FDMA 超时计数器：约 -0.084ns

原路径从 AXI Clock Converter 的写通道反压信号，经 AXI Interconnect、CONV_DMA 和 TX bridge 的组合逻辑，直接到 32 位 `fdma_wait_count` 的时钟使能。路径包含 9 级逻辑，且布线占主要部分。

修复是在 adapter 内把 `fdma_waiting` 和 `fdma_progress` 先寄存为同一拍快照，再驱动超时计数器和 sticky 状态。数据通路、FDMA 握手、地址及长度不变。超时阈值为 65535 拍，修复仅使超时报告最多晚一个 250MHz 周期（4ns）。

### 2.4 PCIe 参考时钟未覆盖顶层

旧报告含 16760 个 `no_clock` 寄存器和 48001 个未约束内部端点，根时钟指向 `pcie_diff_clk_p[0]`。BD 的 `design_1_ooc.xdc` 只对 BD 端口名 `pcie_diff_clock_clk_p` 建钟，未覆盖顶层端口。

修复是在实际启用的 `DDR4_PIN.xdc` 中对顶层 `pcie_diff_clk_p[0]` 显式创建 10ns（100MHz）参考时钟。新实现后必须复核 `check_timing`；若端点数量没有消失，应继续核对 XDMA 生成时钟传播，不能用宽泛 false path 掩盖。

## 3. DDR4 2400MT/s 风险判断

报告识别到三组 `pll_clk[*] = 2400MHz` 和对应的 `pll_clk[*]_DIV = 300MHz`。2400MHz 物理侧主要由 MIG 的专用 I/O、PHY 和生成约束处理，旧报告没有显示这些 2400MHz 时钟的 setup/hold 失败；脉宽检查也通过。

当前与 DDR 速率直接相关的剩余风险是 MIG 内部 300MHz 控制逻辑 -0.068ns，而不是 2400MHz 数据采样路径。其最差路径位于 MIG 的仲裁/校准读使能逻辑，路由占 79.2%。重新综合和实现会改变布局，可能自然收敛；若仍为小幅负裕量，按以下顺序处理：

1. 先确认本轮 CDC、温度流水和 PCIe 顶层时钟修复后的标准 GUI 实现结果。
2. 若只剩 MIG 内部小幅负裕量，使用 Vivado 的 performance explore / post-route physical optimization 策略重跑实现。
3. 比较多个实现 seed，选择满足 setup/hold 且 DRC 干净的结果。
4. 不修改 MIG 生成 RTL，不对 MIG 内部真实同步路径增加 false path。
5. 上板前仍需完成 MIG 校准、持续读写压力和温度/电压角落测试；静态时序通过不能代替板级 2400MT/s 可靠性验证。
