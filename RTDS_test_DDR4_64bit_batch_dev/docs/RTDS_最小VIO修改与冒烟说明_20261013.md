## 修改与功能边界

- 新增 `rtl/rtds_rx_vio_stim.v`：250MHz 同域固定数据发生器，start 上升沿触发一次；控制、周期事件、完成事件先寄存；数据与 valid 由寄存器输出。反压时保持数据；忙期间的触发忽略。
- `TOP.v`、`PCIe.v`、adapter 传递 `RX_VIO_TEST_ENABLE`，RTL 默认值为 0；当前工程 sources_1 的 generic 已设为 1，方便本次手动生成测试 bit。参数 0 保留原 FIFO 输入；参数 1 编译选择固定测试源，上行不再来自 Aurora。下行和 BAR 寄存器协议保持。
- writer 仅增加两个观察输出：原周期到期事件、原成功非空块登记事件；未修改计数、DDR 写入、尾字处理、块容量、队列和确认规则。
- 新增官方 `vio_rtds_rx_start` IP，只有一个 1bit 控制输出，默认值 0。观察量另寄存一拍后送 VIO，减少业务信号扇出。IP 采用全局综合方式，当前只生成输出文件，未运行 IP 综合。
- 触发要求原 DDR/PCIe 存储条件满足且待取块数小于 8。两拍在原周期结束后开始，保留生产周期 25,000,000 拍。触发至块完成约需 100～200ms 加剩余写响应时间。
- 中途失去就绪或收到失败写响应时停止，fault 保持到全局复位，避免残留半字与新激励混合。发生器接受两拍后仍保持 busy，直到原 writer 真正登记成功块。
- 数据依次为 `64'h00000000_00000011`、`64'h00000000_00000022`；writer 只取每拍低 32bit，写成 `64'h00000022_00000011`。单块有效长度 8Byte，小端读取为 `11 00 00 00 22 00 00 00`。

## 手动综合、实现和操作

远程原 GUI 仍可能保留旧工程内存。先重新打开 `RTDS_test_DDR4_64bit.xpr`，确认 Sources 有 `rtds_rx_vio_stim.v`、IP 有 `vio_rtds_rx_start`，工程 generic 为 `RX_VIO_TEST_ENABLE=1`，再手动综合、实现和生成 bit。

如果需要在当前 GUI 重新登记，可在 Tcl Console 执行：

```tcl
source C:/project/RTDS/DDR/RTDS_test_DDR4_64bit_batch_dev/scripts/register_rx_vio_20261013.tcl
```

此脚本只登记文件、设置本次测试 generic、生成 VIO IP 输出文件，不启动综合或实现。恢复正式上行时，将 `RX_VIO_TEST_ENABLE` 设为 0 后重新生成 bit；不要把本次测试源当作 Aurora 接收功能。

生成并下载同一版 bit/ltx 后，在 Hardware Manager 找到 `u_pcie/G_RX_VIO.U_VIO_RX_START`。VIO 探针含义如下：

| 探针 | 位宽 | 含义 |
|---|---:|---|
| probe_out0 | 1 | start；先提交 0，再提交 1，保持 1 不重复 |
| probe_in0 | 1 | busy；包含等待周期、两拍发送、等待块完成 |
| probe_in1 | 2 | 本次已接受的32bit字数，0、1、2；2不代表DDR已经成功 |
| probe_in2 | 4 | bit0 DDR就绪、bit1 PCIe就绪、bit2 fault、bit3 上行通知请求 |
| probe_in3 | 4 | 当前可读块数，0～8 |

先确认 probe_in2 的 bit0、bit1 均为 1、fault 为 0。在原 FDMA ILA 以 `fdma_wareq=1` 等待触发，再提交 start 的 0→1。看到一次写请求，`fdma_wsize=1`、数据为 `00000022_00000011`。随后软件按原 5.3 流程检查 `0x30`、`0x18/0x1C`，C2H 完成并比对后才写 `0x14=1`。清通知仍为先保存 `0x2C`、再读 `0x10`；没有新增或简化 BAR。
