# RPT205 板级约束与 CDC 修复记录

## 范围与硬件确认

用户授权修正当前工程 XDC 和已经定位的 CDC RTL 缺陷，不增加 BIST、自测顶层或测试业务功能。仅运行一个短仿真；综合、实现及后续 bitstream 由用户手动执行。

硬件同事经用户确认：

- 使用背板 PCIe x2，100 MHz 参考时钟 AF6(P)/AF5(N)。PERST# 为 H24 输入、3.3 V、无电平转换；XLSX 的输出方向标注有误。
- AC34 悬空，不能作为 DDR 系统复位输入。
- TX_DISABLE、RS0、RS1 不使用。ETH_ON1/5 是光检测输入，有光为高；ETH_LINK1/5 是低有效点灯输出。它们不是上述三个 SFP 控制脚的替代网络。
- CFGBVS 接 VCCO，配置 bank 供电 3.3 V。
- 1G 使用光口 1，125 MHz AB6(P)/AB5(N)；10G 使用光口 5，156.25 MHz V6(P)/V5(N)。两个时钟上电自动输出，不依赖软件配置。

## CDC 修复

只读 routed 网表审计确认了 209 条 CDC-1、1 条 CDC-7，源头是 XDMA user_lnk_up 直接用于 fdma_clk 域，以及另外两条 CDC-10。报告是修复前基线，不代表修复后结果。

1. adapter 新增 `u_cdc_pcie_link_to_fdma` 两级 XPM 单比特同步器；link_up_fdma 和 rx_store_enable 使用其输出，原始状态不再直接驱动 FDMA 域控制、计数或 INFO_EXCH 完成事件。
2. TX bridge 的 FDMA/user 两侧复位改为本域寄存器输出。全局复位异步断言，链路/事务门控在本域采样清空，连续两拍后释放，消除组合门控直接驱动大量异步 CLR/PRE 的结构。接口和有效数据协议保持。
5. 将 tx_start_valid、tx_frame_done_fdma 声明移到首次使用之前，消除对应 Synth 8-6901。

## IP 一致性与后续复核

PCIe 必须从原 bank225 改到背板 bank224，并关闭 dedicate_perst；否则 H24 约束会与专用 PERST 接法冲突。1G 必须从原 bank224 迁往光口 1 所在 bank225。脚本 `scripts/configure_rpt205_ip_20260921.tcl` 通过 Vivado 配置接口修改 BD/IP，重新生成输出产物；不编辑生成的 GT HDL 或 *_board.xdc，不启动任何综合/实现 run。

重新综合、实现后需确认 NSTD-1/UCIO-1/CFGBVS-1/PORTPROP-10、原 user_lnk_up 的 CDC-1/7、两处 CDC-10、自定义 TX LUTAR-1，以及新 GT pin/LOC/refclk 的一致性。旧 WNS +0.011 ns 是修改前结果，本轮不会把它当作修改后的时序通过结论。

IP 内部未使用输出、MIG/debug 的 RTSTAT、OOC 时钟估计等告警分类保留；BUFGCE_DIV 级联及 Aurora init 配置频率差异仍须在后续实现报告复核，未用 false path 或 DRC 降级消除。

- FDMA 的 1 位线程 ID 经补零进入 Crossbar，源地址范围为 0–1；实际 CONV_DMA 固定发送 ID 0。
- XDMA 的 4 位线程 ID 经补零进入 Crossbar，Crossbar 添加源标识后的范围为 16–31，与 FDMA 不重叠。
- Crossbar 在返回 BID/RID 时使用 f_thread_id_mask 清除源标识。FDMA 取低 1 位、XDMA clock converter 取低 4 位均保留完整线程 ID；DDR 侧仍为 5 位。
- 生成 HDL 中 AWID/ARID 拼接明确补零；响应截位发生在已去除源标识之后。因此此次列出的 BD 41-2384 是自动互联的正常位宽适配，不需要改动 RTL 或强行统一 ID 位宽。没有设置消息抑制或告警降级。这一结论不自动覆盖其他位宽告警。
