# 50 μs 主机—子机接口变更方案（2026-09-29）

> 状态：讨论稿。此前的主机 50 μs 试验性 RTL 已于 2026-09-29 恢复到修改前版本；下述“试验性实现”未在当前远程工程生效，接口格式尚未定稿。

## 依据与边界

依据 `50us方案_20260928.md` 后段会议转写：主机产生共同的 50 μs 节拍，经 Aurora 10G 通知子机；1G 模拟参数发送与该节拍对齐；3588 软件不承担每 50 μs 硬实时触发。转写稿没有确定报文二进制格式、计算步数和 2.0/2.5 μs 取舍。下列格式是本次主机 RTL 采用的**待子机确认接口**，不能当作会议已批准的协议。

本工程是主机中的 FPGA 辅助板。子机 RTL 未提供。目前保持 CPU→DDR→10G 的 16 Byte 原始数据帧、10G→DDR 的 100 ms×8 块缓存和逐块 CPU 确认。

## 前次试验性实现（已撤销，供讨论）

1. 250 MHz 域计数 12500 拍产生一个 50 μs 周期事件。用翻转位分别跨到 10G 和 1G 用户时钟域；不把单拍脉冲直接跨域。
2. 10G 发送口在既有 CPU 数据帧之间插入 16 Byte 同步帧；不能抢断已呈现或正在发送的数据帧。每周期至多保留一个待发同步帧。长时间反压导致待发帧被覆盖时，内部 `missed_epochs` 饱和计数增加；该计数尚未映射到软件寄存器。
3. 1G 保留首次有效配置锁存及现有 6 Byte 参数帧。首次有效配置前不发业务帧。每次收到同源 50 μs 事件后重置 63 拍分频相位；链路恢复后等待下一次事件，避免本地自由运行导致长期漂移。无反压时，一个窗口内最多在边界及其后每 2.016 μs 形成约 25 次发送机会。
4. 原有 10G 上行接收、DDR 写入、100 ms 封块和 PCIe 块就绪中断未改。主机当前只保留每个 64 bit 上行拍的低 32 bit，且不保存 SOF/EOF，因此子机若要让 CPU 看到 50 μs 序号，必须把它放进被保留的低 32 bit 数据字，或另行约定并修改主机上行格式。

## 10G 同步帧格式（主机当前发送）

16 Byte、两拍 64 bit LocalLink，均为 8 个有效字节，第一拍 SOF、第二拍 EOF；下表按**线路字节顺序**编号。

| 字节 | 内容 | 说明 |
|---|---|---|
| 0–3 | `52 54 44 53` | ASCII `RTDS`，同步帧标识 |
| 4 | `01` | 类型：50 μs 同步 |
| 5 | bit0=RUN，其余位0 | RUN 在主机首次合法 1G 配置跨域完成后为1；系统复位后回0。当前没有运行中软件停止命令 |
| 6–7 | `00 10` | 帧长 16 Byte，大端 |
| 8–11 | `epoch_seq` | 32 bit 大端，10G 用户域每观察到一个事件加1；复位后重从1开始，自然回绕 |
| 12–15 | `00 00 00 00` | 预留 |

CPU 下行数据帧仍原样转发，但不能使用与上述同步帧相同的保留头部，否则子机无法区分控制帧与业务帧。子机须按 SOF/EOF 先分类，再把其余 16 Byte 帧交给原业务解析器。

## 子机需要实施的接口

1. 10G 接收器识别同步帧并锁存 `epoch_seq` 和 RUN。RUN=1 的**新序号**产生一个本地单拍 `epoch_start`；重复、过期或格式错误的同步帧不得重复启动计算。若序号跳变，记录失步次数；10G 链路复位后重新建立基准。
2. 应用计算的 50 μs 主循环由 `epoch_start` 触发，不能仅靠子机自由运行计数器或 3588 中断。一次计算未结束而下一序号到来时须定义丢弃、跳过或告警规则，不能静默把两周期数据混用。
3. 1G 接收器保持 6 Byte duty/Vin 参数格式。以当前 10G 周期为窗口锁存 1G 参数，并定义窗口边界附近到达帧的归属；10G 控制帧和 1G 数据经过不同物理链路，**到达先后不保证**。子机最好以序号启动周期、在规定的采样截止点取最近完整的 1G 参数帧。
4. 10G 回传结果建议携带对应 `epoch_seq`、子机丢周期/超时状态和数据长度；具体回传格式需与现有主机“每拍只存低 32 bit”的规则一起定稿。若直接按现有上行数据流发送，主机仍只按 100 ms 块通知 CPU，不能宣称软件每 50 μs 收到一次结果。

## 时序与中断结论

50 μs 是主机本地事件间隔，不等于10G线上到达严格每 50 μs。跨时钟域同步、正在发送的业务帧和链路反压会造成延迟；同步帧额外净荷约 `16×20000=320000 Byte/s`，与业务帧共用同一个10G发送口。1G 与10G由同一个250 MHz事件对齐，但不同链路的传播延迟要在子机联调测量。

31.25 MHz 的一拍是32 ns：固定63拍=2.016 μs；精确固定整数分频无法得到2.0或2.5 μs。若子机要求平均2.0 μs，可交替62/63拍（25次/50 μs）；平均2.5 μs 可按78/79拍的分数分频（20次/50 μs）。两者单次间隔均有一拍级抖动。本次保持63拍，待子机确定每个50 μs所需计算次数及允许的抖动再改。

会议提到的“中断”包括原有 FPGA→3588 的数据就绪 PCIe 中断，以及建议3588用定时器每50 μs主动扫描。二者都不应作为子机硬件同步源；本方案无需新增PCIe中断或背板中断线。原PCIe中断继续用于100 ms块就绪通知。若将来必须证明3588每50 μs完成一次取数，需要单独评估操作系统、驱动和DMA时延，当前RTL不作此保证。
