# RPT205 上板前管脚与告警审计（2026-09-21）

## 结论

最新 GUI 实现通过静态时序，但当前完整 TOP 还不具备直接作为 RPT205 独立自测镜像的条件。DDR 管脚匹配；非 DDR 的 GT/参考时钟/控制引脚存在板级映射问题，DRC 中还有会阻止生成 bitstream 的缺失约束，以及真实的单比特 CDC 风险。不能通过降低 DRC 严重程度或给所有跨域加 false path 来解决。

本次为审计：保留当前已通过的 RTL、IP、XDC 和 XPR，不启动综合、实现、bitstream 或下载。新增逐脚比对脚本、CSV 和只读网表 CDC 检查。

| pcie_rst_n | K22，DEFAULT，MCAP/PERST 专用位置 | 表中 K22 未列出 | 须追踪实际 PERST 来源和电压；表中 H24/AK13 标为输出，不能直接拿来替代输入 |
| ddr_sys_rst_n | AC34，LVCMOS18 | RP DDR 文本和 XLSX 均未列明该复位输入 | DDR 数据脚正确不代表 AC34 是本板有效复位，须确认来源/上拉；不能换到 BANK0 的 T7 配置复位脚 |

PCIe 目标可能为背板 bank224、金手指 bank227 或 OCULINK bank228。接口选择必须由真实连接确认；切换 GT 可能同时要求调整 PCIe block 位置、MCAP/PERST 设置及 refclk 选择，不能只覆盖生成 XDC 中的 LOC。

XLSX 第 103、104 行均把网络名写成 `REFCLK4-BUFFER-N`，存在正负端标注疑点；器件 pin 表区分 P6 为 P、P5 为 N，但连接器侧实际极性仍应回查 DSN/netlist。

## 已定位的真实 CDC 与独立测试障碍

`PCIe.v` 将 `user_lnk_up_int` 直接接 adapter 的 `pcie_link_up`。该信号来自 XDMA 时钟域，adapter 在系统 250 MHz 域使用它生成 `link_up_fdma`、`rx_store_enable` 和 `tx_fdma_rstn`。

当前 timing report 的跨域路径明确从 XDMA `user_lnk_up_reg` 到 RX `dropped_frames`、写状态机、TX 计数器及异步复位端。这些路径虽然被报告为正裕量，也不能保证独立时钟的物理 CDC 安全。修复方案是在控制域同步 link-up，并在各消费域规范复位释放；对同步器首级用精确约束，后级保持检查。不能仅添加全局异步时钟组把该缺陷隐藏。

不依赖软件有两种范围，应区分：

1. 插在主机上但不运行自编驱动/应用：PCIe 物理建链通常可以依赖主机硬件完成，但当前配置和数据搬运仍需命令源。不能把 link-up 当作 DDR 读写自测通过。
2. 完全不接 PCIe 主机：当前 `rx_store_enable = ddr_ready && pcie_link_up`，RX 入 DDR 被禁止；1G `cfg_req/cfg_ack` 也依赖 `cfg_byte_valid`。当前 TOP 没有替代软件的 DDR 自检主机和自主配置入口。

### 范围更正

用户已明确本轮只修当前工程的板级约束和已确认的 CDC 缺陷；不增加独立自测顶层、BIST 或测试业务代码。前述独立测试障碍仅作为现状说明，不扩展为本轮开发任务。最新硬件确认及实际改动以 `RPT205_板级约束与CDC修复记录_20260921.md` 为准。

## DDR 约束复用边界


当前启用的手写 XDC 只有 `DDR4_PIN.xdc` 与 `rtl/aurora1g_board.xdc`；旧 `PIN.xdc` 不应整份重新启用。手写主时钟分别为 SYSCLK 100 MHz、PCIe refclk 100 MHz、1G refclk 125 MHz、10G refclk 156.25 MHz；不同物理输入各一份是合理的。避免的是同一输入重复建钟，不是整个设计只允许一个 create_clock。MIG NO_BUFFER 的上游主时钟与其内部自动生成时钟各负其责。

本次逐脚比对证明现有 DDR 引脚匹配，但未证明实际焊接颗粒型号、电压及板上速率裕量。当前 MIG 配置为 MT40A512M16HA-083E、TimePeriod 833 ps，应继续与实板 BOM/原理图一致。
