# 本轮代码规范核对

依据用户指定的 `E:\centOS\代码规则建立\代码规范输出`：

- 01_ASIC_Verilog_RTL代码规范.md
- 02_SystemVerilog_UVM验证代码规范.md
- 03_用户自定义规则.md / config/custom_rules.json
- config/approved_cells.json

本轮为FPGA本地工程开发，不构成ASIC或板级签核。这里只记录实际采用的结构和仍需要工具验证的内容，不把规范包中尚未批准的单元登记成approved。

| 规则/重点 | 本轮处理 | 证据与限制 |
|---|---|---|
| CUSTOM-RTL-001，一个always一个根寄存器 | 新增核心、CONV_DMA、adapter及INFO时序按寄存器拆分 | 按原条件树投影保留优先级；新的IRQ/完成判定改成显式互斥优先分支，尚未功能仿真 |
| 组合LUT多目标例外 | duty/Vin/valid共同编号分支集中核对 | 例外说明位于1G模块LUT之前；不混合时钟/复位域 |
| CUSTOM-RTL-002，声明与驱动分离 | 修改的核心RTL使用独立wire/assign | 保留厂商生成代码及历史验证代码的语言边界，不能用RTL规则否认合法SV验证语法 |
| CUSTOM-RTL-004，语义段注释 | 为首次锁存、四相握手、周期、反压、封块、ACK、中断竞争及错误统计补中文说明 | 注释解释保持/清除条件，不用“赋值给某信号”代替协议说明 |
| 状态机 | 新增发送/块管理及CONV_DMA采用curr_st/next_st两段式 | 组合次态默认保持，非法状态回空闲；尚未动态验证 |
| 组合赋值 | INFO读译码改为阻塞赋值 | 保留原读数据锁存和AXI握手，不把组合NBA延迟当作协议时序 |
| 端口/位宽 | 新模块命名端口，明确32bit 1G与64bit 10G，48bit配置完整传递 | 源码端口名可静态对应；最终位宽、CDC、RDC、时序仍需Vivado/专用工具检查 |
| SV驱动/采样 | 新定向测试使用interface/clocking，区分激励和采样入口 | 本轮不强行把原厂商Root Port/TPI迁移为UVM；新SV接口仍需目标仿真器兼容性检查 |
| 错误计数 | 快速断言改为具名fatal，消除多断言共享NBA加一；计分板同拍加错不漏计 | Root Port错误按域分开，统一观察求和 |
| 验证完成 | 定向用例使用有限任务和全局watchdog，检查残留 | 只交付源码，尚无新版运行通过结果 |

兼容边界：PCIe/INFO/CONV及厂商接口的既有大小写和端口名保留，以免破坏BD模块引用与官方TPI层次；新业务模块采用大写模块名及小写文件名。厂商版权头不移除。原有MIG、AXI转换器和ILA不做无关改写。

未执行的规范/工具项目：Vivado生成结果一致性、语义展开、Lint/CDC/RDC、时序和仿真。静态语法解析与端口名检查不等于完整规范PASS；批准单元登记仍需后续项目评审。原快速BFM及官方Root Port包含历史过程式测试结构，不能把本轮定向interface改造描述为整个旧环境已经完成UVM迁移。
