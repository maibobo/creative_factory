# PCIe交互协议 V2.02

本轮实现目标：下行16Byte帧；单个32bit Aurora 1G按2µs同源事件发送16Byte同步帧；10G上行按连续有效字流写入100ms×8块DDR。V2.02更新1G四拍字段格式、0x2C Aurora状态调试位及版本/日期；10G原始16Byte下行继续原样转发。本次修改尚未完成Vivado综合、实现或上板验证。

## 数据与地址

CPU下行窗口为0x00008000～0x0000FFFF，长度为16Byte的正整数倍，地址16Byte对齐。整批最大32KiB。每个16Byte帧分两次64bit DDR读拍原样送10G，由子机解释报文内容；主机不截取10G数据的低2Byte，也不做字节交换或整帧反转。发送桥将每个64bit FDMA读拍原样写入FIFO，再将FIFO数据原样送到Aurora用户接口，保持原始位位置。主机1G逻辑只解析首个64bit读拍中的Byte1，即`fdma_rdata[15:8]`，合法值1～10按既有十组表锁存duty和Vin；Byte0不参与1G配置，后续帧不改变已锁定配置。

1G数据格式为四拍32bit，总计16Byte；Vin保留32bit原始位序，不做字节交换，duty放在第二拍[31:16]。主机250MHz域每500拍产生一个2µs源事件，跨域到31.25MHz Aurora用户域后尝试发送。每拍`tx_rem=3`，首拍SOF、第四拍EOF：

| 拍序号 | `tx_data[31:0]` | 内容 |
|---|---|---|
| 第一拍 | `decoded_vin[31:0]` | 完整32bit Vin，保持高位在高位 |
| 第二拍 | `{decoded_duty[15:0], 16'h0000}` | duty位于[31:16]，低16bit预留为0 |
| 第三拍 | `32'h00000000` | 预留拍 |
| 第四拍 | `32'h0000EB90` | [15:0]=`16'hEB90`同步字，[31:16]=0 |

按高字节先发送的字节表示，第四拍最后两个字节为`EB 90`（Byte14、Byte15）。

配置与链路就绪后从下一个事件发帧。事件到来时若接口反压或前帧尚未发完，该次事件跳过并计入内部`skipped_periods`；在途帧每拍保持到握手。链路断开会中止在途帧，恢复后不补发。31.25MHz域采样将实际起始时刻量化为32ns拍；反压和链路故障时不保证每个源事件都形成一帧。`skipped_periods`目前不是软件寄存器。

上行每个有效64bit拍只有低32bit有效。接收FIFO先保留64bit原拍，DDR域将两个低32bit拼成一个64bit写拍，先到数据在低位。线路SOF/EOF不进入DDR，也不用于固定长度检查；软件不能从DDR恢复线路帧边界。按接收顺序形成小端32bit数据数组。

上行地址0x00100000～0x002FFFFF，共8个256KiB块；块k基址=0x00100000+k×0x40000。DDR域100ms边界请求封存，等待在途写响应；单个剩余字使用WSTRB=0x0F写入，有效长度只增加4Byte。积压数据按实际进入DDR窗口归属，不是采样时间戳。空块不发布；块满或队列全满时不覆盖旧数据。

## 同源同步 GPIO 与设备协同

主机板级100MHz经Clock Wizard得到250MHz；2µs事件和50µs CPU GPIO都由这一路250MHz计数产生。GPIO周期12500拍（50µs），高、低各6250拍（25µs）；上升沿与该周期第一个2µs源事件在同一250MHz拍，共有25个源事件。GPIO在1G尚未建链时也继续运行。50µs仅经主机`cpu_sync_50us`端口、RPT205 TEST3/AM11输出，不经1G或10G向子机发50µs同步帧。AM11为LVCMOS33；RK3588接收GPIO已确认可使用3.3V。联板前仍需确认TEST3/AM11到RK3588输入脚的实际连线。

RK3588软件将对应管脚配置成3.3V GPIO输入，以**上升沿**对齐50µs计算节拍，忽略下降沿作为计算触发，并记录边沿时间及软件超期次数。软件先按现有16Byte PCIe H2C流程提交首个有效配置（Byte1为1～10），然后期待1G周期帧；该配置保持到主机复位。GPIO出现不表示1G已建链，也不表示本周期结果已可读。

子机1G接收逻辑须校验一帧恰有16个有效字节且第四拍低16bit为`16'hEB90`（高字节先发送时对应Byte14=`0xEB`、Byte15=`0x90`），完整接收后锁存duty/Vin，再把稳定参数与事件送到Buck的25MHz域，在该域产生单拍40ns计算触发。Byte8～15本版全零，留给后续补报等功能；本版没有补报或序号，异常跳帧不能由子机按帧内序号检测。子机接收、跨域和Buck脉冲由对应逻辑负责人实现与联板验证；多子机间的实际到达偏差也需联板测量。

CPU取结果继续使用现有`UP_READY_BLOCK_CNT`、上行块地址/长度、C2H及`CPU_REC_STATE`确认流程；约100ms发布上行块。本版没有每50µs的PCIe读写、结果就绪承诺或同步寄存器。CPU/FPGA联板时应测量GPIO周期/占空比，主子机联板时应测量1G帧到达间隔与子机40ns脉冲。

## 寄存器

所有寄存器为32bit、小端、相对于原AXI-Lite BAR的字节偏移。

| 偏移 | 名称 | 语义 |
|---|---|---|
| 0x00 | VERSION | 0x00002002 |
| 0x04 | PROG_TIME | 0x20261029，源码版本日期 |
| 0x08 | BUF_LEN_MAX | 0x00040000，仅指上行单块容量 |
| 0x0C | FPGA_TEMP | 原温度接口 |
| 0x10 | INT_STATE | 读清通知，不释放块 |
| 0x14 | CPU_REC_STATE | 写bit0=1确认一次；硬件消费后清0 |
| 0x18 | FPGA_CPU_START_ADDR | 最老待取块地址；空队列为0 |
| 0x1C | FPGA_CPU_LEN | 实际有效长度，4Byte整数倍；空队列为0 |
| 0x20 | CPU_WR_DONE | 写1提交；整批10G发送完成或拒绝/中止后清0 |
| 0x24 | CPU_FPGA_START_ADDR | 下行DDR地址，忙期间写入忽略 |
| 0x28 | CPU_FPGA_LEN | 下行长度，忙期间写入忽略 |
| 0x2C | DDR_STATUS | Bit0～4为原DDR状态/错误；Bit5～8为Aurora调试状态，见V2.02寄存器说明 |
| 0x30 | UP_READY_BLOCK_CNT | 待取块数0～8 |
| 0x34 | UP_BLOCK_SEQ | 每发布非空块递增，32bit自然回绕，首块0 |
| 0x38 | UP_DROP_WORD_CNT | 累计丢失32bit有效字数，32bit饱和 |

0x2C为只读DDR_STATUS。Bit5=10G Aurora通道已建立，Bit6=10G通道曾建立后断链的sticky记录，Bit7=1G Aurora通道已建立，Bit8=1G首次合法配置已完成；Bit31:9保留为0。内部部分兼容连线暂保留RX_DROPPED_FRAMES名称，但统计单位为32bit字，不能按帧解释。

## 软件操作与可靠性边界

下行：等0x20为0→写地址和长度→完成H2C写DDR→最后写0x20=1→等待清0。无需软件先写0。忙期间重复写1不追加任务；非法范围不访问DDR，消费后清0。清0表示本次请求结束，不能单独作为远端子机已处理或非法请求成功的证明；当前寄存器表未增加事务结果码。

上行：单一消费者读通知→读地址/长度/序号→完成C2H→写0x14=1。确认前队头元数据及DDR内容保持稳定。读清中断不释放块；确认后还有待取块会重新通知。禁止两个软件线程分别读头和确认。DMA完成及MMIO操作必须使用驱动提供的完成和顺序保证。

计数包含接收FIFO溢出、DDR缓存不能接收及写响应错误对应的数据字；每个丢失字只统计一次。上行数据被丢弃后只通过累计计数报告，不在数据流插入占位字。因此软件发现计数变化后，不能仅凭连续数组定位缺口位置。

AXI写响应失败时不增加块有效长度，下一次写入覆盖尚未提交的位置。写响应一直不返回时不发布成功块；接收FIFO最终满并累计丢失，不能假称该故障已恢复。

## V2.02与V2.01的差异

V2.02将1G四拍格式更新为Vin、duty高16位、预留拍和`16'hEB90`同步尾拍；10G原始16Byte下行仍保持原样转发；`0x2C DDR_STATUS`增加四个Aurora调试位。V2.01文档保留作历史版本，本文件为当前协议说明。

板上仍使用DDR。2MiB块总分配空间保持不变，不据未经确认的上行发送频率估算固定每块数据量。
