# 主机模块应用验证方案 单机

## 1. 目标与范围

以管理板 CPU 已能读写主机 FPGA 寄存器为起点，规划 CPU 与主机 FPGA 之间的数据交互和主机内部业务逻辑验证。假设 H2C、C2H 尚未接入或验证；先确认并接入驱动提供的数据传输能力，再由应用组织测试。已有提前完成的 DMA 实验仅供方法参考，不作为本方案的通过结论。

测试对象为管理板 CPU、主机 FPGA 和主机 DDR；不连接真实子机。上行使用 FPGA 的 VIO 固定测试源，ILA 和板级测量用于辅助观察。测试结果应区分实板、仿真和待验证。

## 2. 验证策略与应用接口

按“环境与配置 → DDR 数据往返 → 模拟上行与队列 → 同步、中断及异常”的顺序开展。管理板应用负责准备数据、调用 DMA、操作业务寄存器、比较结果并记录日志；驱动负责提供寄存器访问和 DMA 传输能力。

- **寄存器访问**：按用户 BAR 相对偏移进行 32 bit 小端读写。启动时核对实际 FPGA 版本、DDR 就绪和异常状态；BAR 地址由设备枚举和驱动映射确定。
- **DMA 接口**：确认 H2C、C2H 的设备入口、卡端 DDR 地址、CPU 缓冲区、长度、对齐要求、完成字节数、超时及错误返回。若驱动缺少所需接口，先由驱动侧补齐；测试应用不假定接口已可用。
- **上行处理**：单一消费者检查 `0x30`，逐块读取 `0x18/0x1C`，完成 C2H 并比较有效数据后，再向 `0x14` 写 1 归还一次。`0x10` 是读清通知及相关异常记录，读取前先保存 `0x2C`，读清本身不归还数据块。
- **数据顺序与记录**：记录卡端地址、有效长度、DMA 请求和完成长度、数据比对、队列状态及 `0x38` 丢字计数。DMA 失败、短传输或数据不一致时停止并保留现场，不归还该块或盲目重试。

## 3. 测试项与通过条件

| 测试项 | 验证方法 | 通过条件 |
| --- | --- | --- |
| 环境与状态 | 确认 PCIe 设备、驱动、用户 BAR 和 FPGA 版本；读取 `0x2C`、`0x30`、`0x38`。 | 设备与版本匹配；DDR 校准和业务就绪，记录异常及丢字基线。 |
| 下行配置 | 在 `0x20` 空闲状态写入合法的 `0x24` 地址、`0x28` 长度并回读；测试后在健康空闲时恢复原配置。 | 写入与回读一致；配置动作不自行启动发送，原配置恢复。 |
| 下行命令局部检查 | 在满足现场条件时提交一次合法下行命令，记录 `0x20` 及本地状态，必要时结合 ILA 观察。 | 命令结束后返回空闲；无真实对端时仅记录本地行为，不判定 10G 发送成功。 |
| DDR 数据往返 | 从下行窗口 `0x8000` 开始，以 16 Byte 已知数据进行 H2C 写入和 C2H 回读，再测试合法的多帧和窗口边界长度。 | 每次 DMA 完成长度与请求一致，全部数据相同，无新增 DDR 异常。窗口最大 32 KiB；实际请求须符合驱动对齐和长度要求。 |
| 单块上行 | 在 `RX_VIO_TEST_ENABLE=1` 的测试版本中，VIO 注入固定数据；读取队头、C2H 并比较后归还。 | 一次形成一个有效长度为 8 Byte 的块，数据为 `11 00 00 00 22 00 00 00`；读清通知不改变队头，归还后该块释放。 |
| 多块与环回 | 按 2 块、8 块、2 块积累和排空；每块使用返回的地址、长度及序号。 | 块数变化正确，数据和顺序一致，覆盖 8 个槽并最终排空，无新增丢字。 |
| 50 µs 同步 | 在 FPGA 测试点测量周期与高低电平；确认接线后，由 CPU 记录 GPIO 上升沿、间隔和超期情况。 | 板侧周期约 50 µs、高低各约 25 µs；CPU 侧能接收并记录上升沿。CPU 调度时延以实测为准。 |
| 用户通知 | 驱动支持用户中断时，在队列为空时使能通知，触发 VIO 并完成取块。 | CPU 实际收到通知；读清不释放块，应用按队列数量读取并归还至空。 |
| 异常与丢字 | 通过可控的测试桩、仿真或具备条件的现场方法检查 DMA 错误、短传输、超时及丢字状态。 | 能记录失败与状态，失败块不归还；`0x38` 以丢失的 32 bit 有效字为单位，发现增加时报告丢字；计数饱和后无法据此确认无新增丢字。 |

VIO 固定源可验证单块和多槽队列协议，但队列满后会拒绝继续注入，不能据此证明真实 Aurora 过载丢字行为；单字尾部、大块和溢出等场景需具备相应激励或用仿真补充。若 DMA 仅支持 16 Byte 对齐请求，单块可在确认安全的前提下读取 16 Byte，只比较前 8 Byte 有效数据，并分别记录请求长度和有效长度。

## 4. 条件、判定与输出

- 测试使用匹配的 FPGA 产物及 LTX，并记录版本与测试模式；`VERSION=0x00002001` 不能单独证明当前使用的是哪一份 bit。
- 每项记录测试条件、输入、寄存器状态、DMA 请求／完成长度、比较结果和失败信息；中断、GPIO、ILA 或仿真证据按实际执行情况分别记录。
- 未具备驱动、VIO、接线或故障激励条件的项目标记为待验证，不能记为通过。真实 10G/1G 收发、子机接收及执行结果不属于本单机验证结论。
- 寄存器手册与较新设计对 `0x28` 复位值存在差异；测试前以所用 FPGA 版本、RTL 和现场读值核对，不把示例配置值当成固定复位值。
