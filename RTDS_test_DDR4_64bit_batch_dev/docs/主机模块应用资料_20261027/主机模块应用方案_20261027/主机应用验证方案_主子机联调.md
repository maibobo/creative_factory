# 主机模块应用验证方案 主子机联调

## 1. 目标与范围

以管理板 CPU 已能读写主机 FPGA 寄存器为起点，假设 H2C、C2H 尚未接入或验证。先确认并接入驱动的数据传输能力，完成 CPU 与主机 FPGA 的基础交互，再通过真实子机验证 10G 上下行和 1G 参数链路。

测试对象为管理板 CPU、主机 FPGA、主机 DDR 和真实子机。已有提前完成的 DMA 实验仅供方法参考，不作为本方案的通过结论；实际结果按本次设备、程序版本和现场记录判定。

## 2. 验证策略与应用接口

按“CPU 与主机基础交互 → 10G 下行 → 10G 上行 → 1G 参数与同步 → 联动、积压及异常”的顺序开展。管理板应用准备已知数据、调用 DMA、控制业务寄存器并记录结果；子机或配套接收工具提供可核对的发送、接收数据。

- **接口前提**：确认用户 BAR 的 32 bit 小端寄存器访问，以及 H2C、C2H 的入口、卡端地址、CPU 缓冲区、长度、对齐、完成字节数、超时与错误返回；缺失的 DMA 能力先由驱动侧补齐。
- **下行流程**：确认 `0x20` 空闲，完成 H2C 写 DDR，设置 `0x24/0x28` 后向 `0x20` 写 1；保存状态，由子机核对实际接收数据。`0x20` 回 0 只能说明本地任务结束，不能单独证明子机接收成功。
- **上行流程**：由单一消费者检查 `0x30`，逐块读取 `0x18/0x1C` 和需要记录的 `0x34`，完成 C2H 和有效数据比较后，向 `0x14` 写 1 归还一次。读 `0x10` 会清通知及相关异常记录，先保存 `0x2C`；读清不归还块。
- **版本与数据**：真实 10G 上行使用 `RX_VIO_TEST_ENABLE=0` 的匹配 FPGA 产物；`RX_VIO_TEST_ENABLE=1` 选用内部固定源，不能作为真实接收通过的证据。记录有效长度、DMA 请求／完成长度、数据和 `0x38` 丢字变化。

## 3. 测试项与通过条件

| 测试项 | 验证方法 | 通过条件 |
| --- | --- | --- |
| 基础交互与 DDR | 核对 PCIe、FPGA 版本、DDR 就绪及 DMA 接口；进行 H2C 写入、C2H 回读和配置回读。 | 设备与版本匹配；请求完成长度正确，读回数据逐字节一致，无新增 DDR 异常。 |
| 10G 下行单帧与多帧 | CPU 将 16 Byte 已知帧和多帧数据写入下行窗口、配置并提交，子机保存接收内容。 | 子机收到的完整 16 Byte 帧、帧数、顺序及内容与 CPU 输入一致；仅本地 `0x20` 回 0 不算通过。 |
| 10G 上行单块 | 子机发送已知数据，CPU 轮询块数并读取队头，C2H 后比较有效数据，再归还。 | 返回地址、有效长度和全部有效数据正确；每块完成后仅归还一次，无新增丢字。 |
| 上行多块与边界 | 子机发送带顺序信息的已知字流，覆盖多块、8 个槽循环及单个 32 bit 尾字。 | 各块顺序与内容一致，长度按 4 Byte 粒度记录，尾字有效数据正确；队列最终按预期排空。 |
| 1G 参数 | 发送 Byte1 为合法编号的下行配置，再发送不同合法编号；由子机或接收工具采集 1G 参数帧。 | 首次合法配置对应的参数正确；对端收到完整 16 Byte 帧，Byte6 为 `0xF0`；后续合法编号不覆盖首组配置，直至主机逻辑复位。 |
| 同步与时序 | 测量主机 50 µs GPIO，接线后记录 CPU 上升沿；由对端测量 1G 帧到达间隔。 | 板侧周期约 50 µs、高低各约 25 µs；CPU 可接收并记录。1G 以 2 µs 同源事件提供发送机会，实际到达间隔与异常按测量记录。 |
| 连续收发与积压 | 按双方约定的数量和速率连续发送，分阶段积累、读取并归还上行块。 | 数量、顺序、有效长度及内容与发送清单一致；无预期之外的错误或丢字，数据处理后队列可排空。 |
| 满队列与丢字 | 在可控激励和约定的现场条件下，使 8 块待取并继续输入；保存队头和丢字计数。 | 未归还的旧块不被覆盖；无法保存的数据按 32 bit 有效字计入 `0x38`；计数饱和后无法据此判断新增丢字，处理后可继续验证。 |
| 通知与异常恢复 | 驱动支持时验证用户中断；按现场条件测试 DMA 失败、超时、链路中断及恢复。 | 能记录通知和错误；失败块不提前归还或盲目重试；恢复后重新核对就绪状态并执行基础数据验证。 |

上行每个有效 64 bit 接收拍只保存低 32 bit，并按到达顺序形成连续小端字流；DDR 中不保留线路帧边界。约 100 ms 形成非空可读块，不把 GPIO 边沿视作该周期结果已经可读。1G 链路反压或中断时可能跳过发送机会，不能假设每个 2 µs 源事件都必然形成对端帧。

## 4. 条件、判定与输出

- 准备匹配的主机 FPGA 产物和 LTX、管理板驱动与应用、可发送和保存数据的真实子机或等效对端，以及同步信号测量与接线条件。
- 每项记录测试版本、双方输入／输出、块地址和有效长度、DMA 请求／完成长度、队列及异常状态、丢字变化与实际证据。对端不可用、中断不支持或故障条件不可控时，对应项目记为待验证。
- 寄存器手册与较新设计对 `0x28` 复位值存在差异；测试前以所用 FPGA 版本、RTL 和现场读值核对，不把示例配置值当成固定复位值。
- 端到端通过须包含对端接收或发送数据与管理板数据的比较；仿真、ILA 和本地状态可用于定位，但各自不能代替对端比较。
