# 1 设计概述

RTDS 主机 FPGA 连接 RK3588、板载 DDR4 和子机 Aurora 链路。CPU 通过 PCIe XDMA 写入下行数据，FPGA 从 DDR4 读取后经 Aurora 10G 发送；上行数据经过接收缓存、有效字提取和 DDR4 写入，再由 CPU 按块读取。Aurora 1G 用于周期发送参数，cpu_sync_50us 为 CPU 提供同步节拍。

主机采用 xcku040-ffva1156-2-i 器件，板级顶层为 TOP。PCIe 为 Gen3 ×2、Memory Mapped 配置，DMA 数据宽度为 64 bit，AXI-Lite 寄存器宽度为 32 bit。主机业务逻辑运行于 250 MHz；Aurora 用户接口和 MIG 存储接口分别使用各自的时钟。

本文说明各模块的功能、端口、握手时序、数据排列、缓存使用和异常处理。子机内部参数解析与 Buck 计算不属于主机逻辑；主机只通过板间接口提供参数帧并接收返回数据。

# 2 总体架构、数据流与接口时序

## 2.1 系统组成与模块连接

@FIG architecture|系统组成与业务通路

TOP 连接时钟产生、PCIe 存储子系统、两路 Aurora、同源计时、温度采集和运行指示。PCIe 子系统内，XDMA 与 CONV_DMA 共享 DDR4；INFO_EXCH 提供控制和状态寄存器，pcie_fdma_aurora_brg_adapter 连接寄存器、FDMA、10G 收发桥及上行块管理。

| 通路 | 数据处理 | 接口推进条件 |
| --- | --- | --- |
| CPU 下行 | H2C 写 DDR4 → 提交地址与长度 → FDMA 读取 → TX FIFO → Aurora 10G | DMA 完成后提交；FDMA 与 Aurora 分别按握手前进 |
| 10G 上行 | Aurora RX → 异步 FIFO → 取每拍低 32 bit → 配对写 DDR4 → 形成可读块 | FIFO 可接收；写响应成功后增加有效长度 |
| VIO 数据输入 | 固定数据发生器 → 块写入器 → FDMA 与 DDR4 | RX_VIO_TEST_ENABLE=1 时选择该数据源 |
| 1G 参数 | 下行首读拍 Byte1 → 参数表 → 跨域握手 → 周期参数帧 | 首次合法编号与配置跨域完成 |
| 同源计时 | 250 MHz 计数 → 2 µs 事件与 50 µs GPIO | 逻辑复位解除且时钟运行 |

RX_VIO_TEST_ENABLE 为编译参数。值为 0 时，上行块写入器使用 Aurora 接收 FIFO；值为 1 时，使用固定数据发生器，并禁止真实接收数据进入该输入。当前工程取值为 1，两个数据源不会同时写入块缓存。

## 2.2 CPU 下行与 10G 发送

| 阶段 | CPU 与寄存器 | FPGA 行为 |
| --- | --- | --- |
| 空闲 | 读取 0x20，bit0=0 | 没有正在执行的软件发送任务 |
| 写入载荷 | H2C 写 DDR4，并等待 DMA 完成 | 下行窗口保存本批数据 |
| 设置参数 | 写 0x24 地址和 0x28 字节长度 | 空闲时按字节写使能保存参数 |
| 提交任务 | 向 0x20.bit0 写 1 | 产生 RD_START，检查地址、长度和就绪条件 |
| 数据发送 | 0x20 保持忙 | 每 16 Byte 读两拍 64 bit，缓存在 FIFO 后发送 |
| 任务结束 | 硬件将 0x20.bit0 清零 | 正常末帧完成、请求被拒绝或异常中止均可结束任务 |

正常完成以最后一帧 EOF 被本地 Aurora 接口接受为条件。DDR 读取结束不能代替发送结束，0x20 清零也不表示子机已经完成业务处理。下行不由 50 µs GPIO 自动触发，CPU 每次发送新数据都需要提交任务。

每帧首个 FDMA 读拍中的 fdma_rdata[15:8] 同时送至 1G 参数支路。该支路只观察 Byte1，不修改两个 64 bit 数据拍。配置可以先于整批 10G 发送结束到达 1G 用户域。

## 2.3 上行写入、块完成与 CPU 确认

@FIG write_timing|写入接受、最终响应与块可读的时序

| 阶段 | 硬件动作 | CPU 可见状态 |
| --- | --- | --- |
| 接收与配对 | 接受有效字，先到字放低 32 bit，后到字放高 32 bit | 正在写入的块不可读 |
| 写数据 | 发起单拍 FDMA，保持数据和掩码至接受 | 有效长度暂不增加 |
| 等待响应 | 等待 fdma_wdone，并检查 fdma_werror | 成功时有效长度增加 8 Byte 或 4 Byte |
| 周期收尾 | 100 ms 到期，完成在途写和剩余单字 | 本周期新块尚未进入可读队列 |
| 形成可读块 | 保存非零长度与序号，推进写指针 | 可读块数增加，必要时产生通知 |
| 读取与确认 | CPU 按队头地址和长度完成 C2H，再写 0x14.bit0=1 | 释放一块，下一块成为队头 |

读 0x10 只清除通知和相关异常记录，不释放 DDR4 块。CPU 确认之前，队头地址、长度、序号和对应 DDR4 数据保持不变。软件应由同一读取流程完成取块和确认。

周期到期只提出收尾请求。若 DDR4 仍在响应，块完成时刻将向后延长；FIFO 中积压的数据按进入块写入器的时刻计入相应块。数据内不含逐字采样时间戳。

## 2.4 同源事件与 CPU 同步信号

@FIG sync_timing|2 µs 事件与 50 µs GPIO 的相位关系

250 MHz 每拍为 4 ns。计时模块每 500 拍产生一次 2 µs 翻转事件，每 12,500 拍产生一个 50 µs GPIO 周期，高、低电平各 6,250 拍。每个 GPIO 上升沿与相应 2 µs 源事件在同一时钟沿发生，每个完整 50 µs 区间包含 25 个源事件。

1G 用户时钟为 31.25 MHz，每拍 32 ns。事件跨域后提供一次发帧机会；四拍数据在无反压时占用 128 ns。同步采样、接口反压及串行传输会影响子机收到帧的时刻，不能将主机源事件的时刻直接当作子机计算开始时刻。

GPIO 在 1G 未配置或未建链时继续运行。其上升沿用于 CPU 节拍，不表示新上行块已经可读，也不与某个上行块一一对应。

# 3 顶层集成、时钟、复位与跨时钟域处理

## 3.1 TOP 板级集成模块

### 3.1.1 规格概述

TOP 负责板级引脚、共享差分时钟输入、时钟产生、DDR4、PCIe、两路 Aurora 及辅助信号连接。TOP 不解析 10G 业务字段，也不执行子机 Buck 计算。1G 接收输出没有接入主机业务控制。

### 3.1.3 接口时序

CLK_GEN 输出稳定后，sys_rst 解除。计时模块开始产生同步事件；DDR4 在校准及接口复位解除前不接受新存储请求。10G 发送任务还要求 PCIe、DDR4、Aurora channel 和 lane 的同步状态均有效。

### 3.1.4 功能设计

板级差分时钟经过同一个 IBUFDS 后分成两支，分别进入 CLK_GEN 和 MIG 系统时钟输入。MIG 采用 NO_BUFFER，避免在同一输入上重复放置差分缓冲。CLK_GEN 的 156.25 MHz 输出不作为 10G 业务用户时钟，10G 业务使用 Aurora 核输出的 user_clk。

PCIe 输出 cfg_byte 与 cfg_byte_valid，连接 1G 参数发送器。RTDS_SYNC_TIMEBASE 同时提供 tick_toggle_2us 和 cpu_sync_50us。温度和忙状态在 250 MHz 域寄存后进入 INFO_EXCH。

PCIe 模块集成 design_1_wrapper、协议适配器和 DDR4 后端。XDMA 执行 CPU DMA 及 AXI-Lite 访问；CONV_DMA 执行业务 FDMA；INFO_EXCH 保存软件控制参数并返回状态。

| aurora_user_clk / aurora_user_rstn | 输入 | 各 1 | 10G 用户域时钟与低有效复位 |
| aurora_channel_up / aurora_lane_up | 输入 | 各 1 | 10G 链路状态 |

### 3.2.3 接口时序

XDMA axi_aclk 与业务 clk_250m 虽然名义频率相同，但来自不同的时钟源。BD 的 AXI Interconnect 对该边界进行时钟转换，存储和寄存器事务分别按 valid/ready 握手传递。

AW、W、B、AR、R 五通道独立推进。写地址已被接受不代表写数据已经完成，写数据末拍被接受也不代表最终写响应成功。

### 3.2.4 功能设计

axi_interconnect_0 的 S00 连接 CONV_DMA，S01 连接 XDMA，M00 导出共享存储接口。axi_interconnect_1 将 XDMA AXI-Lite 连接至 INFO_EXCH。DDR4 后端使用存储地址低 32 bit；BD 存储映射为 4 MiB。

INFO_EXCH 的 AXI 地址段为 0x40000000、大小 4 KiB。软件使用用户 BAR 内的寄存器偏移；BAR 的 CPU 地址由 PCIe 枚举分配。PCIe 模块还汇总 DDR4 就绪、响应错误、接收溢出及超时状态。

## 3.3 时钟与复位管理

| 时钟 | 频率 | 使用模块 | 连接关系 |
| --- | --- | --- | --- |
| clk_100m_ibuf | 100 MHz | CLK_GEN、MIG 系统输入 | 共享板级输入缓冲 |
| clk_250m | 250 MHz | 寄存器、FDMA、队列、温度、计时 | 主机业务时钟 |
| clk_100m | 100 MHz | Aurora 初始化、DDR4 启动控制 | CLK_GEN 输出 |
| init_clk_25m | 25 MHz | 1G 初始化 | clk_100m 经 BUFGCE_DIV 四分频 |
| XDMA axi_aclk | 250 MHz 配置 | XDMA AXI 与 AXI-Lite | 经 BD 转换至业务域 |
| 10G user_clk | 名义 156.25 MHz | 10G 收发与 FIFO 用户侧 | Aurora 核输出 |
| 1G user_clk | 31.25 MHz | 四拍参数帧发送 | Aurora 核输出 |
| MIG ui_clk | 名义约 300 MHz | DDR4 AXI 控制器 | 经异步 AXI 转换器连接业务域 |

主机逻辑复位由 CLK_GEN 的时钟稳定状态产生。pcie_rst_n 用于 PCIe 核复位，PCIe 断链不会单独清除已保存的 1G 参数。同源计时、1G 参数、接收 FIFO 用户侧及 DDR4 启动等接口分别处理复位释放。PCIe 集成层将 !sys_rst 连接到适配器与 BD 的业务复位端，发送桥事务复位在两域内处理；FIFO 复位忙期间禁止业务读写。

1G 启动控制先解除 GT 复位，再解除核复位；解除后仍等待 Aurora 建链。1G user_reset 或 channel_up 失效会停止当前帧并重新等待发送条件，不清除主机已保存的首组参数。

DDR4 存储失效时，Clock Converter 两侧及 MIG AXI 接口共同进入复位。各侧保持相应复位时钟序列，并在本域连续 16 拍后释放；校准与接口恢复完成后，再由业务侧处理未结束事务。业务就绪不只由校准状态决定。

# 4 PCIe、寄存器与协议适配

## 4.1 INFO_EXCH 寄存器模块

### 4.1.1 规格概述

INFO_EXCH 在 250 MHz 域提供 32 bit、小端 AXI-Lite 寄存器。模块按 WSTRB 更新可写字节，将启动写入转换为 RD_START，将读完确认转换为单周期命令，并返回队头信息和业务状态。

### 4.1.3 接口时序

写通道等待 AWVALID 与 WVALID 同时有效后给出接受信号。主设备应分别保持各自 valid 至握手，不能只发短脉冲。BVALID 保持到 BREADY，RVALID 保持到 RREADY。

空闲时向 0x20.bit0 写 1，使启动位保持为 1，再由上升沿检测产生 RD_START。CPU_WR_DONE_EVENT 使启动位清零，结束事件优先。忙期间写地址、长度被忽略，重复写 1 不增加任务，写 0 不作为取消命令。

向 0x14.bit0 写 1 且 WSTRB[0] 有效时，产生一次 CPU 确认脉冲；寄存器读回为 0，不需要先写 0。读 0x10 的副作用发生于 ARVALID && ARREADY 的地址接受沿，读数据反压不会推迟已经执行的清除。

| bit0 | 当前状态 | 存储就绪，且读写异常结束过程已完成，允许业务请求 |

| bit2 | 异常记录 | 已接受非 OKAY 的 AXI R 或 B 响应 |
| bit3 | 异常记录 | 接收 FIFO 溢出或相应接收异常 |
| bit4 | 异常记录 | DDR4 或 FDMA 无进展超时 |
| bit31:5 | 保留 | 0 |

校准恢复后，若先前事务的错误响应尚未处理完，bit1 可为 1 而 bit0 仍为 0。读 0x10 不撤销异常结束过程，也不清空 0x38；0x38 由主机逻辑复位清零。

队头多字段在 CPU 确认前保持不变，软件可依次读取数量、地址、长度与序号。空队列时不根据残留地址或序号发起 DMA。AXI-Lite 写响应 OKAY 只表示寄存器访问被接受，参数合法性由适配器继续检查。

### 4.2.3 接口时序

下行长度必须为正的 16 Byte 整数倍，起点按 16 Byte 对齐，长度不大于 32 KiB。起点与长度之和采用 33 bit 检查，请求必须整体落在 0x00008000～0x0000FFFF 内。

接受合法任务后保存基址和 LEN/16 帧数。桥内游标从 0 开始，每帧读取两拍并增加 16 Byte；适配器将基址与游标相加形成完整地址。只有每帧首拍真实接受时，才产生 cfg_byte_valid。

用户域每次末拍握手产生一次帧完成事件，经翻转同步送回 FDMA 域。完成帧数达到目标值后结束任务；FIFO 提前读入的数据不计为已发送帧。

### 4.2.4 功能设计

@FIG tx_recovery|下行任务执行与异常结束

下行读取期间，PCIe、DDR4、Aurora channel 或 lane 就绪状态失效时，适配器结束当前软件命令，停止新读请求，不再将该任务返回的数据写入 TX FIFO，也不再产生 Byte1 配置事件。

若 fdma_rbusy 仍为 1，适配器继续给出读接受许可，让 CONV_DMA 收完已接收请求的返回数据。存储不能返回剩余数据时，由 DDR4 后端提供对应错误响应。读通道结束前不会把这些数据交给下一任务。

再次开始发送需要 fdma_rbusy=0、用户域发送桥已停止确认返回，并连续 8 个 FDMA 时钟没有残留帧完成事件。正常结束后的清理期间可保存一条新合法命令；异常中止期间拒绝新命令。

RX_VIO_TEST_ENABLE=0 时，接收缓存允许条件使用 10G 用户域复位、channel 和 lane 状态。存储允许条件使用 PCIe 与 DDR4 就绪状态。存储不可用时，块写入器可消费并丢弃输入字，防止把本地 ready 当作能够暂停光链路的控制。

FIFO 与块写入器的丢字数使用 33 bit 求和后输出 32 bit 饱和值。rx_dropped_frames 的统计单位为有效 32 bit 字。异常清除经翻转事件进入用户域，并等待先前保持的异常电平下降，避免同一记录立即重新置位。

无进展计数默认阈值为 65,535 个业务时钟，约 262.14 µs。请求接受、数据接受及写完成等进展使相应计数重新开始；计数用于报告超时，已接受存储事务的结束由后端恢复逻辑处理。

### 5.2.4 功能设计

突发拍数为 min(剩余拍数，256，(4096−address[11:0])/8)。例如从 0x0FF0 读取 4 拍，先在当前 4 KiB 区间读取 2 拍，再从 0x1000 读取 2 拍。主机下行业务每次读取 2 拍，上行每次写入 1 拍。

新写请求开始时清除 fdma_werror。任一 B 响应非 OKAY 或 BID 不匹配时记住错误，最后一个突发响应后给出 fdma_wdone。零长度或非 8 Byte 对齐的非法写请求可直接返回 done/error。

读数据计数按请求拍数推进，没有独立 rd_error 输出。RRESP 错误由 DDR4 后端记录，fdma_rvalid 仍表示实际 R 握手；它不是可脱离 AXI 返回总线独立保持的数据寄存器。

### 5.3.4 功能设计

@FIG ddr_recovery|DDR4 失效与未结束事务处理

MIG 采用 DDR4-2400 名义配置，时钟周期参数为 833 ps，PHY 时钟比为 4:1。物理数据与 AXI 数据均为 64 bit，AXI 地址 32 bit，ID 5 bit，MIG UI 名义频率约 300 MHz。

后端监视 AW、W、B、AR、R 接受事件和未结束事务。存在未结束事务且没有进展时，计数达到阈值后记录超时；非 OKAY 的读写响应记录响应错误。clear_status 清除诊断记录，不撤销已接收请求。

存储就绪下降时，后端禁止新请求并复位存储转换接口。已被上游接受的请求仍需结束：无法由存储返回的剩余读拍，按原 ID 和剩余拍数返回 SLVERR，最后一拍给出 RLAST；未结束的写请求按已接受的事务和数据进度完成错误响应。

失效发生前已向上游展示、但因反压尚未接受的响应保持原值，不改成新的响应码。只有这一级寄存响应被接受后，才继续装入下一拍数据或错误响应，避免同一有效拍的内容发生变化。

校准状态恢复并不立即允许新业务。后端还要等待读写异常结束状态清除，再使 ddr_ready 有效。因此 CPU 应分别理解校准状态、业务就绪和异常记录。

@FIG block_writer|字配对、写入状态与块队列

frame_ready 在 IDLE、非收尾等待且非周期事件当拍时有效。第一个字 A 到达后保存在 half_data；第二个字 B 到达后形成 {B,A}，保存数据、0xFF 掩码与 8 Byte 有效长度，再启动写事务。

| 状态 | 输出与处理 | 转移条件 |
| --- | --- | --- |
| IDLE=0 | 接收有效字或处理收尾 | 配对字或尾字准备完成 → REQ |
| REQ=1 | wareq=1，地址与数据保持 | wbusy=1 → DATA |
| DATA=2 | wvalid=1，保持数据和掩码 | waccept=1 → RESPONSE |
| RESPONSE=3 | 等待最终写响应 | wdone=1，按成功或错误处理后 → IDLE |

### 5.4.4 功能设计

写地址为 0x00100000 + write_block × 0x00040000 + used_bytes。成功的完整拍使 used_bytes 增加 8，成功尾字增加 4；失败写不增加长度，下一次写仍使用该位置。CPU 只读取实际有效长度，不读取尾拍高四字节。

队列保存每块长度和序号，write_block 指向当前写块，read_block 指向最老可读块。新块登记后写指针和序号前进；CPU 确认且队列原本非空时，读指针前进。同拍增块和减块时数量不变；空队列的确认不会释放同拍刚形成的块。

新块形成且队列原来为空时置通知。确认后仍有块或同拍形成新块时继续通知；单独清通知不改变队列。因此已有块应连续处理，不要求每块都等待一次新的中断。

存储不允许、所有块均未释放、当前块已满，或者最终写失败时，相关字计入丢失统计。完整失败写计 2 个字，尾字失败计 1 个字；累计值饱和保持。块满后等待本周期收尾，不覆盖未读块，也不提前创建下一周期块。

每周期单块容量为 262,144 Byte，100 ms 的容量折算约为 2.62 MB/s。实际连续处理速率还受单拍 FDMA 及响应等待限制，不能按 10G 线路速率推算 DDR4 保存速率。周期等待只保留一次收尾请求，不补建多个空块。

| channel_up / lane_up | 输出 | 各 1 | 链路状态 |

### 6.1.3 接口时序

用户复位解除、channel_up 与 lane_up 有效后，发送接口才进入可工作状态。tx_src_vld && tx_dst_rdy 接受一个 64 bit 数据拍；ready 为低时，发送源保持数据及 SOF、EOF、REM。

RX 有效时输出一个完整数据拍。接收接口不能通过本地暂停读取来保证远端串行数据停止到达，因此接收缓存不足时使用丢字统计报告。

### 6.1.4 功能设计

包装内部转换业务高有效标志与核接口的有效极性，并适配数据向量下标。转换不解析 CPU 字段，不对 64 bit 载荷做业务裁剪。板间双方按相同字节对应关系解释数据。

GT 与用户时钟处理由 Aurora IP 实现；用户域到 250 MHz 业务域的数据分别经发送与接收异步 FIFO 传递。

## 6.2 fdma_aurora_brg_tx 下行发送模块

### 6.2.1 规格概述

发送桥将 DDR4 读出的完整 64 bit 数据写入异步 FIFO，在 10G 用户域按两拍组成一个 16 Byte 帧。每拍 8 Byte 均有效，REM=7；首拍 SOF=1，第二拍 EOF=1。

### 6.2.2 接口列表

| 信号 / 分组 | 方向 | 位宽 | 功能 |
| --- | --- | --- | --- |
| fdma_clk / rstn；user_clk / rstn | 输入 | 每项 1 | 两域时钟及事务复位 |
| channel_up / channel_up_fdma | 输入 | 各 1 | 各域执行允许条件 |
| cfg_tx_burst_limit | 输入 | 16 | 本任务目标帧数 LEN/16 |
| fdma_raddr / fdma_rareq | 输出 | 32 / 1 | 窗口内字节游标与请求 |
| fdma_rbusy / fdma_rdata / fdma_rvalid | 输入 | 1 / 64 / 1 | 请求状态、读数据、接受事件 |
| fdma_rready | 输出 | 1 | 允许读数据进入 FIFO |
| tx_d / tx_rem / tx_sof / tx_eof / tx_src_rdy | 输出 | 64 / 3 / 1 / 1 / 1 | 发送拍与帧标志 |
| tx_dst_rdy | 输入 | 1 | Aurora 接受条件 |
| tx_frame_done | 输出 | 1 | 用户域末拍接受事件 |

### 6.2.3 接口时序

@FIG tx_timing|两拍 10G 帧在反压期间的数据保持

| 读状态 | 行为 | 退出条件 |
| --- | --- | --- |
| RD_IDLE | 检查任务允许、FIFO 余量和剩余帧数 | 允许时进入 RD_REQ |
| RD_REQ | 持续读请求 | fdma_rbusy=1 |
| RD_DATA | 接受完整读拍并写入 FIFO | 两拍完成后进入 RD_WAIT |
| RD_WAIT | 等待 CONV_DMA 结束读忙 | busy=0，游标增加 16 Byte |

| 发送状态 | 数据与标志 | 退出条件 |
| --- | --- | --- |
| TX_IDLE | 等待链路和足够 FIFO 数据 | 允许时进入 TX_SOF |
| TX_SOF | 首拍，SOF=1，EOF=0，REM=7 | tx_src_rdy && tx_dst_rdy |
| TX_DATA | 第二拍，SOF=0，EOF=1，REM=7 | 握手后产生完成事件并回空闲 |

FIFO 为 FWFT，输出端可直接取得当前字。读指针仅在发送握手时推进，反压期间不会提前弹出数据。请求接受附近到达的首个读拍同样按实际握手计入，不因状态转换漏计。

### 6.2.4 功能设计

TX FIFO 为 512 × 64 bit，prog_full 阈值为 504。读接受许可结合读阶段、wr_rst_busy 和 FIFO 余量，为已开始的读取保留空间。每次目标读取帧数与已发送帧数分别计数，允许 FIFO 中暂存尚未发送的数据。

若连续 CPU 字节为 B0～B15，则两拍数据保持为 {B7,…,B0} 与 {B15,…,B8}。适配器只旁路提取首拍 Byte1，不改变上述两个值。异常或任务结束时清除发送事务，尚未发送的数据不带入下一任务。

## 6.3 RTDS_RX_FRAME_FIFO 接收缓存模块

### 6.3.1 规格概述

接收缓存使用 2048 × 64 bit 异步 FIFO，保存每个有效 64 bit 接收拍。该模块不按 16 Byte 重组帧，也不根据 SOF、EOF、REM 检查帧长度。低 32 bit 的有效字提取在块写入器中进行。

### 6.3.2 接口列表

| 信号 / 分组 | 方向 | 位宽 | 功能 |
| --- | --- | --- | --- |
| rst_n / user_clk / mem_clk | 输入 | 各 1 | 主机逻辑复位、10G 接收域与 250 MHz 读取域时钟 |
| user_ready | 输入 | 1 | 接收允许条件 |
| rx_data / rx_valid | 输入 | 64 / 1 | 接收数据与有效 |
| rx_sof / rx_eof / rx_rem | 输入 | 1 / 1 / 3 | 保留帧标记接口 |
| rx_ready | 输出 | 1 | 接收接口保持为 1 |
| frame_data / frame_valid；frame_ready | 输出 / 输入 | 64 / 1；1 | 缓存数据与读取接受 |
| fifo_full / fifo_almost_full | 输出 | 各 1 | 同步到 mem_clk 的容量状态 |
| dropped_frames | 输出 | 32 | 用户域计数跨域后的累计丢字 |
| length_error | 输出 | 1 | 固定为 0，不参与帧长判断 |

### 6.3.3 接口时序

用户域 user_ready、数据有效、FIFO 未满且写侧复位结束时，写入一个完整数据拍。不能写入的有效拍计为丢失的一个低 32 bit 业务字。同步到读取域的满状态只用于诊断，不作为用户域的即时写允许条件。

读取域在 FIFO 非空且读侧复位结束时给出 frame_valid。frame_valid && frame_ready 才推进读指针；块写入器暂时不接受时，当前数据保持。

### 6.3.4 功能设计

FIFO 使用 FWFT、两级指针跨域同步及 block RAM，prog_full 阈值为 2043。它吸收两个时钟域之间的瞬时速率差，不能代替持续存储能力。累计丢字通过 Gray 计数传递到读取域，达到 0xFFFFFFFF 后保持。

当前 RX_VIO_TEST_ENABLE=1 时，真实接收输入被隔离，块写入器取固定数据源；参数为 0 时恢复 FIFO 输入。两种配置使用相同的块写入、DDR4 和 CPU 取块接口。

# 7 Aurora 1G 参数发送与同源同步

## 7.1 RTDS_1G_PERIODIC_TX 参数发送模块

### 7.1.1 规格概述

参数发送器从下行首读拍接收 Byte1 编号，首次合法编号决定 duty 与 Vin，并保持到主机逻辑复位。48 bit 参数经请求与确认传到 31.25 MHz 用户域；每次 2 µs 事件提供一次四拍发送机会。

### 7.1.2 接口列表

| 信号 / 分组 | 方向 | 位宽 | 功能 |
| --- | --- | --- | --- |
| clk_250m / rst_n | 输入 | 各 1 | 参数源域与逻辑复位 |
| cfg_byte / cfg_byte_valid | 输入 | 8 / 1 | 编号及接受脉冲 |
| tick_toggle_2us | 输入 | 1 | 每 2 µs 翻转一次的事件标志 |
| user_clk / user_reset / channel_up | 输入 | 各 1 | 用户时钟、核复位与链路状态 |
| tx_ready | 输入 | 1 | 核接受发送数据 |
| tx_data / tx_rem | 输出 | 32 / 2 | 四拍数据与 REM=3 |
| tx_sof / tx_eof / tx_valid | 输出 | 各 1 | 首末拍与有效 |
| configured / configured_id | 输出 | 1 / 8 | 参数跨域完成与首个合法编号 |
| skipped_periods | 输出 | 32 | 忙或反压时跳过的发送机会数 |

### 7.1.3 接口时序

首次 cfg_byte_valid 且编号在 1～10 时，源域保存 cfg_hold={Vin,duty} 并提出 cfg_req。参数保持至确认返回，目的域整体保存 cfg_user。configured 表示主机内部跨域完成，不代表子机已经收到数据。

tick_toggle_2us 经两级同步后与前拍值异或，形成 period_tick。链路或用户复位失效时停止当前帧；条件恢复后等待四个用户时钟，再由下一次有效事件启动。

@FIG oneg_frame|1G 四拍参数帧与有效字节排列

| 状态 | 数据 / 标志 | 转移条件 |
| --- | --- | --- |
| IDLE=0 | tx_valid=0 | period_tick 到来且 tx_ready=1 |
| FIRST=1 | Byte0～3，SOF=1，EOF=0 | tx_ready=1 |
| SECOND=2 | Byte4～7，SOF=0，EOF=0 | tx_ready=1 |
| THIRD=3 | Byte8～11=0 | tx_ready=1 |
| FOURTH=4 | Byte12～15=0，EOF=1 | tx_ready=1 后回空闲 |

valid 有效而 ready 为低时，当前数据、状态和标志保持。事件到来时若仍在发送或接口不能启动，该次机会跳过，不排队补发；末拍握手与新事件同拍时，仍按事件到来前的忙状态处理。

### 7.1.4 功能设计

| Byte1 编号 | duty 原始值，16 bit | Vin 原始值，32 bit |
| --- | --- | --- |
| 1 | 3000 | 0x00500000 |
| 2 | 5000 | 0x00500000 |
| 3 | 8000 | 0x00500000 |
| 4 | 2000 | 0x00C00000 |
| 5 | 3000 | 0x00C00000 |
| 6 | 5000 | 0x00C00000 |
| 7 | 8000 | 0x00C00000 |
| 8 | 3000 | 0x01800000 |
| 9 | 5000 | 0x01800000 |
| 10 | 8000 | 0x01800000 |

非法编号不启动参数传递，也不影响同一批数据的 10G 原样发送。参数已保存后，再收到合法编号也不会覆盖首组值。Vin 按电压乘以 1,048,576 的整数编码；帧内保留该 32 bit 原始值。

| 拍 | 按 tx_data[31:24] 至 [7:0] 排列 | 帧标志 |
| --- | --- | --- |
| 0 | duty[7:0]、duty[15:8]、Vin[7:0]、Vin[15:8] | SOF=1，EOF=0，REM=3 |
| 1 | Vin[23:16]、Vin[31:24]、0xF0、0x00 | SOF=0，EOF=0，REM=3 |
| 2 | 0x00、0x00、0x00、0x00 | SOF=0，EOF=0，REM=3 |
| 3 | 0x00、0x00、0x00、0x00 | SOF=0，EOF=1，REM=3 |

字段内部低字节在前，单拍先发字节放在 tx_data 高位。编号 1 对应 duty=0x0BB8、Vin=0x00500000，四拍分别为 0xB80B0000、0x5000F000、0x00000000、0x00000000。

skipped_periods 只在已配置、已建链且恢复等待结束后统计忙或反压造成的跳过，自然回绕；未配置或断链期间不增加。主机逻辑复位清参数及统计；1G 用户复位或断链只中止在途帧并重新等待，参数继续保留。这些观察量没有映射为软件寄存器。

### 7.2.1 规格概述

该模块提供单 lane Aurora 8B/10B、1.25 Gb/s 线路与 32 bit 用户接口。参考时钟为 125 MHz，用户时钟为 31.25 MHz。主机只连接其发送业务，接收数据未参与业务控制。

| tx_data / tx_rem / tx_sof / tx_eof / tx_valid | 输入 | 32 / 2 / 1 / 1 / 1 | 四拍发送接口 |

## 7.3 RTDS_SYNC_TIMEBASE 同源计时模块

### 7.3.1 规格概述

同源计时模块在 250 MHz 域生成 2 µs 翻转事件与 50 µs GPIO。两个计数器共用时钟与复位，因此源域相位关系固定。

### 7.3.2 接口列表

| 信号 | 方向 | 位宽 | 功能 |
| --- | --- | --- | --- |
| clk_250m / rst_n | 输入 | 各 1 | 250 MHz 与低有效复位 |
| tick_toggle_2us | 输出 | 1 | 500 拍翻转一次 |
| cpu_sync_50us | 输出 | 1 | 12,500 拍周期，高低各 6,250 拍 |

### 7.3.3 接口时序

复位时 GPIO 为低，计数清零。复位解除后的首个有效更新沿，旧计数为 0，事件翻转且 GPIO 变高。之后每 500 拍翻转一次事件；GPIO 在半周期边界变低，完整周期边界再次变高。

### 7.3.4 功能设计

2 µs 计数使用 9 bit，范围为 0～499；50 µs 计数使用 14 bit，范围为 0～12,499。GPIO 为寄存输出，不将组合计数比较直接接到板级引脚。

cpu_sync_50us 连接 AM11 / TEST3，采用 LVCMOS33。该输出作为 CPU 异步 GPIO 输入，输出时序约束不按 CPU 外部时钟建立数据接口关系。主机源域相位固定，不代表 CPU 调度和子机计算在同一时刻开始。

# 8 辅助模块与外部接口

## 8.1 TEMP_RD 温度采集模块

### 8.1.1 规格概述

TEMP_RD 通过 sys_mon DRP 取得原始温度值。SYS_CLK=250,000,000，RD_TEMP_CYCLE=1000 µs；温度只用于状态读取，不控制收发或同步计时。

### 8.1.2 接口列表

| 信号 | 方向 | 位宽 | 功能 |
| --- | --- | --- | --- |
| sys_clk / sys_rst | 输入 | 各 1 | 250 MHz 与高有效复位 |
| busy | 输出 | 1 | 计时产生的采集窗口指示 |
| temp | 输出 | 16 | sys_mon DRP 原始输出 |

### 8.1.3 接口时序

计数周期为 250,000 拍。旧计数到 CYCLE−10 时，den_in 与 dwe_in 置位一拍；最后 10 拍 busy 为 1。TOP 再将 {15'd0,busy,temp} 寄存后交给 INFO_EXCH。

### 8.1.4 功能设计

daddr_in 与 di_in 为 0，drdy_out 不参与完成判定。busy 表示模块的计时窗口，不是严格 DRP 读完成标志。0x0C.bit15:0 为温度原始值，bit16 为 busy；采集与寄存均在业务时钟域。

## 8.2 LED 运行指示模块

### 8.2.1 规格概述

LED 模块使用 250 MHz 时钟产生 1 s 完整电平周期，表示主逻辑计数运行。该输出不代表 PCIe、DDR4 或 Aurora 已就绪。

### 8.2.2 接口列表

| 信号 | 方向 | 位宽 | 功能 |
| --- | --- | --- | --- |
| i_sys_clk / i_sys_rst | 输入 | 各 1 | 250 MHz 与高有效复位 |
| o_led | 输出 | 1 | 接至 AP11，LVCMOS33 |

### 8.2.3 接口时序

复位时 o_led=1，计数清零。每 125,000,000 拍翻转一次输出，即高低各 0.5 s。

### 8.2.4 功能设计

计数器与输出寄存器均在同一业务域运行。LED 与 AM11 的同步 GPIO 使用不同输出，不共享计时计数器。

## 8.3 VIO 与 ILA 辅助逻辑

VIO 提供 start 控制与状态观察，ILA 观察 FDMA、链路及存储相关信号。两者不修改业务寄存器的块数量，也不代替 DDR4 写响应。

RX_VIO_TEST_ENABLE=1 时，RTDS_RX_VIO_STIM 在 start 上升沿、存储就绪且有空块时启动，等待块周期事件后依次送出低 32 bit 为 0x11、0x22 的两个输入字。数据按 ready 握手，通过块写入器形成 8 Byte 数据：11 00 00 00 22 00 00 00。发生器等待成功块登记后结束，异常时保持 fault，直至逻辑复位。

| 辅助单元 | 连接位置 | 作用 |
| --- | --- | --- |
| VIO 与数据发生器 | 块写入器输入侧，250 MHz | 控制固定数据输入，观察忙、故障及接受状态 |
| ILA | FDMA 与链路状态信号 | 观察请求、数据和模块状态，不控制事务推进 |

## 8.4 CPU 与板间接口

| 交互 | 主机 FPGA 提供 | 对接条件 |
| --- | --- | --- |
| CPU 下行 | 32 KiB 窗口、地址长度寄存器与启动位 | H2C 完成后提交，执行期间保持载荷 |
| CPU 上行 | 可读块数、队头地址、长度、序号与确认 | 按有效长度完成 C2H 后确认一次 |
| CPU 通知 | 队列通知与异常状态 | 清通知不释放块，已有块连续处理 |
| CPU 同步 | 50 µs、3.3 V GPIO | 上升沿作为节拍，不能作为结果就绪标志 |
| 子机 10G | 16 Byte 两拍下行；接收有效拍低 32 bit 入块 | 双方保持相同字节定义；上行 DDR4 不保存线路帧标记 |
| 子机 1G | 四拍参数帧与 Byte6=0xF0 标识 | 按完整 16 Byte 解释 duty 与 Vin |

CPU 的 DMA 完成与 MMIO 访问需要保持先后顺序：下行数据写完再启动，接收数据读完再确认。确认前保存队头信息，避免多个读取流程分别确认同一块。

50 µs GPIO 只连接 CPU，不通过 Aurora 发送同周期同步帧。1G 参数帧携带参数与同步标识，没有子机执行回执；10G 本地发送完成也不作为子机计算完成的判断。
