# RTDS 驱动与主机单机联调：上、下行完整操作步骤

日期：2026-10-13。当前只有驱动和主机 FPGA，没有子机。本文的“软件操作”由驱动同事使用现有调试工具或接口完成，不要求业务应用参与。

**下行先做 H2C 写 DDR，再做 C2H 回读，长度均为 `0x10`；上行由 VIO 产生固定数据，再按原寄存器流程读取、比对和归还。两项可独立执行，本轮建议先下行、再上行。**

## 1. 准备与地址约定

| 项目 | 配置／要求 |
|---|---|
| 远程工程 | `C:\project\RTDS\DDR\RTDS_test_DDR4_64bit_batch_dev` |
| FPGA 程序 | 手动完成本次修改的综合、实现和 bit 生成，下载匹配的新版 bit/ltx |
| 测试参数 | `RX_VIO_TEST_ENABLE=1`：上行接 VIO 固定数据源；下行和 BAR 协议保留。设为 0 后重新生成 bit 才恢复原 Aurora/FIFO 上行 |
| VIO 实例 | `u_pcie/G_RX_VIO.U_VIO_RX_START`；Hardware Manager 须能看到它。版本常量未因本次修改而更新，不能独自证明已下载新版 bit |
| 软件能力 | 用户 BAR 32bit 小端读写、H2C DMA、C2H DMA、完成等待和错误返回；只有 BAR 读写接口不足以完成数据比对 |
| 就绪条件 | 软件读取 `0x2C`，要求 `(value & 0x3)==0x3`，即 DDR 业务就绪且校准完成 |
| 初测方式 | 业务采用轮询；建议间隔 1ms、状态等待上限 500ms。这是联调建议，不是 RTL 固定超时；DMA 等待使用驱动接口，不能用固定延时替代 |
| 操作归属 | 一条软件流程管理上行取块与归还；`0x10` 清通知也由一方统一处理。DMA 缓存同步和 MMIO 顺序由驱动保证 |

三个地址不要混用：

- **BAR 偏移**：`0x24` 等，相对驱动映射的用户 AXI-Lite BAR。
- **卡端 DDR 字节地址**：下行本例 `0x8000`，上行使用 `0x18` 返回值，传给 DMA 接口。
- **CPU 缓冲区**：驱动分配或映射的 DMA 缓冲区，不能直接用卡端地址代替。

以下函数名称仅表示操作，不是现有驱动命令名：`read32(offset)`、`write32(offset,value)`、`H2C(card_addr,buf,len)`、`C2H(card_addr,buf,len)`。

## 2. 共用启动检查

| 顺序 | FPGA／硬件操作 | 软件操作与检查 |
|---:|---|---|
| 1 | 连接主机 FPGA 与 RK3588，下载新版 bit/ltx，打开 Hardware Manager | 在 RK3588 确认 PCIe 枚举、驱动绑定及用户 BAR 映射；复位或重下载后重新确认这些状态 |
| 2 | 确认新增 VIO 存在，将 `probe_out0` 提交为 0 | 读取 `0x00=0x00002001`、`0x04=0x20260914`、`0x08=0x00040000` |
| 3 | 查看 DDR 校准和 VIO 就绪状态 | 等待 `0x2C[1:0]=3`；保存 `0x2C`、`0x38` 作为基线 |
| 4 | 保持 VIO start=0，不触发数据 | 如 `0x2C[4:2]` 非零，先保存状态，再读一次 `0x10` 清相关记录，复查；未消除的错误先定位，不继续记通过 |

本轮数据测试预期无新 AXI 错误、溢出或超时，即 `0x2C[4:2]=0`；`0x38` 丢字计数不增加。

## 3. 下行：写入 16Byte，再回读 16Byte

### 3.1 固定配置

```text
CARD_ADDR = 0x00008000
LEN       = 0x00000010       // 16Byte，H2C与C2H均用这个长度
TX_BUF    = 00 01 02 03 04 05 06 07 08 09 0A 0B 0C 0D 0E 0F
RX_BUF    = A5 A5 A5 A5 A5 A5 A5 A5 A5 A5 A5 A5 A5 A5 A5 A5
```

读缓冲区先填 `A5`，便于发现 DMA 没有更新缓冲区。按小端 32bit 解释，回读应为 `0x03020100、0x07060504、0x0B0A0908、0x0F0E0D0C`。

### 3.2 执行顺序

| 顺序 | FPGA／硬件操作 | 软件操作 | 预期／判定 |
|---:|---|---|---|
| D1 | 保持 VIO start=0；本测试不需要子机 | 轮询 `0x20.bit0=0`，保存原 `0x24/0x28` | 下行空闲才配置 |
| D2 | 保持主机 DDR、PCIe 就绪 | 写 `0x24=0x00008000`、`0x28=0x00000010`，分别读回确认 | 地址、长度一致；`0x20` 仍为 0，配置本身不启动发送 |
| D3 | 无需点击 VIO | 准备上面的 TX_BUF、RX_BUF；使用驱动要求的 DMA 缓冲区与对齐 | 两个缓冲区分开，实际可访问长度均至少 16Byte |
| D4 | FPGA 接收 H2C，写入真实 DDR | 执行 `H2C(0x8000, TX_BUF, 0x10)`，等待 DMA 完成，检查错误及完成字节数 | 驱动报告成功，完成 16Byte |
| D5 | FPGA 从同一 DDR 地址返回数据 | 执行 `C2H(0x8000, RX_BUF, 0x10)`，等待 DMA 完成及必要缓存同步 | 驱动报告成功，完成 16Byte |
| D6 | — | 比较全部 16Byte；不一致时打印偏移、期望值、实际值 | 与 TX_BUF 逐字节一致，不能只比较一个字 |
| D7 | — | 读取 `0x24/0x28/0x20/0x2C`，保存结果 | 配置仍为 `0x8000/0x10`、忙位为 0、无新异常 |

**D1～D7 是当前无子机条件下的必做流程。通过结论写为“下行 DDR 区域 H2C 写入、C2H 回读及 BAR 配置通过”。**

此过程不产生软件 `0x20=1` 启动命令，也不依赖 Aurora。当前 FDMA ILA 观察业务 adapter 的访问，CPU 直接 H2C/C2H DDR 搬运不一定在该 ILA 中出现活动；其没有触发不能据此判失败。

### 3.3 `0x20` 提交命令：本轮可选检查

若驱动还需要检查启动寄存器，则在 D6 数据比对通过后：

1. 再确认 `0x20=0`，`0x24=0x8000`、`0x28=0x10`。
2. 向 `0x20` 写 32bit 值 1 一次，无需先写 0。
3. 轮询 `0x20.bit0`，记录最终回到 0；不要求软件一定采到中间的 1。
4. 保存 `0x2C`、驱动日志和硬件观察结果。超时则停止并定位。

**无子机且 10G 未建链时，任务可能被拒绝或中止；回到 0 只能记“启动后返回空闲”，不能记发送成功。** 完整下行发送须后续建链，由对端比对 1 个 16Byte 帧、2 个 64bit 有效拍及内容。VIO 上行激励不会自动替下行产生发送数据。

有效下行限制：地址 16Byte 对齐，长度为正且为 16Byte 整倍数、最大 32KiB，地址加长度不超过 `0x10000`。本例 `0x8000/0x10` 满足限制；忙时修改配置或重复启动会被忽略。

## 4. 上行：VIO 触发，读取并归还一个 8Byte 块

### 4.1 VIO 和固定数据

| 探针 | 含义 | 触发前要求 |
|---|---|---|
| `probe_out0` | start，0→1触发一次 | 先提交0，稍后再提交1 |
| `probe_in0` | busy：等待周期、发送及等真实块完成 | 0 |
| `probe_in1` | 本次已接受输入字数：0、1、2 | 首次为0；上次完成后可保持2 |
| `probe_in2` | bit0 DDR就绪；bit1 PCIe就绪；bit2 fault；bit3通知请求 | bit0、bit1为1，bit2为0 |
| `probe_in3` | 可读块数：0～8 | 本次单块测试先为0 |

发生器送两个输入拍，低 32bit 分别为 `0x11`、`0x22`；writer 拼成 `64'h00000022_00000011`。有效长度为 **8Byte**，CPU预期字节为：

```text
11 00 00 00 22 00 00 00
```

### 4.2 执行顺序

| 顺序 | FPGA／硬件操作 | 软件操作 | 预期／判定 |
|---:|---|---|---|
| U1 | 暂不触发，保持 start=0 | 读 `0x30`，本次要求为0；保存 `0x24/0x28`、`0x2C/0x38` | 上行不写 `0x20/0x24/0x28`。若有旧块，先正常读取、归还，不盲写 `0x14` 清空 |
| U2 | 确认上表条件；FDMA ILA设 `fdma_wareq=1`，点击 **Run Trigger** | 开始准备轮询 `0x30`；初测不依赖用户中断 | 先使 ILA 等待，再操作触发 |
| U3 | 将 VIO start 提交为1 | 轮询 `0x30`，建议1ms一次、500ms上限，不循环读取 `0x10` | busy先为1，已接受字数变为2；保持start=1不重复 |
| U4 | ILA应看到一次写请求：`fdma_wsize=1`、`fdma_wdata=00000022_00000011`；块登记后busy变0 | 等 `0x30=1`，读取 `0x18/0x1C` | 长度为8；复位后首块地址为`0x100000`，以后使用`0x18`返回地址，不硬编码下一块 |
| U5 | start保持1 | 先保存 `0x2C` 和 `0x38`，再读一次 `0x10` 保存通知并清通知；复读 `0x30/0x18/0x1C` | 块数仍为1，地址、长度不变。若没有其他清通知者，读到的通知bit0应为1；是否有块始终看`0x30` |
| U6 | — | 从`0x18`返回地址执行 C2H，读取`0x1C`有效长度；等待 DMA 完成及缓存同步，比对全部8Byte | 数据为`11 00 00 00 22 00 00 00` |
| U7 | — | DMA完成且比对通过后，向`0x14`写32bit值1 **一次**；最低字节写使能有效 | 无需再写0；不要通过读回`0x14`判断归还；重复写可能归还更多块 |
| U8 | 不产生新触发 | 读取`0x30/0x18/0x1C/0x2C/0x38`，复查`0x24/0x28` | 块数、地址、长度回0；无新异常或丢字；下行配置未变 |
| U9 | 再次测试：busy=0后，先提交start=0，再提交start=1 | 重复U3～U8 | 每次一个独立8Byte块；归还后按硬件返回的新地址读取 |

发生器先等原 writer 周期到期，再发送两个字并等后一个周期登记块。生产周期为 250MHz、25,000,000 拍，即100ms；**从触发到块可读约100～200ms，加剩余写响应处理时间**。已接受字数为2不代表DDR成功，单独看到ILA写数据也不代表块可读。

优先按有效长度8Byte读取。若现有DMA工具只支持16Byte，先确认驱动的长度与对齐规则；本次固定测试可从同一块基址读取16Byte，但仅前8Byte有效并参与比对，后8Byte没有规定值。`0x1C`仍记录8，不能把填充字节算作有效数据。

多块时：读`0x30`得到N → 连续N次“读地址/长度→C2H完成→写`0x14=1`” → 再读`0x30`，继续至0。`0x34`仅用于可选顺序日志，不能用其是否为0判断队列为空。

## 5. 中断专项与故障处理

第一轮用轮询；DMA完成仍使用驱动原有机制。若关闭通知中断，只针对XDMA用户通知源，不应整体禁用DMA完成所需的中断。

单独测用户MSI时，顺序为：**队列为空→驱动注册并使能用户中断、开始等待→ILA等待触发→VIO start=0→1→收到中断→保存0x2C、读0x10清通知→按0x30取块→C2H完成后写0x14归还。** 清通知和归还各由一方管理；中断次数不是块数，读清后队列仍非空时不能只等下一次中断，应处理至空并用0x30轮询兜底。

DMA失败、数据不一致、等待超时或VIO fault=1时，先保存寄存器、VIO、ILA和驱动日志，停止本次流程；不要继续写0x14。注入fault保持到全局复位，复位／重下载后重新做启动检查。
