# RTDS 当前软件联调推荐配置与操作顺序

适用：2026-10-13最小VIO修改版，工程 `RX_VIO_TEST_ENABLE=1`。上、下行可分别测试；二者共享PCIe、DDR和复位，建议本轮串行执行，便于定位。VIO只产生上行数据，下行数据仍由CPU H2C DMA写入。

当前无子机，可以完成VIO上行写DDR、通知、C2H读取和逐块归还。完整下行发送需要10G Aurora建链及对端检查；仅做H2C/C2H DDR比对不能记作子机收数通过。

## 共用配置

| 项目 | 推荐值或要求 |
|---|---|
| FPGA程序 | 先手动完成综合、实现、生成并下载匹配的新版bit/ltx；Hardware Manager能看到 `u_pcie/G_RX_VIO.U_VIO_RX_START` |
| PCIe/BAR | 在RK3588确认枚举、驱动和用户AXI-Lite BAR；32bit小端MMIO，偏移相对用户BAR |
| 固定读值 | `0x00=0x00002001`、`0x04=0x20260914`、`0x08=0x00040000`；这些常量未因VIO修改而更新，不能独自证明下载了新版bit |
| 就绪 | 业务前要求 `(read32(0x2C)&3)==3`；VIO状态bit0、bit1也须为1 |
| 初测方式 | 业务先轮询，建议间隔1ms、单次等待上限500ms；此为软件联调设置，不是RTL周期参数。DMA完成按驱动接口等待，不能用固定延时替代 |
| 异常与丢字 | 保存 `0x2C` 和 `0x38`；预期 `0x2C[4:2]=0`、`0x38`不增加。需要清通知/相关异常时，先保存 `0x2C`，再读 `0x10` |
| 访问归属 | 一条流程管理上行地址、长度、DMA和归还；驱动保证DMA完成、缓存同步及MMIO顺序。清通知也统一由一方处理 |

DDR卡端地址（例如0x8000、0x100000）用于DMA，不是CPU BAR映射地址。

## 上行：硬件触发与软件读取按此顺序

| 步骤 | 硬件操作 | 软件操作及检查 |
|---:|---|---|
| 1 | 下载新版bit/ltx并确认VIO存在；start先提交0 | 完成共用检查，先读 `0x30`。首次测试要求队列为空；若已有块，按正常DMA读取、归还流程处理，不重复盲写 `0x14` 清空 |
| 2 | VIO `probe_in0=0`（空闲）；`probe_in2[1:0]=3`（DDR/PCIe就绪），bit2=0（无注入错误） | 保存下行 `0x24/0x28`、异常状态及 `0x38` 基线；上行全程不写 `0x20/0x24/0x28` |
| 3 | FDMA ILA以 `fdma_wareq=1` 执行Run Trigger，然后VIO start提交1 | 开始轮询 `0x30`，不循环读 `0x10`；单次建议500ms上限 |
| 4 | busy先为1；已接受字数变为2；等待真实块登记后busy为0。生产周期100ms，触发至块完成约100～200ms加剩余写响应时间 | 单次触发从空队列开始，预期 `0x30=1`、`0x1C=8`。读取 `0x18`作为DMA卡端地址，复位后首块为0x100000；后续块不要硬编码地址 |
| 5 | start保持1不重复发送 | 保存 `0x2C`、`0x38`；读取 `0x10`保存通知并清通知。此后仍须 `0x30=1`，`0x18/0x1C`保持；是否有块始终看 `0x30` |
| 6 | — | C2H从 `0x18`返回地址读取 `0x1C`有效字节，并等待驱动报告完成；本例期望 `11 00 00 00 22 00 00 00` |
| 7 | — | 比对和DMA完成后，向 `0x14`写32bit值1一次，最低字节写使能有效；无需再写0，也不靠读回0x14判完成 |
| 8 | — | 本次无新触发，预期 `0x30=0`、`0x18/0x1C=0`；`0x38`不增加、`0x24/0x28`与基线一致 |
| 9 | 再测时确认busy=0，再提交start=0→1 | 重复步骤3～8。每块一次确认；不要因为一次中断只处理一块 |

多块时：读0x30得到N；连续N次读取0x18/0x1C→C2H完成→写0x14=1；再读0x30，继续直到0。0x34仅用于可选顺序日志，不能用它是否为0判断队列空。

中断专项另跑：先让队列为空，再注册、启用XDMA用户中断并开始等待，最后操作VIO start。驱动接到中断后先保存0x2C、读0x10清通知并通知应用；应用仍按0x30取块，DMA完成后才归还。驱动与应用不得重复清通知或重复归还。中断次数不等于块数；读清后队列仍非空时，后续块到达也可能不产生新通知，必须把队列处理至空，并保留0x30轮询兜底。用户通知中断与DMA完成事件分别处理。

若VIO fault=1或超时，先保存VIO、寄存器和驱动日志，停止当前测试。注入fault需全局复位后重试；复位/重下载后重新确认枚举、驱动和BAR。不要用写0x14冒充DMA已完成。

## 下行：推荐从16Byte开始

| 项目 | 推荐值 |
|---|---|
| 卡端起始地址 | `0x00008000` |
| 长度 | `0x00000010`，即16Byte |
| 按地址递增的测试字节 | `00 01 02 03 04 05 06 07 08 09 0A 0B 0C 0D 0E 0F`；Byte1=1为合法首次配置编号 |
| 通路条件 | DDR、PCIe就绪；完整发送还需要硬件确认10G Aurora已建链、对端可以接收 |

执行顺序：

1. 轮询 `0x20.bit0=0`。
2. H2C DMA将16Byte写入卡端DDR 0x8000，并等待驱动报告写完成。可先C2H读回比对，确认主机侧DDR搬运。
3. 向 `0x24`写0x8000、`0x28`写0x10，读回确认。
4. 10G对端就绪后，向 `0x20`写1一次，轮询直到bit0回到0；该任务可能很快结束，不要求软件一定采到中间的1。
5. 硬件/对端检查1个16Byte帧、2个64bit有效拍及16Byte内容；保存异常和丢字状态。仅0x20回0不能证明发送成功，它也可能因拒绝或链路中止而回0。

暂时没有子机或可控10G对端时，完成步骤1～3和DDR读回即可，记录为“BAR及H2C/C2H DDR检查”；完整下行发送待对端具备后执行。

有效下行限制：地址16Byte对齐、长度为正且16Byte整倍数、长度不超过32KiB，地址范围0x8000～0xFFFF，地址+长度不超过0x10000。忙时重复启动、修改0x24/0x28不会形成正常新任务。

## 本轮判定和记录

上行通过至少包括：单次触发一块8Byte、数据一致、读清不释放、一次确认一块、归还后为空、丢字不增加、下行配置不变。BAR-only检查只覆盖动态状态，尚未DMA比对时不能记上行数据通过。

保存bit/ltx标识、固定寄存器读值、触发次数、块地址/长度、C2H比对、确认次数、0x2C/0x38及驱动错误日志；中断专项另保存实际用户中断记录。模块冒烟已通过不替代本轮板级结果。
