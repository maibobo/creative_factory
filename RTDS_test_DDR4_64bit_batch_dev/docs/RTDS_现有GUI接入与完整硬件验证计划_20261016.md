# RTDS 现有GUI接入与完整硬件验证计划

本轮沿用远程机已经打开的Vivado和ARM终端，不增加前台窗口，不启动第二个Vivado。验证过程中双方串行操作：助手执行时，人工观察，不同时点Trigger或VIO start。

## 1. 在现有GUI接入

已连接实验板、关联配套LTX后，在同一个Tcl Console执行：

~~~tcl
source C:/project/RTDS/DDR/RTDS_test_DDR4_64bit_batch_dev/debug/hardware_joint_lab_20261016/vivado/gui_bridge.tcl
::rtds_gui::start
~~~

出现GUI_BRIDGE_READY表示接入成功。source只定义命令，start才检查所选设备并启动桥接。桥接每秒检查一次请求，空闲时不读取硬件；不重新连接目标、不下载bit、不复位、不清历史。命令限定为inspect、snapshot、arm、inject、save、stop。

VIO状态和各步执行结果在当前Tcl Console打印；可在现有VIO面板刷新查看。save会把采集结果保存为CSV/ILA，并显示在同一Vivado的波形视图。首次DMA读写、单块上行采波形；多块环回主要看VIO、队列和数据结果，避免低性能电脑产生过多波形标签。

结束接入可以执行：

~~~tcl
::rtds_gui::stop
~~~

只停止桥接轮询，保持现有GUI和硬件连接。故障时先保留现场，不重新下载或清历史。

## 2. 在已有ARM终端观察

助手运行带--live-log的PC入口时，ARM侧会持续追加日志。已有ARM终端可执行：

~~~sh
tail -F /root/rtds_joint_lab_20261016/live_status.log
~~~

Ctrl+C仅停止tail观察；不会停止另一个SSH通道里的实验。人工不要同时再启动测试程序、清通知或归还块。

## 3. 当前板内验证

| 项目 | 动作与判据 |
|---|---|
| 环境、寄存器 | 检查BDF/驱动/节点、固定寄存器、DDR就绪；起步队列空 |
| 配置回读 | 两组合法配置写回，随后恢复原值，保持下行不启动 |
| DDR闭环与原生ILA | H2C/C2H各16Byte，逐字节一致；分别在操作前布防，保存两次波形 |
| VIO单块上行与FDMA ILA | 一次注入、长度8Byte、数据1100000022000000；读清不释放，数据正确后一次归还 |
| 多块排队、环回 | 依次2块、8块、2块，逐块用返回地址读数据；顺序连续、覆盖8槽，无新错误和丢字 |

每次下载bit后重新做环境检查。2026-10-16本次现场发生BAR全FFFFFFFF：PCIe配置空间中的BAR地址和Command已随重配置清零，而Linux仍保留旧设备记录。对FPGA端点0000:01:00.0移除并重扫后，原xdma驱动重新分配BAR、启用访问，寄存器恢复正常。该操作记录在validation/post_bit_endpoint_recovery.json；没有修改内核/驱动文件。

不得仅因lspci仍列出10ee:8032就判定BAR和DMA可用。遇到全FFFFFFFF先保存PCI配置、资源和日志，再检查；不要向无效映射发DMA或归还。
