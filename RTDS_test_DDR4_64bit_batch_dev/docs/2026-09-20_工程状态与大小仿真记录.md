## 10. MIG实现阶段两次时钟修改错误与最终修复

本节保留两次失败过程，避免以后重复采用已经证伪的时钟连接。

### 10.1 第一次失败：差分负端AK16缺少显式管脚约束

- 现象：`impl_1`在`opt_design`的MIG Core Generation阶段报`Mig 66-99`，指出`c0_sys_clk_p/c0_sys_clk_n`未放置或时钟结构不受支持。
- 根因：板上100MHz差分时钟为AK17/AK16，但`PIN.xdc`只约束了`clk_p → AK17`，没有显式约束`clk_n → AK16`。综合不会完成MIG物理时钟合法性检查，所以顶层综合可以通过，错误只在实现阶段出现。
- 正确修改：在`PIN.xdc`中增加`set_property PACKAGE_PIN AK16 [get_ports clk_n]`，正负端继续使用相同的`DIFF_HSTL_I_12`。

### 10.2 第二次错误修改：把No_Buffer MIG接到Clock Wizard输出

- 错误做法：为绕过第一次`Mig 66-99`，曾把TOP中的`ddr_sys_clk_i`从共享IBUFDS输出`clk_100m_ibuf`改接到Clock Wizard输出`clk_100m`。
- 新现象：GUI手动实现能够完成`link_design`并取得Implementation许可证，但`opt_design`再次报`Mig 66-99`，明确指出用户MMCM/PLL级联MIG MMCM在当前高速配置下不受支持，随后报`Opt 31-306 MIG Core Generation Failed`。
- 根因：MIG配置为`System_Clock=No_Buffer`。`clk_100m`来自Clock Wizard内部MMCM/PLL和BUFG，接入MIG后形成用户MMCM→MIG MMCM级联；DDR4-2400下该结构因抖动不满足PG150要求。
- 最终修复：TOP恢复`.ddr_sys_clk_i(clk_100m_ibuf)`。AK17/AK16只经过一个共享IBUFDS；该IBUFDS输出一支送Clock Wizard，另一支直接送`No_Buffer` MIG。禁止在MIG支路前插入Clock Wizard、MMCM或PLL。
