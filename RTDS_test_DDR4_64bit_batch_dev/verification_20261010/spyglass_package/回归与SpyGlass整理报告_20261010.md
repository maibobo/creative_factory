TOP lint 与 CDC setup 的共同单条 Error 是 XPM `u_cdc_pcie_link_to_fdma.src_ff` 的恒定时钟。该实例 `SRC_INPUT_REG=0` 且 `src_clk=1'b0`，输出只使用 `src_in` 和目的同步级；原 XPM 仍定义未使用的 `src_ff`，工具未消去它。应按未使用逻辑/模型告警审查，不能据此判定目的同步器缺失。本包保留原 XPM，没有用 waiver 隐藏这项。

结构报告中的 `u_cdc_pcie_link_to_user.src_ff` 也来自 `SRC_INPUT_REG=0` 时未使用的输入寄存器；真正输出路径直接进入 Aurora 用户域的目的同步级。应与上述模型告警一并分类。

全 TOP 还需重点处理或确认：

- `CLK_GEN` 将 Clock Wizard `locked` 反相为 `sys_rst`；部分业务过程直接使用该信号作为同步复位条件。需检查各域复位解除和包装层覆盖，不能仅因频率相同便忽略报告。
- RX writer 的保持型 `irq` 从业务 `clk_250m` 直接到 XDMA `usr_irq_req` / `axi_aclk` 边界；需要确认两时钟关系或补足目标域同步/握手契约。
- DDR `ready_sync` 是两级同步结构，但以 `s_axi_aresetn` 同步复位；SpyGlass 报 `Sync reset used in multi-flop synchronizer`，需结合复位假设审查，不能直接等同于没有两级同步。
- Aurora 输出复位、异步 FIFO reset、MIG 校准/复位与 GT 物理输入属于模型契约或 IP 边界审查项；物理串行引脚的虚拟输入时钟告警不代表这些引脚需要普通 RTL 两级同步。
- Gray 计数解码与多个独立状态同步后的汇合报 Warning；当前结构目标的 Gray encoding check 为 disabled，后续应做针对性检查。

## Linux Vivado 的取舍

建议先用已部署的包收敛自写逻辑和 IP 接口契约。Windows 现有 Vivado 已提供可读 RTL、BD wrapper 与 stub；安装 Linux Vivado 不会自动解密 IP，也不会自动写好跨域端口约束。AMD 的第三方 IP 流程允许以 stub 描述接口。[AMD 第三方工具流程](https://docs.amd.com/r/2023.2-English/ug896-vivado-ip/Third-Party-Synthesis-Flow)

当需求升级为 Linux VCS 的真实厂商 IP 动态仿真时，Linux Vivado 2020.2 才更方便：用 `compile_simlib -simulator vcs_mx` 编译兼容库，并导出对应仿真脚本，或使用兼容 Linux 环境已经编译好的库。Windows XSim 产物不能作为 Linux VCS 库使用。2020.2 官方说明中的 VCS 支持为 Linux，版本 Q-2020.03 及以后；当前虚拟机工具版本在此范围，但仍需核对安装平台/补丁和目标 IP 的仿真库组合。[Vivado 2020.2 compile_simlib](https://docs.amd.com/r/2020.2-English/ug835-vivado-tcl-commands/compile_simlib)、[导出仿真文件和脚本](https://docs.amd.com/r/2020.2-English/ug900-vivado-logic-simulation/Exporting-Simulation-Files-and-Scripts)

CDC 最终结论依赖正确的时钟、复位和 IP 边界契约；工具能执行与静态签核通过应分开记录。[Synopsys CDC 约束检查](https://www.synopsys.com/webinars/constraints-driven-cdc-and-rdc-verification.html)
