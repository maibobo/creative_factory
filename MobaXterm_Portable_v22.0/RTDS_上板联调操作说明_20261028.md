# MobaXterm Portable v22.0：RTDS 上板联调操作说明

本目录保留原始 MobaXterm v22.0 便携程序，并新增 RTDS 联调资料与操作说明。原始 EXE、插件、INI 和旧备份保持原样；这次只更新 Windows 本地 C:\project\RTDS\github 工作目录，不连接 GitHub、不提交或推送。

## 资料目录

- RTDS_joint_demo_20261027\：本轮提示窗口、Python/Tcl 源码、联调文档、实时事件、运行日志和 ILA/VIO 采样。
- linux_design_handoff_20261019_155820\hardware_joint_lab_20261016\：既有 ARM/Linux 联调资料及 C DMA 源码 arm\rtds_dma.c。
- 原始 MobaXterm_Personal_22.0.exe、CygUtils.plugin、MobaXterm.ini 与备份均未修改。

## 窗口分工

| 窗口 | 用途 |
|---|---|
| MobaXterm 的 ARM root 终端 | 运行只读寄存器监视器并记录 Linux 端变化 |

## 启动顺序

1. 打开 MobaXterm，连接 ARM Linux 192.168.50.10 的 root 会话。密码在交互提示中输入，不写进命令或日志。
2. 在 MobaXterm 终端启动寄存器观察窗口：

   python3 /root/rtds_joint_demo_20261027/arm/rtds_regs_watch.py --log /root/rtds_joint_demo_20261027/live_status.log

   该监视器只读安全寄存器，不轮询读清寄存器 0x10，不写 0x14，不提交 DMA。观察结束按 Ctrl+C。
3. 在远程 Windows 当前 Vivado Tcl Console 初始化 GUI 桥接及提示窗口：

   source C:/project/RTDS/DDR/RTDS_test_DDR4_64bit_batch_dev/debug/hardware_joint_demo_20261027/vivado/open_demo.tcl

   确认控制台返回本次 DEMO_READY_JOBS。如果独立提示窗没有显示，再执行：

   source C:/project/RTDS/DDR/RTDS_test_DDR4_64bit_batch_dev/debug/hardware_joint_demo_20261027/vivado/open_notice.tcl

   每次重开 Vivado 都要为当前会话重新启动桥接，不能复用旧 service.ready 文件。
4. 需要启动实板流程时，在远程 Windows PowerShell 使用工程中的规范运行副本：

~~~powershell
Set-Location 'C:\project\RTDS\DDR\RTDS_test_DDR4_64bit_batch_dev\debug\hardware_joint_demo_20261027'
python .\pc\demo_runner.py --jobs "C:/project/RTDS/DDR/RTDS_test_DDR4_64bit_batch_dev/debug/hardware_joint_demo_20261027/jobs/gui_<本次会话>" --events "C:/project/RTDS/DDR/RTDS_test_DDR4_64bit_batch_dev/debug/hardware_joint_demo_20261027/events/live_<唯一编号>.jsonl" --arm-dir /root/rtds_joint_demo_20261027 --exclusive --prompt-password
~~~

将 gui_<本次会话> 换成当前 Tcl 返回的实际目录，每轮使用新的事件文件名。--prompt-password 隐藏输入 ARM 密码；--exclusive 表示操作者已停止其他 XDMA 业务，不会自动停止外部程序。

## 观察内容与证据

- Linux 寄存器窗口：观察 0x30 队列数、0x18/0x1C/0x34 队头地址/有效长度/序号、0x38 丢字计数。0x14=1 只在数据读回并校验后归还一个块。
- Vivado VIO：看 rx_test_blocks_r、rx_test_accepted_r 和 rx_test_status_r。accepted=2 是两个 32 bit 输入字，不是两个块。
- ILA2：看上行 FDMA 请求、地址、数据和忙状态；ILA1：看 DMA AXI 的 VALID/READY、地址、数据和响应。需 VALID 与 READY 同拍为 1 才算握手。
- 实时提示窗读取本轮 events\live_<唯一编号>.jsonl，不直接操作硬件。慢速 8 块阶段约每个确认状态停留 2 秒；这是自动停留，不是等待人工按键。连续阶段更快。
- 本次 2026-10-27 实板记录为 VIO 固定源：16 Byte DDR 往返通过，慢速和连续各 8 块读回/比较/归还通过，队列最终为 0；保存 18 组 ILA 采样。该轮未接真实 Aurora 子机，不能当作真实链路或吞吐测试。

- Word 版日志解读：RTDS_joint_demo_20261027\docs\RTDS双日志详细解读与上板验证计划_20261027.docx。
