# 16Byte下行、1G独立周期发送、上行有效数据流缓存



| 通路 | 处理规则 |
|---|---|
| CPU→10G→子机 | 每个下行配置帧16Byte，主机原样透传；支持一次提交多个完整帧 |
| CPU配置→1G→子机 | 首次合法Byte1译码，独立发送6Byte参数；不发送Buck其他信号 |
| 子机→10G→DDR | 每个有效64bit拍只保存低32bit；DDR连续存放有效数据，不要求上行固定帧长 |
| DDR→CPU | 每100ms封存一块，CPU按实际有效长度读取并确认释放 |

**上行采用有效数据流模型。** Aurora封装继续处理线路成帧，业务缓存层依据接收有效信号收集低32bit，不再用“必须收到若干拍”决定是否存储。DDR不保存SOF/EOF，也不保留线路帧边界；软件按连续32bit数据序列处理。

### 1G发送

- 在31.25MHz用户时钟域每63拍产生一次发送机会，名义周期 **2.016µs**；删除原250MHz域500拍定时及周期事件跨时钟。
- 首次合法Byte1对应的48bit参数仍通过完整握手跨时钟，配置保持至主机逻辑复位。
- 6Byte载荷为小端`duty[15:0]`和`Vin[31:0]`，使用现有十组映射。
- 按verified封装发两拍：第一拍4Byte，第二拍高16bit为剩余2Byte，`REM=1`并结束帧。
- 忙时跳过新的周期任务；已经发起的有效拍保持至握手完成。链路恢复后继续按周期发送，不补发历史任务。
- 2.016µs是发送机会间隔；反压或掉线时，实际成功发送间隔可能超过3µs。

## 3. 上行DDR：先透传、写入前压缩

### 接收与压缩

- 10G接收端先将每个有效64bit拍送入异步FIFO，不按固定线路帧长组帧。
- DDR域取出数据后丢弃高32bit，按到达顺序紧凑拼接：
  `DDR写拍 = {后到的低32bit, 先到的低32bit}`。
- 不存无效高32bit，不在DDR中为其保留空洞。每个接收有效拍贡献4Byte有效长度。
- 当前接口约定有效拍的低32bit始终完整有效；高32bit的数值不参与合法性判断。
- FIFO满时继续消费线路输入，丢弃无法保存的32bit有效数据字并计数，不覆盖已缓存数据。

### 八块管理

- 保留100ms×8块，每块256KiB，上行地址仍为`0x00100000～0x002FFFFF`。
- 封存按DDR域100ms窗口进行，不等待线路EOF。边界到达后停止给当前块追加新数据，完成在途写事务再发布。
- 若封存时仅剩一个32bit数据字，发起低4Byte有效的64bit写拍，`WSTRB=8'h0F`；有效长度只增加4Byte。
- 将尾拍字节使能贯穿FDMA和AXI写通路；常规完整写拍为`WSTRB=8'hFF`。
- 只有成功写响应对应的数据才计入有效长度。写失败的数据计为丢失，后续写入从尚未提交的位置继续，避免CPU读取无效空洞。
- 空窗口不发布；块满后丢弃该窗口后续新数据，等待下一窗口。八块全部待取时不覆盖旧块。
- FIFO中的积压数据按实际进入DDR写窗口归属，块序号不代表精确采样时间。
- 实际有效长度为4Byte整数倍；不再沿用“每100ms固定2000个128Byte帧”的容量计算。

## 4. 寄存器与CPU交互

采用自动清零门铃，寄存器偏移保持不变；由于上行格式及统计单位改变，协议版本标为 **V2.01**，RTL版本值沿用工程编码方式更新为`0x00002001`。

| 偏移 | 最终语义 |
|---|---|
| `0x08` | 上行单块容量，固定`0x40000` |
| `0x10` | 通知状态，读清；不释放DDR数据 |
| `0x14` | CPU完成C2H后写1，硬件消费一次并清0 |
| `0x18/0x1C` | 最老待取块地址及实际有效字节数，确认前稳定 |
| `0x20` | 下行提交门铃：写1提交，整批10G末拍握手完成后清0 |
| `0x24/0x28` | 下行地址及长度；地址16Byte对齐，长度为16Byte整数倍，限制在32KiB下行窗口内 |
| `0x30` | 完整待取块数，0～8 |
| `0x34` | 非空块发布序号，每成功发布一块递增 |
| `0x38` | 累计丢失的**32bit有效数据字数**，32bit饱和计数 |

- `0x38`改名为`UP_DROP_WORD_CNT`。上行不再识别固定业务帧，因此不能继续称“丢帧数”；不额外增加寄存器。
- 丢失计数覆盖FIFO溢出、缓存无法接收及DDR写失败，按数据字计数，不重复统计。
- `0x14`一次有效写1最多释放一个当前队头；空队列确认不释放同拍新发布块。
- `0x20`提交时锁存地址和长度，忙期间重复写1不重复启动；软件等待清0再提交下一批。非法提交不访问DDR，消费后清0，软件须先检查地址和长度。
- 新队头通知优先于旧通知读清，避免并发确认导致中断丢失。
- CPU使用单一队列消费者：读通知→读取地址/长度→完成C2H→写确认。下行先完成H2C，再写提交门铃。

## 1. 总体数据通路

| 方向 | 路径 | 说明 |
|---|---|---|
| 下行 | CPU → XDMA(H2C) → DDR → CONV_DMA → TX异步FIFO → Aurora 10G | 16Byte 帧原样透传，不解析帧内容（除 Byte1 观测） |
| 下行(1G) | 首次合法 Byte1 → 参数译码 → 48bit握手CDC → 1G周期发送器 → Aurora 1G | 仅 6Byte 参数，单次配置锁存 |
| 上行 | Aurora 10G → RX异步FIFO → 低32bit压缩/八块管理 → CONV_DMA → DDR → XDMA(C2H) → CPU | 每有效64bit拍仅取低32bit，紧凑拼接写入 DDR |

## 2. DDR 地址映射（XDMA/CONV_DMA 映射低 4MiB）

| 区域 | 地址范围 | 容量 | 用途 |
|---|---|---|---|
| 下行窗口 | 0x00008000 ~ 0x0000FFFF | 32KiB | CPU 批量下发 16Byte 帧 |
| 上行窗口 | 0x00100000 ~ 0x002FFFFF | 2MiB（8块） | 上行数据缓存，块 k 基址 = 0x00100000 + k×0x40000 |

## 3. 下行规格（CPU → 10G）

| 项目 | 规格 |
|---|---|
| 帧长 | 16Byte，长度为 16Byte 正整数倍，地址 16Byte 对齐 |
| 整批上限 | 32KiB（须完整位于下行窗口内） |
| 发送方式 | 每帧一次 DDR 读突发，经 512 深度异步 FIFO（阈值 504）送 10G LocalLink |
| 完成标志 | 整批 10G 末拍握手完成后 0x20 自动清 0；清 0 ≠ 远端子机执行成功回执 |
| 非法请求 | 不访问 DDR，消费后门铃清 0；忙期间写入 0x24/0x28 被忽略，重复写 1 不追加任务 |

## 4. 下行规格（1G 参数通道）

| 项目 | 规格 |
|---|---|
| 配置来源 | 首次合法 Byte1（小端 64bit 首拍 [15:8]，编号 1~10）按十组表锁存 |
| 参数内容 | duty16 + Vin32，共 48bit；Vin = 电压 × 1048576 |
| 载荷顺序 | duty 低字节、高字节、Vin 低到高四字节（共 6Byte） |
| 发送时机 | 31.25MHz 用户域每 63 拍一个发送机会（名义 2.016µs）；两拍发送，第二拍高 16bit 有效，REM=1 |
| 反压行为 | 忙时跳过新机会不积压；已有效拍保持到握手；链路恢复不补发 |
| 配置保持 | 保持到主机逻辑复位；重复合法帧不改变锁存值 |

## 5. 上行规格（10G → DDR → CPU）

| 项目 | 规格 |
|---|---|
| 有效数据 | 每有效 64bit 拍仅低 32bit 有效；两个低 32bit 拼成一个 DDR 64bit 写拍（先到在低位） |
| 帧边界 | 线路 SOF/EOF 不进 DDR、不用于定长检查；软件无法从 DDR 恢复线路帧边界 |
| 长度粒度 | 4Byte 整数倍；单个剩余字用 WSTRB=0x0F 尾拍写入 |
| 窗口封存 | DDR 域 100ms 边界请求封存，等待在途写响应完成 |
| 块发布 | 空块不发布；块满或八块全满不覆盖旧数据；成功 B 响应才计入有效长度 |
| 块容量 | 8 × 256KiB；写失败数据计为丢失，下次从未提交位置覆盖继续 |

## 6. 寄存器表（AXI-Lite BAR，32bit 小端，字节偏移）

| 偏移 | 名称 | 语义 |
|---|---|---|
| 0x00 | VERSION | 0x00002001，业务版本 |
| 0x04 | PROG_TIME | 0x20260914，源码版本日期 |
| 0x08 | BUF_LEN_MAX | 0x00040000，上行单块容量（256KiB） |
| 0x0C | FPGA_TEMP | 原温度接口读数 |
| 0x10 | INT_STATE | 读清通知，读清不释放块 |
| 0x14 | CPU_REC_STATE | 写 bit0=1 确认一次；硬件消费后自动清 0 |
| 0x18 | FPGA_CPU_START_ADDR | 最老待取上行块地址；空队列为 0 |
| 0x1C | FPGA_CPU_LEN | 队头实际有效长度（4Byte 整数倍）；空队列为 0 |
| 0x20 | CPU_WR_DONE | 写 1 提交下行整批；发送完成或拒绝/中止后清 0 |
| 0x24 | CPU_FPGA_START_ADDR | 下行 DDR 地址；忙期间写入忽略（复位默认 32KiB） |
| 0x28 | CPU_FPGA_LEN | 下行长度；忙期间写入忽略 |
| 0x2C | — | 保留 |
| 0x30 | UP_READY_BLOCK_CNT | 待取块数 0~8 |
| 0x34 | UP_BLOCK_SEQ | 每发布一个非空块递增，32bit 自然回绕，首块 0 |
| 0x38 | UP_DROP_WORD_CNT | 累计丢失 32bit 有效字数，32bit 饱和（含 FIFO 溢出、DDR 不能接收、写响应错误） |

注：RTL 内部兼容连线保留 `RX_DROPPED_FRAMES` 名称，但 V2.01 统计单位为 32bit 字，不可按帧解释。

## 7. 软件操作流程

**下行**：等 0x20==0 → 写 0x24 地址 + 0x28 长度 → 驱动完成 H2C 写 DDR → 写 0x20=1 → 等待自动清 0。无需先写 0。

**上行**：收到通知（0x10 读清）→ 读 0x18/0x1C/0x34 → 驱动完成 C2H → 写 0x14=1 确认。确认前队头元数据及 DDR 内容保持稳定；确认后若有下一块会重新通知。

## 8. 软件约束

- 禁止两个软件线程分别读队头和写确认（单一消费者模型）
- 0x20 清 0 仅表示硬件消费完成，无事务结果码，不能证明远端成功
- 丢失只通过 0x38 累计计数报告，数据流不插占位字，无法从数组定位缺口位置
- AXI 写响应一直不返回时该块不发布，FIFO 最终满并累计丢失
- DMA 与 MMIO 必须使用驱动提供的完成和顺序保证
- 1G 反压时不承诺实际发送间隔小于 3µs

## 9. 关键差异

- 上行从"按帧计数"改为"低32bit紧凑字流 + 4Byte 长度粒度 + 字丢失计数"
- 下行帧长从 128Byte 改为 16Byte
- 跨域定时从 2µs 改为 63 拍（2.016µs）
- 八块地址规划（2MiB）与门铃交互保持不变
