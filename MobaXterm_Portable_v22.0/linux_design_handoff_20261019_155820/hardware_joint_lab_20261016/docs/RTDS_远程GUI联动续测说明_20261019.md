## 2. 每次重开 Vivado 后接入

在已经连接板卡并加载配套 LTX 的同一个 Tcl Console 执行：

```tcl
source C:/project/RTDS/DDR/RTDS_test_DDR4_64bit_batch_dev/debug/hardware_joint_lab_20261016/vivado/gui_bridge.tcl
::rtds_gui::start
```

出现 GUI_BRIDGE_READY 后，助手经 SSH 投递受限命令，GUI 事件循环执行布防、VIO、采集与显示。ARM 的寄存器/DMA 与 GUI 之间按完成消息握手，不以固定延时猜测操作完成。source/start 不下载 bit，也不重新连接目标。

当前 VIO 输入和命令状态会在 Tcl Console 显示；已有 VIO 面板在刷新输入时同步变化。DDR 写、读各保存一次原生 ILA，单块上行保存 FDMA ILA，并显示在同一个 GUI。多块实验不逐块新增波形标签。

实验期间只观察，不另行点击 Trigger/VIO start，不在其他终端读清通知、归还数据或运行并行测试。

## 3. 在已有 ARM root 窗口看日志

连接 192.168.50.10 后执行：

```sh
tail -F /root/rtds_joint_lab_20261016/live_status.log
```

这会显示由助手运行的同一份测试输出。Ctrl+C 只停止查看，不停止另一个 SSH 通道中的实验。日志的 PC 时间用于日期记录，ARM 单调时间用于步骤排序和耗时；板端日期不可信。

程序已部署在 ARM 的持久化文件系统中，断电后仍保留；没有设置开机自动运行。程序通过 io 访问 BAR 寄存器，C 辅助程序通过既有 /dev/xdma0_h2c_0 和 /dev/xdma0_c2h_0 搬运数据。

## 5. 测试顺序与边界

详细方案：远程工程 docs 下的 RTDS_现有GUI接入与完整硬件验证计划_20261016.md/.docx。完整操作手册：RTDS_ARM_FPGA板内联调实验手册_20261016.md/.docx。

| 顺序 | 实验 | 判据 |
|---|---|---|
| 1 | 环境与寄存器 | 版本 0x2001、DDR 0x3、队列空、无新增错误 |
| 2 | 配置回读 | 两组合法值一致，最后恢复原配置，不启动下行 |
| 3 | DDR 与原生 ILA | 0x8000 处 H2C/C2H 各 16Byte，数据 00…0F 一致，保存写/读波形 |
| 4 | 单块 VIO 与 FDMA ILA | start 0→1，accepted=2、busy=0、fault=0；有效 8Byte 为 11 00 00 00 22 00 00 00 |
| 5 | 通知与归还 | 读一次 0x10 不改变队头；数据确认后只写一次 0x14=1，队列归零 |
| 6 | 多块与环回 | 2、8、2 块，逐块重新取地址/长度/序号，覆盖 8 槽，顺序和内容正确 |

上行 C2H 请求 16Byte、只比较有效的前 8Byte，分别记录有效/请求/实际完成长度。失败停止，保留队列，不自动重试注入或归还，不清历史或重启。

当前 RX_VIO_TEST_ENABLE=1。即使全部板内实验通过，也只验证本版本 VIO→真实 DDR→C2H 通路；真实 Aurora、对端上下行、外部 I/O、性能及两种启动方式回归仍需分别实测。

## 6. 本次修正和证据

旧控制依赖 R: 映射盘，曾发生 WinError 1117。2026-10-19 改为已有 Windows SSH 连接传递请求和返回结果，不再依赖 R:。

首次续测环境、寄存器和配置回读通过；在首次 DMA 之前，ILA 布防因 CONTROL.TRIGGER_MODE 为只读而失败。修正为：先读取所需设置；值已匹配则不写；不匹配时写入并回读，失败仍立即停止，不忽略错误。固定硬件能力不因辅助程序而改变。

首次结果保留于 validation/gui_validation_20261019_085920_1674d0.json，失败实验为 20261019_085954_ddr_724a4；该轮未执行 DMA 或 VIO 注入。
