# RTDS 板内联调现场操作卡

2026-10-16。先暂停其他寄存器/DMA业务。CPU侧DDR闭环可独立执行，VIO/ILA需要Hardware Target可见。

| 实验 | ARM命令，在/root/rtds_joint_lab_20261016下运行 |
|---|---|
| 环境、寄存器 | python3 arm/rtds_lab.py env；然后python3 arm/rtds_lab.py regs |
| 配置写回/恢复 | python3 arm/rtds_lab.py config --exclusive |
| 16Byte DDR闭环 | python3 arm/rtds_lab.py ddr --exclusive --no-jtag |
| 单块上行并抓波形 | python3 arm/rtds_lab.py single --exclusive --capture |
| 2块→8块→2块环回 | python3 arm/rtds_lab.py multi --exclusive --capture |

ARM提示需要操作时，先完成相应GUI/Tcl动作再输入PASS。最终看FINISH的PASS/FAIL，结果写入results独立目录。

| 顺序 | FPGA/Vivado操作 | ARM自动检查 |
|---|---|---|
| 1 | Hardware Manager→Open Target→Auto Connect，匹配LTX、Refresh | 版本2001、DDR3、队列0 |
| 2 | 旧VIO u_pcie/G_RX_VIO.U_VIO_RX_START：start提交0；busy0、status低3位3 | 有旧块停止，不盲清空 |
| 3 | 加载脚本并inspect；新VIO clear保持0 | inspect请求时确认PASS |
| 4 | FDMA fdma_wareq==1，单箭头Run Trigger；或arm fdma_up | arm请求时确认，必须先布防 |
| 5 | start先提交0再1，或inject；accepted2、busy0、fault0 | 一次块数增加、长度8 |
| 6 | save fdma，成功再确认PASS | 读清通知不释放；C2H请求16，比前8 |
| 7 | 不再注入 | 数据1100000022000000正确后仅一次0x14=1，队列空 |
| 8 | snapshot后确认PASS | 无新错误/丢字，下行配置未变 |

~~~tcl
source C:/project/RTDS/DDR/RTDS_test_DDR4_64bit_batch_dev/debug/hardware_joint_lab_20261016/vivado/rtds_lab.tcl
::rtds_lab::inspect
::rtds_joint::arm fdma_up
::rtds_lab::inject
::rtds_lab::save fdma
::rtds_joint::snapshot
~~~

命令分阶段执行，不一次全部运行。Immediate不用来等待业务。DDR H2C/C2H抓原生PCIe ILA，分别arm dma_write、arm dma_read，save native。失败保存现场，不盲归还、不清历史或重烧。详见完整手册。
